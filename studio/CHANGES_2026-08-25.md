# 자막 타이밍을 끌어서 맞춘다 (2026-08-25)

## 왜

start/duration 을 숫자로 쳐서 맞추고 있었다.  자막 수백 개를 그렇게 맞추려면
"듣기 -> 숫자 고치기 -> 다시 듣기" 를 매번 도는데, **0.2 초를 당기고 싶을 때
숫자를 얼마로 고쳐야 하는지 귀로는 알 수 없다.**  눈으로 보고 끄는 편이 맞다.

숫자 입력은 **그대로 뒀다.**  대체가 아니라 추가다 -- 정밀하게 박을 때는 여전히
숫자가 빠르고, 두 쪽이 같은 값을 본다.  타임라인에서 끌면 그리드의 숫자 칸이
실시간으로 같이 바뀐다.

## 무엇이 되나

```
블록 가운데를 끈다     길이는 그대로 · 시작/끝이 같이 움직인다
블록 왼쪽 끝을 끈다    시작 시간만 바뀐다 (끝은 고정)
블록 오른쪽 끝을 끈다  끝 시간만 바뀐다 (시작은 고정)
블록을 누른다          오른쪽 목록의 그 자막이 같이 선택된다
목록에서 고른다        타임라인의 그 블록이 주황색으로 표시된다
빈 곳을 누른다         재생 위치만 옮긴다 (선택은 안 건드린다)
```

끄는 동안 위쪽에 `시작 → 끝 (길이)` 가 실시간으로 뜬다.
재생 중에 끌어도 멈추지 않는다 -- 재생 → 싱크 확인 → 끌기 → 다시 재생이 바로 돈다.

음성(ADPCM) 탭과 CD-DA 탭 둘 다 같다.

## 자막끼리 절대 안 겹친다

가장 중요한 규칙이다.  **두 자막이 동시에 뜨는 시간은 생기지 않는다.**
언제나 `자막1.end <= 자막2.start` 가 유지된다.

충돌하면 **끌고 있는 자막을 막지 않는다.**  밀고 들어간 쪽이 이기고 이웃이
줄어든다.

```
2 번을 왼쪽으로 밀면   1 번의 끝이 물러난다      자막1.end = 자막2.start
2 번을 오른쪽으로 밀면 3 번의 시작이 밀린다      자막3.start = 자막2.end
                       3 번의 끝은 그대로 -- 길이가 줄어든다
왼쪽 끝을 끌면         start 만 바뀌고 앞 이웃의 끝이 물러난다
오른쪽 끝을 끌면       end 만 바뀌고 뒤 이웃의 시작이 밀린다
```

**틈은 허용한다.**  물러날 때 이웃을 늘려 채우지 않는다 -- 말이 없는 구간은
화면도 비는 것이 맞고, 되돌리기도 손실이 없다.

경계 둘을 뒀다.

```
이웃 최소 길이 0.05 초   이웃이 여기 닿으면 그때부터 끌린 블록이 막힌다.
                         한 번 잘못 끌어 이웃이 사라지면 되돌릴 수가 없다
미는 것은 바로 옆 하나   연쇄로 밀면 드래그 한 번이 앞 자막을 줄줄이 뭉갠다
```

이웃은 **시간 순서**로 찾는다 (part 순서가 아니다).  눈에 보이는 이웃이 곧
겹칠 수 있는 상대이고, 자료가 어긋나 있으면 두 순서가 다르다.
이웃은 끌기를 **시작할 때 한 번만** 정한다 -- 도중에 다시 찾으면 블록이 서로
지나칠 때 엉뚱한 블록이 밀린다.

### 계산은 순수 함수로 뺐다

`SubtitleTimeline.Resolve()` 는 마우스도 화면도 안 본다.  스펙에 적힌 예시
숫자를 그대로 시험할 수 있게 하려는 것이다.  6 가지를 확인했다 -- 예시 A/B,
양 끝 드래그, 틈 유지, 왼쪽 끝까지 밀어붙였을 때 겹치지 않는지.

```
초기  1=0.0~2.5  2=2.5~5.0  3=5.0~7.0
A     2 를 왼쪽으로 start=2.0  ->  1=0.0~2.0  2=2.0~4.5  3 그대로
B     2 를 오른쪽으로 end=5.5  ->  1 그대로   2=3.0~5.5  3=5.5~7.0
```

## 데이터는 안 건드렸다

`start_sec` / `duration_sec` 에 `0.000` 형식으로 쓴다.  TSV 스키마도 런타임
포맷도 그대로다.  끄는 것은 **그 두 값을 고치는 다른 방법**일 뿐이다.

## 구현에서 걸렸던 것 둘

### 1. 끄는 중에 목록이 다시 만들어지면 잡고 있던 블록이 사라진다

그리드 칸을 고치면 `CellValueChanged` -> `RefreshVoiceTimeline()` 이 돌아
`Spans` 가 통째로 새로 만들어진다.  끄는 중에 그러면 잡고 있던 블록의 인덱스가
어긋난다.

두 겹으로 막았다.

```
SubtitleTimeline   끄는 중에는 Spans 대입을 아예 무시한다 (IsDragging)
MainForm           끄는 중에는 무거운 전체 갱신을 부르지 않는다 (draggingSubtitleBlock)
```

놓는 순간(`SpanDragged`)에 한 번만 전체 갱신을 돈다.  그때는 `IsDragging` 이
이미 false 라 대입이 먹는다 -- 순서가 중요하다.

### 2. 겹치는 블록은 잡을 수가 없다

한 줄에 다 그리면 뒤 블록이 앞 블록에 가려 클릭이 안 닿는다.  겹치는 것을
아래 줄로 내린다 (`LayoutLanes`).  시작 순서대로 놓아야 줄이 적게 나온다.

## 블록을 어떻게 알아보나

블록 안에 `조각번호 + 한국어 앞 24 자` 를 적는다.  번호만으로는 어느 자막인지
알 수 없어서 매번 목록을 봐야 했다.
