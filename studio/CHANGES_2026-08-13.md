## 1. 음성 재생 중 선택이 튀던 것

**증상** 음성 자막 작업 중 재생이 끝나면 선택한 행이 다른 데로 옮겨가
잡고 있기 어렵다.

**원인** `RefreshVoiceEvents()` 가 재생 상태가 바뀔 때마다 불리는데, 그 안에서

```csharp
voiceEventGrid.Rows.Clear();          // 전체 행을 지우고 다시 만든다
...
activeRow.Selected = true;
voiceEventGrid.CurrentCell = activeRow.Cells[0];             // 재생 중인 행으로 강제 이동
voiceEventGrid.FirstDisplayedScrollingRowIndex = activeRow.Index;   // 스크롤까지 이동
```

행을 통째로 재생성한 뒤 커서와 스크롤을 재생 중인 행으로 옮긴다. 재생이 끝나면
활성 목록이 바뀌면서 또 옮겨간다. 보고 있던 행은 그 과정에서 사라진다.

**수정** 요청하신 대로 "그 자리에 두고 색만 갱신" 하도록 바꿨다.

* `VoiceGridMatchesData()` — 화면 행과 데이터 행이 1:1 로 그대로인지 확인
* 그대로면 `PaintVoiceActivity()` 로 **배경색만** 갱신하고 즉시 반환.
  행 재생성 없음, 선택·스크롤 건드리지 않음. 바뀐 행만 다시 칠하므로
  재생 중 깜빡임도 없어진다
* 행 구성이 실제로 바뀐 경우(가져오기 · 삭제 · 병합)에만 재생성하고,
  그때도 **보고 있던 행을 복원**한다. 선택이 아예 없었을 때만 재생 중인
  행으로 옮긴다

## 2. "적용 후 다음" 이 느리던 것

**증상** UI 탭에서 한 행 넘길 때마다 눈에 띄게 멈춘다.

**원인** `ApplyUiCurrent()` 와 `SetUiReview()` 가 각각

```csharp
foreach (DataGridViewRow gridRow in uiGrid.Rows)
{
    if (!ReferenceEquals(gridRow.Tag, currentUiRow)) continue;
    ...
    break;
}
```

`ui_text.tsv` 는 992 행이다. 한 번 넘길 때 `ApplyUiAndMoveNext` →
`ApplyUiCurrent` → `SelectUiRow` → `ApplyUiCurrent` 로 이 탐색이 여러 번 돈다.

**수정** 현재 화면 행을 캐시한다.

* `currentUiGridRow` 필드와 `CurrentUiGridRow()` 헬퍼 추가
* 캐시가 유효하면(같은 그리드에 붙어 있고 `Tag` 가 현재 데이터 행이면) 그대로 사용
* `RefreshUiGrid()` 등으로 행이 재생성돼 캐시가 어긋나면 그때만 다시 찾는다

동작은 같고 탐색만 사라진다.

## 4. 종료 후 프로세스가 남던 것

**증상** 창을 닫아도 프로세스가 남을 때가 있다.

**원인** `Program.cs` 에 이미 같은 증상에 대한 대응이 들어 있다.

```csharp
Application.Run(mainForm);
Application.ExitThread();
// FileSystemWatcher/WinForms callbacks can occasionally keep the
// single-file portable process alive after its last window closes.
Environment.Exit(0);
```

그런데 이 `Environment.Exit(0)` 은 **`Application.Run()` 이 반환해야 도달한다.**
메시지 루프가 반환하지 않으면 영영 실행되지 않는다. 파이썬 자동 빌드를
`await process.WaitForExitAsync()` 로 기다리는 경로가 있어(`MainForm.cs` 1966-1983),
빌드 중에 창을 닫으면 이 상황이 만들어질 수 있다.

**수정** 창이 닫힌 시점에서 직접 끝낸다.

```csharp
FormClosed += (_, _) => { ShutdownBackgroundServices(); Environment.Exit(0); };
```

이 시점이면 `FormClosing` 의 저장 확인과 백그라운드 정리가 모두 끝난 뒤다.

> **주의 — 이 건은 재현하지 못한 상태에서 코드만 보고 고쳤다.**
> 작업 중 프로세스를 확인했을 때 남아 있는 것이 없었고, `Program.cs` 주석도
> "occasionally" 라고 적고 있다. 즉 조건부로 발생하는 문제이고, 위 원인 분석은
> 코드 경로에 근거한 것이지 실측이 아니다. 계속 재현되면 자동 빌드 실행 직후인지
> 먼저 확인할 것 — 그렇다면 파이썬 자식 프로세스 정리까지 필요하다.
