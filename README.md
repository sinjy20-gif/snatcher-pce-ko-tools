# Snatcher (PC Engine CD-ROM²) 한국어화 — 도구와 분석 기록

코나미 《SNATCHER》 PC Engine CD-ROM² 판을 한국어화하면서 만든 **도구와 분석
자료**입니다. 게임 데이터·번역문·글꼴은 들어 있지 않습니다 ([NOTICE.md](NOTICE.md)).

PC Engine CD 쪽 리버싱 자료가 거의 없어서, 푸는 과정에서 알아낸 것을 그대로
남겨 둡니다. **틀렸던 기록도 지우지 않았습니다** — 실패가 대개 더 유용합니다.

---

## 무엇을 풀었나

| | |
|---|---|
| **한글 글꼴** | 시스템 카드 3 BIOS 의 12×12 글리프 자리에 갈무리를 얹어, 번역을 **BIOS 폰트 코드로 내보내면** 그대로 출력된다. 15자 예산·AC 의존이 한꺼번에 사라졌다 |
| **자막 엔진** | ADPCM 음성과 CD-DA 트랙에 자막을 붙인다. 음성 신원은 `sector + 길이` (끝 주소는 672→59 값으로 뭉개진다) |
| **전면 그래픽** | 헌정사·RSS·면책·깁슨·전화·엔딩을 **디스크에서 제자리 치환**. 훅 0 개, 런타임 코드 0 바이트 |
| **타이틀·오프닝** | 스프라이트 압축 블록을 제자리 치환 |
| **가우디 단말** | 인물검색 한글 입력 (자판 45칸 + 검색표 16명 + 퀴즈 4개) |
| **BIOS 부팅화면** | 디스플레이 리스트를 다시 써서 스내처 로고로 |

* **화면 위쪽 한 프레임 깜빡임** — 자막 프레임에 그림 창 스크롤이 마감을 놓친다.
  최악 노출 41→17줄까지 줄였지만 남아 있다

## 특히 쓸모 있을 만한 것

### 디스플레이 리스트로 그리는 BIOS 부팅화면

Super CD-ROM² System BIOS 의 부팅화면은 BAT 가 아니라 **디스플레이 리스트**가
그립니다.

```
리스트  $00297D-$002A81  261 B   FF <팔레트> <x> <y> <타일...>  ·  FF FF = 묶음 구분
타일    $02C000                  ★ 타일 번호 == ASCII 코드
```

풀어낸 지렛대는 리스트 안의 `56 45 52 2E 20 33 2E 30 30` = ASCII **"VER. 3.00"**
이었습니다. 글자가 ASCII 코드 그대로 타일 번호라는 뜻이고, 그걸로 타일 기준이
`$02C000` 임이 확정되면서 나머지가 전부 풀렸습니다.

**묶음을 비우면 안 됩니다.** 자리를 몰아주려고 빈 묶음을 만들었더니 뒤에 이어진
메시지 표("PUSH RUN BUTTON!")가 통째로 사라져 게임 로딩이 시작도 안 됐습니다.
파서가 빈 묶음의 `FF FF` 를 표 끝으로 읽는 것으로 보입니다. **정적 검증으로는
안 잡혔습니다** — 되읽기·감사·적용 시험을 전부 통과했는데 실기에서 죽었습니다.

`tools/build_bios_boot_snatcher.py`

### 압축 블록 ↔ VRAM 짝 찾기

디스크의 압축 그래픽 블록이 화면의 어디로 가는지는 **풀어서 그림이 맞는지로는
확정되지 않습니다.** 그 코덱은 아무 타일 경계에서나 이어 풀려서, 재개점이 블록
시작처럼 보입니다. 그걸 믿고 두 판을 깼습니다.

확정은 프로브로 합니다 — 압축 해제기 호출마다 MAWR(VRAM 주소)을 기록하면
**순서가 남습니다**. `lua/GFX/0.7.0-block-to-vram.lua`

### 색은 실기 CRAM 을 떠야 압니다

BIOS 안에서 16색×4벌짜리 팔레트 모양을 찾아 "이게 부팅 팔레트다" 라고 단정했다가
틀렸습니다. 디코딩하니 회색 램프·파랑·초록·빨강이 나와서 예상과 맞았는데,
그게 확증편향이었습니다. **거기를 갈아도 실기 색이 안 바뀌었습니다.**

색 없는 미리보기는 미리보기가 아닙니다. `lua/GFX/PROBE_GFX_SCREEN_*.lua` 로
CRAM 을 뜨고, 그 팔레트로 그려야 합니다.

### 빌드 사슬에서 조용히 빠지는 것

손으로 돌리던 패치 단계는 **한 번 빠뜨리면 그대로 굳습니다.** 증상이 없어서
안 잡힙니다 — 빌드도 감사도 통과하고 그 화면만 일본어로 남습니다.

이 프로젝트에서 두 번 당했습니다. 타이틀·오프닝이 세 판 동안, 가우디 인물검색이
다섯 판 동안 빠져 있었습니다. 둘 다 사용자가 눈으로 잡았습니다.

그래서 감사가 **산출물에서 지문을 직접 읽습니다.** 사슬을 믿지 않습니다.

```
가우디 검색 훅     Track02 raw $0C6CD0 == 20 56 BE
가우디 검색표·퀴즈  Track02 raw $0C7146 (동굴)이 전체 표인가 (옛 97 B 스텁이 아닌가)
부팅화면 묶음      앞 세 묶음에 빈 것이 없는가
```

`tools/check_build_invariants.py` 의 `check_features()`

## 문서의 `환경 A` / `환경 B`

인계서에 **환경 A · 환경 B** 라는 말이 자주 나옵니다. 이 프로젝트는 컴퓨터 두 대를
오가며 진행했고, 그 둘 사이에서 작업을 주고받다가 생긴 문제가 꽤 됩니다 —
"어느 쪽이 최신인가", "묶음이 뭘 빠뜨렸나" 같은 것들이요.

그 병합 사고들이 기록의 큰 부분이라 그대로 뒀습니다. 두 환경을 오가며 작업하는
분이라면 그대로 겪을 만한 것들입니다.

## 돌리려면

파이썬 3.11+ 와 **본인이 보유한 게임의 덤프**가 필요합니다. 도구들이 기대하는
경로는 각 파일 머리말에 적혀 있습니다. 이 저장소만으로는 빌드가 되지 않습니다 —
의도한 것입니다.

배포판은 xdelta(VCDIFF) 세 개로 나갑니다 (BIOS · Track02 · Track24).
`tools/make_xdelta_patch.py`
