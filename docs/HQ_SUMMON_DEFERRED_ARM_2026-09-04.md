# 국장실 "천장 국장" — 지연 arm 방식 (보류 · 2026-09-04)

우선순위를 **가장 뒤로** 미룬다.  기능 구현과 플레이 불가 버그가 먼저다.
다시 잡을 때 차갑게 이어갈 수 있도록 방식만 여기 남긴다.

---

## 1. 증상

그림 창 스크롤이 늦게 닿아 화면 위쪽이 **타일맵 꼭대기(천장)** 로 그려진다.
원래 아래만 보여야 하는데 **천장에 매달린 국장**이 보인다. 자막을 쓰는 순간에만.

★ 단순 그래픽 깨짐이 아니다. **본편 핵심 스포가 새고 출하불가급이다.**

---

## 2. 원인 (확정)

`BYR=96` (그림 창 스크롤) 이 닿는 스캔라인이 늦어진다.

```
원본 일본판 BIOS   10,016 프레임 전부 줄 32.  예외 0        (0.5.157 대조군)
우리               0.64~0.84 % 가 줄 33~72 로 밀린다
```

범인은 **arm 1 회가 엔진 671 B 를 AC 포트로 한 바이트씩 옮기는 것**이다.
뱅크1 에서 약 4,300 명령 ≈ 25,800 cyc ≈ **57 스캔라인**.  줄 24 에서 시작하니
줄 32 의 래스터 IRQ 를 밀어낸다.

```python
# build_snatcher_0_4_6_29_native_arm.py 의 arm_copy_engine_*
copy_engine_bytes = max(engine_bytes, cdda_engine_bytes)   # 약 671 B
# 바이트당 LDA $1A00 / STA $1A10 / INY / BNE = 4 명령
```

⚠ 이 복사는 없앨 수 없다 -- 헬퍼와 렌더러가 **같은 `$5B80`** 을 쓰므로, 음성이
끝나 헬퍼가 올라간 뒤 다음 arm 은 렌더러를 다시 실어야 한다.
⚠ AC 읽기는 `TAI $1A00 금지` 제약이라 블록 전송으로 못 줄인다.

## 3. 시도한 방식 — 무거운 arm 을 줄 160 으로 옮긴다

BIOS 의 RCR 설정 루틴이 프레임당 3 번 불린다.  그중 **줄 160 호출**에서
줄 250 까지 약 90 줄 ≈ 40,900 cyc 가 비어 있다 (복사는 25,800 cyc).

```asm
$E41F  48        PHA          ; A = RCR lo
$E420  A9 06     LDA #$06
$E422  85 F7     STA $F7
$E424  8D 00 00  STA $0000    ; ★ 훅 자리 (3 B · JSR $FFD4 로 교체)
$E427  68        PLA
$E428  8D 02 00  STA $0002    ; RCR 하위
$E42B  8E 03 00  STX $0003    ; RCR 상위  ← X 를 쓴다
$E42E  60        RTS
```

### 훅 자리를 고른 이유 (셋 중 하나만 된다)

```
$E41F (PHA/LDA #$06)  ✗ 밀려난 명령이 스택을 건드린다.  진입 시 A 가 RCR lo 인데
                        디스패처 두 번째 명령이 그것을 덮는다
$E42B (STX $0003)     ✗ 디스패처가 TSX 로 X 를 덮어 밀려난 STX 를 재현 못 한다
$E424 (STA $0000)     ✓ 채택.  그 시점 A 는 상수 $06 이고 RCR 값은 이미 스택에 있다
```

### ★ 어느 호출인지는 **스택의 RCR 값**으로 가른다

`$E41F` 의 `PHA` 가 밀어 둔 값이 디스패처가 `TSX` 한 X 기준으로 여기에 있다:

```
$2101,X  P           (다리의 PHP)
$2102,X  JSR ret lo  ($26)     <- 기존 복귀주소 판별이 쓰는 자리
$2103,X  JSR ret hi  ($E4)
$2104,X  ★ RCR lo
```

```asm
LDA $2104,X
CMP #$D4        ; 212 = 화면줄 148 예약 = 줄 160 호출
BNE rcr_bail
```

실측 (0.5.164 · 0.4.6.72 · 4,500 프레임):

```
RCR lo=212  X=0  line 160   ★ 212 는 여기서만 나온다
RCR lo=199  X=0  line 250 · 71 X=0 line 250 · 64 X=0 line 31
X 는 전 조합에서 0  ->  rcr_tail 의 LDX #$00 근거 확보
```

### ⚠ 처음에 **순번**으로 가르려다 자막이 전멸했다

"`$E424` 는 프레임당 정확히 3 번" 을 전제하고 호출 순번을 셌다.  실측 프레임 끝
순번이 **0 · 2 · 3** 으로 흔들린다 (리셋과 호출의 **순서**가 장면마다 다르다).
그러면 무거운 arm 이 줄 32 나 줄 250 에서 터진다.  줄 32 가 치명적이다 --
게임은 스캔라인 **40~119** 에서 AC 를 쓰는데(0.5.161 실측 · 148~250 은 0 회),
그 직전에 채널 0 포인터를 갈아엎으면 게임의 AC 읽기가 우리 주소를 문다.
-> 이분 검색이 miss 로 끝나 슬롯만 소비되고 `STATE=1` 이 안 온다 = 자막 전멸.

**값 판별로 바꾼 뒤 이 문제는 사라졌다.**

## 4. 구조 — 세 갈래

```
줄 24  FEC4    슬롯이 A1 이면 LBA 3 B 를 AC 스크래치에 넣고 **대기 플래그만** 세운다
줄 160 $E424   RCR 값이 212 이고 대기가 서 있으면 -> 검색 + arm 전부
줄 24  안전밸브 대기가 다음 프레임까지 남아 있으면 거기서 처리 (옛 동작으로 복귀)
```

⚠ **AC 채널 1 은 쓰지 않는다.**  그것은 게임 것이고 `arm_found` 의 보호 구간
  **밖**이다.  채널 0 만 쓰고 3 B 는 스택으로 옮긴다 -- 스택이 역순이므로
  스크래치에도 역순으로 넣고 역순으로 꺼낸다 (대칭이라 맞는다).
⚠ `arm_found` 이후는 **한 덩어리**다.  엔진 671 B 복사만 떼어 옮길 수 없다 --
  그 뒤가 복사된 이미지에 selector 와 VRAM 즉치를 덮어쓴다.
⚠ 꼬리는 복귀주소로 가른다 (`$FEC6` -> `arm_return` · `$E426` -> `rcr_tail`).

## 6. 다시 잡을 때 — 여기서 시작

1. **`gate=22~24 · engine=-` 무리가 정말 안전밸브인지 확인한다.**
   `0.5.158`(BYR=96 이 닿는 줄) 과 `0.5.163`(A1/PEND/D) 을 같이 띄워 겹치는지 본다.
2. 겹치면 **안전밸브를 줄 24 밖으로 옮긴다.**
   ⚠ 밸브를 없애면 안 된다 -- RCR 이 안 오는 장면에서 자막이 통째로 죽는다.
3. 안 겹치면 arm 이 아니라 다른 것이 줄 24 를 먹고 있다는 뜻이니 거기부터 다시 잰다.

## 8. ⚠ 지뢰 (다시 밟지 말 것)

**8-1. `emit()` 의 첫 3 B 는 반드시 `AD DF 7F` 다.**
`patch_bios_cpu_cache.py` 가 디스패처 json 의 `extra` 라벨을 읽어 그 자리를
`JSR entry_hook` 으로 갈아끼운다 (671 B 처방).  거기에 뭘 끼우면 처방이 통째로
안 걸리고 **챕터1 화면이 깨진다** (0.4.6.75 가 그렇게 죽었다).
순번 리셋 같은 것은 `arm_return`(FEC4 공통 출구) 에 둔다.

**8-2. `$E42B` 가 `STX $0003` 으로 RCR 상위 바이트를 쓴다.**
디스패처의 `TSX` 가 X 를 덮으므로 훅 꼬리에 `LDX #$00` 이 필요하다.
0.5.164 로 전수 확인했다 (X 는 전 조합에서 0).  안 넣으면 RCR 이 $F8xx 가 되어
래스터 분할이 통째로 죽는다.

**8-3. 순번으로 가르면 안 된다.**  `$E424` 호출 수가 장면마다 다르다 (§3).

## 9. 오버클럭에 대해

오버클럭하면 밀림이 사라지는 것은 확인했다.  **그러나 그것은 RetroArch + Beetle
PCE 에서 본 것이고 Mesen 에는 PCE 오버클럭이 없다.**  개발·검증은 Mesen 에서
하므로 쓸 수 없다.  이것은 "사이클 예산 문제다" 라는 **진단 근거**로만 유효하다.

⚠ 출하를 특정 에뮬의 특정 옵션에 기대는 것도 약하다.  이미 "스프라이트 리미트
해제" 가 붙어 있는데(그건 Mesen 에 있다) 거기에 "오버클럭 되는 에뮬로 실행" 까지
붙으면 받는 사람이 재현 못 할 확률이 크게 오른다.
