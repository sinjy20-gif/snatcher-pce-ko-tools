# 마스터 병합 지침서

`tools/build_runtime_master.py` 로 마스터를 다시 만들 때 **매번** 보는 문서다.
여기 적힌 것은 전부 한 번씩 실제로 물린 것들이다.  "지난번에도 이랬는데" 를
없애려고 모았다.

> **원칙 하나** -- `--write` 를 안 주면 이 도구는 **보고만 한다.**
> 무엇이 어떻게 바뀌는지 먼저 보고, 숫자를 확인한 다음에 쓴다.

---

## 0. ★ 지금 쓰는 명령 (2026-08-24 기준)

```bash
python tools/build_runtime_master.py --keep-duplicates
```

`--keep-duplicates` 를 **붙인다.**  소유자 지정: 지금 마스터 상태는 그대로 두고
앞으로 늘어나는 것만 막는다.

| 명령 | 보존 | 총 행 |
|---|---|---|
| 고치기 전 (2026-08-24 이전) | 11,856 | **14,715**  ← 돌릴 때마다 +198 |
| `--keep-duplicates` | 11,658 | **14,517**  ← 지금과 정확히 같다 |
| 플래그 없이 (정리까지) | 9,713 | 12,572  (중복 1,169 레코드 접힘) |

정리하는 쪽으로 갈 거면 먼저 §5 를 읽을 것 -- **번역이 갈린 68 종**이 있다.

## 1. 돌리기 전

```
[ ] 스튜디오(SnatcherTranslationStudio)가 떠 있나        -> 떠 있으면 멈춘다
[ ] 소유자가 지금 번역/검토 작업 중인가                   -> 중이면 묻는다
[ ] 마스터 백업이 오늘 것으로 있나
```

**스튜디오를 켜 둔 채로 병합하거나 마스터 파일을 직접 고치지 않는다.**
저장 시점이 겹치면 한쪽이 통째로 날아간다.

2026-08-18 에 확인 없이 병합을 다섯 번 돌려 **번역 32행·검토 O 23행**을 잃었다.
소유자가 하루치 검토를 잃은 사고다.

## 2. 돌린 뒤 반드시 읽는 숫자 넷

출력에서 이 네 줄을 눈으로 확인한다.  하나라도 이상하면 **`--write` 하지 않는다.**

```
1  로그 밖 현역 레코드 보존: N 행
      0 이면 멈춘다.  로그가 마스터 전체를 안 덮는데 덮는다고 착각한 것이다
      빌더는 로그에서 마스터를 "다시 만든다".  로그에 없는 레코드는 이 걸개가
      없으면 그릇째 사라진다 (2026-08-20 실측: 1,919 행이 사라질 뻔했다)

2  기존 레코드 번호 N개 재사용
      레코드 수에 비해 너무 작으면 번호를 못 찾고 있는 것이다 -> §3

3  이번 판이 이미 만든 문단이라 안 되살린 옛 레코드: N 개
      --keep-duplicates 를 줬으면 이 줄이 안 나온다.  나오면 플래그를 빠뜨린 것

4  15자 초과 N      <- 0 이어야 한다
```

## 3. ★ 수집할 때마다 같은 대사가 한 벌씩 늘어나던 것 (2026-08-24 해결)

### 증상

수집하러 한 바퀴 돌고 마스터를 다시 만들면 **볼 것이 늘어 있다.**
같은 대사가 두 벌, 세 벌.  14,517 행 중 여분이 5,773 행까지 쌓였다.

### 고리

```
1  옛 마스터 행에 speaker_jp 가 비어 있다     4,418행 전부 (그 열이 생기기 전 것)
2  existing_record_ids() 가 speaker_jp 로만 화자를 되찾는다  -> 화자 없음으로 오해
3  page_identity 가 (화자,)+몸통  vs  몸통 으로 갈린다        -> 번호를 못 찾는다
4  새 번호를 매긴다                            R00001 -> R04774 로 통째로 밀림
5  옛 번호는 "이번에 안 만들어진 것" 이 되어 §2-1 의 보존 걸개가 살려 둔다
6  살아난 행도 speaker_jp 가 여전히 비어 있다   -> 다음 판에서 3 번으로 ↻
```

### 실측 (2026-08-24)

```
옛 번호 2,616 개 · 새 번호 6,251 개        겹치는 번호 0 개
옛 문단 2,616 개 중 이번 갈래에 글자까지 똑같은 것 2,543 개 (97%)
줄 나뉨이 달라 갈린 것 0 개                 <- 창 경계 문제가 아니었다
```

```
옛 R00004 (speaker_jp='')  vs  새 R04777 (speaker_jp='ギリアン')  <원문 12자>。
옛 R00005 (speaker_jp='')  vs  새 R04778 (speaker_jp='ギリアン')  <원문 16자>。
```

### 고침

`tools/build_runtime_master.py` 두 군데.

```
1  speakers_jp_map()  추가.  speaker_jp 가 비면 한국어 speaker 로 역매핑한다
     -> 실측 3,193 레코드가 번호를 되찾았다 (재사용 8,553 -> 11,402)
2  보존 걸개가 text_key 뿐 아니라 몸통(jp_text)으로도 거른다
     -> 1 번이 실패했을 때의 두 번째 그물.  --keep-duplicates 로 끈다
```

**다음에 또 늘어나면** §2 의 2 번 줄(`기존 레코드 번호 N개 재사용`)을 먼저 본다.
그 숫자가 작으면 또 번호를 못 찾고 있는 것이고, 원인은 "번호를 되찾는 재료가
옛 행에 없다" 는 같은 모양일 것이다.

## 4. 그 밖에 맨날 빠지는 것들

### 4-1. 짧은 조각의 행별 번역이 덮어써진다  ⚠ 미해결

승계가 번역을 **`jp_text` 하나당 하나**로 들고 있다.  `す。` `ます。` `だ。` 같은
짧은 조각은 게임 여기저기서 나오는데, 행마다 다르게 번역해 둔 것이 마지막 하나로
전부 덮인다.

2026-08-18 실측: `す。` 하나에 17 개 레코드가 전부 "주입해 두었습니다" 를 받았다.
`{EMPTY}` 처리한 것까지 날아갔다.

```
근본 수정   승계 키를 jp_text -> (text_key, line_no) 로 바꾸기.  아직 안 했다
복구 방법   백업에서 (text_key, line_no) 키로 되살린다 (2,006행이 정확히 이어졌다)
당장 할 것  병합 뒤 아침 백업 대비 번역·검토 O 차이를 세어 본다
```

### 4-2. 문단 꼬리가 남의 것과 접힌다

게임이 상자를 넘길 때 텍스트 포인터를 다시 설치해서(`$6FFD`) **한 문장이 레코드
둘로 갈린다.**  뒷조각(「い・・・」「る。」)은 짧고 흔해서, 원문만으로 접으면 게임
다른 곳의 같은 조각과 하나가 된다.  그러면 앞조각 뒤에 이어질 줄이 **영영 안 생기고
재수집으로도 안 채워진다.**

고침: 접기 키가 `(pack, ptr) + 텍스트` 다.  실측 1,989 -> 2,093 (+104).
**이 키를 다시 텍스트만으로 되돌리지 말 것.**

### 4-3. 스튜디오 "대사 포함" 이 pack 을 안 넣는다

```
로그 분석   항목 생성 + pack 찍기   <- 새 행이 아직 없다
대사 포함   행 생성 (pack 빈칸)
로그 분석   <- 여기서야 pack 이 찍힌다
```

**"대사 포함" 뒤에는 "로그 분석" 을 한 번 더 누른다.**
그리고 RUNTIME 행의 장면 배정은 마스터의 pack 이 아니라
`logs\audit_archive\runtime_text_catalog_*.tsv` 에서 온다.  스튜디오는 카탈로그를
`logs\runtime_text_catalog.tsv` 에 쓰고 `세션 로그 삭제` 때만 보관소로 옮기므로,
새로 잡은 대사가 빌드에서 "no scene assignment" 로 막힌다.

2026-08-19 에 이것 때문에 314 행을 지웠다.  **pack 이 비어 있는 것은 Lua 문제가
아니다** -- 트리의 모든 수집 Lua 는 pack 을 정상으로 기록한다(실측).

### 4-4. `{FE:n}` 정규화 충돌 (고친 것 아님)

승계 조회가 `{FE:n}` 과 공백을 떼고 찾는다.  「下さい。」와 「下さい。{FE:1}」이 같은
키로 뭉쳐 나중 것이 이긴다.  4,041 종 중 2 종.  **원래 성질이다.**

### 4-5. 헷갈리는 것 -- 스튜디오 하단 `신규 누락 N`

로그 부족과 **무관하다.**  note 에 `[RUNTIME_MISS_UNEDITED]` 가 있는 행 = 게임에서
일본어로 남아 있어 런타임이 자동 등록한 것.  손으로 고치면 표식이 지워진다.

## 5. 같은 원문 일괄 치환 -- 경계는 8자다

"원문이 같아도 번역은 갈린다" 는 맞다.  다만 **갈림이 짧은 조각에만 몰려 있다.**
2026-08-24 마스터 14,517 행 실측:

| 원문 길이 | 겹침 종 | 갈린 종 | 갈림 |
|---|---|---|---|
| 1-4자 | 263 | 61 | **23.2%** |
| 5-8자 | 731 | 21 | 2.9% |
| 9-11자 | 749 | 2 | 0.3% |
| 12-15자 | 1,410 | 4 | 0.3% |
| 16-24자 | 1,695 | 5 | 0.3% |

짧은 겹침 행의 **62%가 `line_no`>1** (문단 꼬리) 이다.  앞 문맥이 다르니 다르게
붙는 것이 맞다.

```
8자 이하    절대 퍼뜨리지 않는다.  か？ · だ。 · な。 · です。
9자 이상    한 번만 보고 퍼뜨려도 된다 (1,000 종에 3 종 갈린다)
```

9자 이상을 접으면 볼 줄이 **14,517 -> 10,418** 로 준다.

§0 에서 중복을 정리하는 쪽으로 갈 때, 옛/새 양쪽에 있으면서 **번역이 갈린 것이
68 종** 있다.  접기 전에 그 68 종만 따로 뽑아 확인할 것.

## 6. 플래그

| 플래그 | 하는 일 |
|---|---|
| (없음) | 보고만 한다.  파일을 안 쓴다 |
| `--write` | 새 마스터를 `runtime_master_<시각>.tsv` 로 쓴다 |
| `--install` | 현역 `snatcher_ko_master.tsv` 자리에 설치 (백업 후) |
| `--keep-duplicates` | 옛 레코드가 이번 판과 내용이 같아도 보존.  **지금 이걸 쓴다** |
| `--no-keep-master-only` | 로그에 없는 현역 레코드를 버린다.  ⚠ §2-1 참고 |
| `--no-prior` | 직전 마스터를 무시하고 legacy 에서만 얹는다 |
| `--use-legacy` | `legacy_static_master.tsv` 를 다시 공급원으로 쓴다 (기본 끊김) |
| `--include-recovered` | 0.1.x 로그를 화자명 규칙으로 소급 복원해 섞는다 (94.6%) |

## 7. 수집 주행 쪽 (마스터가 아니라 로그를 만드는 쪽)

병합에서 자꾸 뭔가 빈다면 애초에 로그에 안 들어왔을 수 있다.

```
[ ] 올릴 수집기가 lua\RUNTIME_TEXT_AUDIT_0.2.3.lua 인가
       0.2.2 는 두 갈래이고 lua\ 쪽에는 음성 클립 덤프가 없다
       확인:  grep -c voiceDumpDir <올릴 파일>      0 이면 소리가 안 떠진다
[ ] C:\snatcher\snatcher_tool\logs\voice_clips\ 폴더가 있나
       없으면 첫 클립에서 "★★★ 음성 덤프 폴더가 없다" 만 찍고 지나간다
[ ] 첫 대사에서 화면 왼쪽 위 카운터가 "음성 1개" 로 오르는가
       0 에 멈춰 있으면 그 주행은 소리를 안 남긴다
```

2026-08-21 엔딩 주행을 덤프 없는 판으로 돌려서, ADPCM 재생 1,735 회에 클립 0 건으로
한 판을 통째로 날렸다.
