# SNATCHER ADPCM · CD-DA 제작방안 인계서

작성일: 2026-09-02  
프로젝트: SNATCHER PCE-CD 한국어 패치  
상태: 최신 마스터 및 Studio 자료 반영 완료, 음성 자막 네이티브화 설계 단계

## 1. 오늘 기준 결론

ADPCM과 CD-DA를 서로 다른 자막 엔진으로 유지하지 않는다. 자막을 화면에 그리는 부분은 하나의 공용 엔진으로 통합하고, 음성 감지와 시간표만 매체별 어댑터로 분리한다.

```text
ADPCM 감지 ─┐
            ├─ 공용 자막 레코드/스케줄러 ─ 공용 렌더러 ─ VDC/SATB 복원
CD-DA 감지 ┘
```

진행 순서는 다음과 같다.

1. ADPCM 네이티브 경로를 기준 구현으로 확정한다.
2. CD-DA는 기존 CD-DA 엔진을 그대로 얹지 않고, ADPCM 공용 엔진에 CD-DA 감지기와 타이밍 어댑터를 연결한다.
3. 두 매체를 동시에 탑재하는 통합판은 각각의 단독 검증이 끝난 뒤 만든다.

## 2. 현재까지 확정된 사실

### ADPCM

- 전체 음성 테이블은 이미 확보되어 있다.
- 현재 테이블 규모는 약 902키, 약 1,950 조각이다.
- 한 음성은 여러 조각으로 나뉘며, 검증된 POC는 3조각을 순차 출력했다.
- `0.5.64` 계열에서 `1/3 → 2/3 @ 90f → 3/3 @ 180f → 종료`가 정상 동작했다.
- ADPCM은 음성 재생 중 조각 전환과 종료 시점의 자막 정리가 핵심이다.
- 효과음 여부는 자동 분류하지 않는다. 사용자가 효과음으로 표시한 항목만 효과음으로 취급한다.
- 자막 파이프라인과 실제 네이티브 전체 연결은 아직 별도 작업이다.

### CD-DA

- 오프닝에서 CD-DA가 두 번 재생된다.
- CD-DA 자막 POC는 고정폭 2줄 출력만 지원한다. 2줄을 넘는 문장은 CD-DA 전용 데이터에서 먼저 접어야 한다.
- 정상 종료와 중간 스킵은 서로 다른 lifecycle이다.
- 자막이 모두 나온 뒤 스킵하면 화면이 정상 복귀한다.
- 첫 자막 또는 중간 자막에서 스킵하면 화면이 깨진다.
- 오프닝을 아예 보지 않고 스킵하는 경로는 CD-DA를 재생하지 않으므로 깨지지 않는다.
- 따라서 원인은 자막 데이터 자체보다 CD-DA 재생 중 화면 백업/복원 시점과 스킵 경로의 차이로 보는 것이 가장 타당하다.
- `0.5.102` Lua에서 CD-DA 중간 스킵 시 `$8411`에서 즉시 state `$02 → $03`으로 전환하는 경로가 정상 화면에 가장 가까운 기준이 됐다.
- 같은 경로에서 스프라이트 와이프는 필요하지만, 중간 스킵 시 VRAM 전체 복원은 오히려 깨짐을 만들 수 있어 생략하는 방향으로 검증됐다.
- 이 Lua 성공 경로를 네이티브로 옮기는 것이 CD-DA의 핵심 과제다.

### 공용 렌더러와 메모리

- AC에는 엔진을 여러 개 올릴 수 있지만, 같은 일을 하는 렌더러를 둘로 유지하면 초기 로딩과 충돌 지점이 늘어난다.
- AC 공간만의 문제가 아니라 BIOS 코드 영역, helper 영역, CPU 워킹램 영역과의 겹침을 반드시 확인해야 한다.
- 과거 통합 시 타이틀 화면과 스프라이트가 깨진 사례가 있었다.
- CD-DA 후보 공간 조사에서 CPU가 `$5B80` 부근을 실제로 쓰는 흔적이 확인됐다. 따라서 helper/활성 엔진/CPU 코드 주소를 고정하기 전에 읽기 전용 범위 검사를 먼저 수행한다.
- 기존 방식처럼 큰 엔진과 텍스트를 매번 워킹램으로 복사하는 구조는 CPU 병목과 그림 밀림을 만들 수 있다.
- 공용 엔진은 가능한 한 작은 상주 코드와 선택된 레코드만 복사하는 구조로 유지한다.

## 3. 권장 최종 구조

### 공용 데이터 레코드

매체에 관계없이 스케줄러가 다음 정보만 받도록 한다.

```text
media        ADPCM 또는 CDDA
voice_key    음성 식별자
part_index   현재 조각 번호
part_count   전체 조각 수
start_frame  출력 시작 기준
duration     음성 또는 조각 지속시간
text_ref     자막 텍스트/글리프 레코드
restore_mode 종료 또는 스킵 시 복원 방식
```

### ADPCM 어댑터

- ADPCM 재생 시작 이벤트에서 키를 확인한다.
- 해당 키의 조각 목록을 찾는다.
- 조각별 원본 start/duration을 사용한다.
- 다음 조각 예약은 프레임 기준으로 수행한다.
- 마지막 조각 종료 시 자막과 스프라이트 상태를 정리한다.
- 없는 키는 fail-closed로 처리한다. 임의의 빈자리나 다른 키를 선점하지 않는다.

### CD-DA 어댑터

- 트랙/섹터/재생 상태로 CD-DA 시작을 감지한다.
- CD-DA 전용 타임라인을 공용 레코드로 변환한다.
- 현재 POC의 2줄 고정폭 제한을 데이터 검증 단계에서 강제한다.
- 정상 종료와 중간 스킵을 별도 상태로 관리한다.
- 정상 종료는 기존 Lua 성공 경로의 refresh/복원 순서를 유지한다.
- 중간 스킵은 즉시 종료 상태로 전환하고, 필요한 스프라이트 와이프만 수행한다. 자막이 끝났다는 이유로 항상 VRAM 전체를 복원하지 않는다.
- 자막 시작 전 스킵과 CD-DA가 없는 스킵에는 개입하지 않는다.

### 공용 렌더러

- ADPCM과 CD-DA가 같은 텍스트 레코드 및 글리프 변환을 사용한다.
- 한 프레임에 여러 번 큰 블록을 복사하지 않는다.
- 현재 정상 출력된 렌더링 경로를 유지하고, 자막 파이프라인은 데이터 공급부로만 연결한다.
- CD-DA 2줄 제한과 ADPCM 조각 수 제한은 렌더러가 아니라 각 어댑터/데이터 검증에서 처리한다.

## 4. 제작 단계

### 단계 A — 기준판 고정

- 최신 마스터는 `SNATCHER_ENV_B_20260902_0821`에서 반영됐다.
- 현재 마스터는 16,075행이다.
- Studio 소스도 최신본으로 반영됐다.
- 반영 전 작업본은 다음 위치에 보관돼 있다.

  `C:\snatcher\_archive\office_merge_backup_20260902_0821`

- 가우디 사전의 수동 꼬리 수정 자료는 다음 파일들을 기준으로 추적한다.

  - `snatcher_tool\translation\fix_dict_tails_20260821.tsv`
  - `snatcher_tool\translation\fix_broken_tails_20260821.tsv`
  - `snatcher_tool\translation\fix_broken_tails_20260822.tsv`
  - `snatcher_tool\translation\fix_broken_tails_20260822_2.tsv`

- 최신 마스터에 병합할 때 위 자료를 키별로 대조하고, 최신 추가 행은 유지한다. `{EMPTY}` 14개는 자동으로 번역하지 말고 원문 분할용 빈 슬롯인지 확인한 후 결정한다.

### 단계 B — ADPCM 단독 확정

- 공용 렌더러의 기준은 현재 3조각 정상 출력 POC로 둔다.
- 먼저 대표 3조각, 1조각, 마지막 조각, 키 미스, 연속 음성 전환을 검증한다.
- 각 검증은 자막 출력, 조각 전환, 음성 종료, UI 복귀를 분리해 기록한다.
- ADPCM 단독판에서 화면 깨짐과 UI 복귀 실패가 없어야 다음 단계로 간다.

### 단계 C — CD-DA 어댑터 연결

- CD-DA 엔진을 별도 렌더러로 추가하지 않는다.
- CD-DA 감지기와 2줄 타임라인만 공용 엔진에 연결한다.
- 오프닝 두 재생을 각각 정상 종료와 중간 스킵으로 시험한다.
- 특히 첫 자막 직후 스킵, 두 자막 출력 후 스킵, 자막 전 스킵을 각각 비교한다.
- `$8411` 조기 state 전환, sprite wipe, VRAM 복원 생략 여부를 한 항목씩 네이티브로 재현한다.

### 단계 D — 통합판

- ADPCM 단독과 CD-DA 단독 결과가 각각 고정된 뒤 통합한다.
- 통합 전 AC, BIOS, helper, CPU 코드 범위의 읽기/쓰기/실행 충돌을 자동 검사한다.
- 통합판에서는 매체별 감지 이벤트가 서로의 상태와 자막을 덮지 않는지 확인한다.
- 마지막에 자막 파이프라인을 연결한다. 파이프라인 연결은 렌더러 교체가 아니라 레코드 공급 방식으로 제한한다.

## 5. 절대적으로 피할 것

- ADPCM 엔진과 CD-DA 엔진을 각각 완성된 렌더러로 동시에 탑재하지 않는다.
- CD-DA의 2줄 고정폭 문제를 ADPCM 방식으로 억지로 해결하지 않는다.
- 자막이 끝났다는 이유만으로 중간 스킵에서 원본 VRAM 전체를 복원하지 않는다.
- AC가 비어 보인다는 이유만으로 BIOS/helper/CPU 영역에 새 코드를 배치하지 않는다.
- 로그가 없다는 이유로 성공/실패를 추측하지 않는다. 읽기 전용 계측으로 분기와 실제 쓰기 위치를 먼저 확인한다.
- 효과음 여부를 자동 추정하지 않는다.
- 전체 902키를 한 번에 네이티브에 올리기 전에 대표 경로와 메모리 범위를 검증한다.

## 7. 한 줄 요약

ADPCM을 공용 자막 엔진의 기준으로 확정하고, CD-DA는 별도 엔진을 하나 더 올리는 대신 감지기·타이밍·복원 정책만 어댑터로 붙인다. CD-DA의 성공 여부는 자막 출력보다 중간 스킵 시 복원 순서를 네이티브로 재현하는 데 달려 있다.
