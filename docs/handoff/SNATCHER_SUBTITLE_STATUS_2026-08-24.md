### 자막 자리는 된다

CD-DA 전체가 아니라 **자막 한 줄 단위**로 정할 수 있다.
TSV 의 `pos` 열에 `위`/`중간`/`아래`. 비면 기본값.
**스튜디오 버튼은 아직 없다.**

## 3. ★ 지금 걸려 있는 문제 — ADPCM 70 조각이 팩에 안 들어간다

```
★ ADPCM 지문 충돌 31 건 (서로 다른 이벤트끼리)
★ 원본에 있는 ADPCM 자막 70 개가 팩에 없다
   '길리언이라고 해, 미카.' · '그냥 길리언이라고 불러.' · '그렇습니다. 3년 전' ...
```

119 조각 중 **49 개만** 들어간다. CD-DA 는 327/327 전부 정상이다 — LBA 구간이
열쇠라 충돌이 없다.

> **어제 검증한 것은 그대로다.** 퇴보가 아니라 데이터가 늘면서 드러난 한계다.
> 어제 테스트한 세 대사(끝 6800 · 5800 · D000)는 지금 팩에도 조각까지 다 살아 있고,
> 접수처에서 켜면 똑같이 나온다. 6 조각일 때는 안 겹쳤을 뿐 열쇠 방식은 같았다.

### 원인

지문 열쇠가 **끝 주소**(`읽기주소 + 길이`)다. 그래야 런타임과 맞는다:

```
팩 0063+CF9D = D000     런타임 0068+CF98 = D000
팩 0066+579A = 5800     런타임 0064+579C = 5800
```

재생 시작 지점이 매번 달라 읽기주소와 길이가 서로 상쇄되고 **합만 안 변한다.**
그런데 그 대가로 **서로 다른 이벤트가 같은 열쇠를 받는다.** 빌더는 열쇠 하나에
이벤트 하나만 달 수 있어서 (대사 > 기타 > 효과음 순), 진 쪽 자막이 통째로 빠진다.

기존 연구가 이미 경고했다: **449 이벤트 -> 71 열쇠**.

### 풀 방향 (아직 안 정함)

```
A  열쇠에 무언가를 더한다        끝 주소만으로 모자라니 다른 불변량을 찾는다
                                예: 클립 내용 해시의 앞 몇 바이트를 런타임에 계산
B  장면으로 좁힌다               같은 열쇠라도 지금 장면이 다르면 다른 대사다
                                오버레이/씬 번호를 같이 본다
C  한 열쇠에 여러 후보를 싣는다    런타임이 그중 하나를 고른다.  고르는 기준이 필요
```

먼저 **31 건이 실제로 어떤 이벤트끼리 부딪히는지** 뽑아 봐야 한다.
같은 대사의 다른 녹음이면 아무거나 써도 되고, 정말 다른 대사면 A/B 가 필요하다.

## 6. 다시 만드는 법

```bash
python tools/subtitle_layout.py                  # 자리표 겹침 검사
python tools/build_subtitle_pack.py && python tools/verify_subtitle_pack.py
python tools/build_subtitle_engine.py --max-glyphs 19 --text "금일부로 JUNKER로 임명된"
python tools/build_subtitle_resident.py          # 디스크
```

**검증기를 꼭 같이 돌릴 것.** 위 3 번 문제가 그것으로 드러났다 —
빌더는 "다 구웠다" 고 하고, 검증기가 "원본 70 개가 빠졌다" 고 한다.

엔진을 다시 구우면 `engine.json` 의 `offsets` 가 바뀔 수 있다.
Lua 의 `OFF` 표와 맞출 것 (지금 `ready 138 · list 139 · count_x 44 · count_a 130 · org 98`).
