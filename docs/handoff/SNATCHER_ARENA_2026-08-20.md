## 1. 결론 — 3 바이트였다

**해결됨.  실기 검증 완료.**

게임 스크립트 VM 의 데이터 스택이 `$5C00` 에서 위로 자란다.
우리 프리로더가 `$5E40` 을 차지하고 있어서 스택이 576 B 밖에 못 썼다.
쇼핑 화면은 **579 B** 를 요구했다.

    스택 포인터가 $5E43 까지 올라감
      -> 지역변수 쓰기가 base-3 = $5E40 을 때림
      -> 프리로더 첫 바이트 PHX($DA) 가 $00 으로 지워짐
      -> 다음 JSR $5E40 이 $00 = BRK 실행
      -> BRK/IRQ 폭주

원판은 `$5C00-$5FFF` 1,024 B 를 다 쓰므로 445 B 가 남는다.
**원판이 멀쩡하고 다른 UI 가 안 죽은 이유가 이것이다.**

### 수정

    $4880   A9 00 85 25 A9 5C 85 26   ->   A9 80 85 25 A9 5B 85 26
            스택 바닥 $5C00 -> $5B80          용량 576 B -> 704 B

빌더에 정식 반영됨: `build_direct_overlay_patch_ui.py` 의 `arena_floor` 패치.
프리로더 위치를 옮기거나 바닥을 올려 704 B 미만이 되면 **빌드가 실패**한다.

빌드: `build\patch\0.4.5.3`

## 2. 어떻게 찾았나 — 전부 정적 분석

프로브를 새로 돌리지 않고 디스크에서 코드를 읽어 끝냈다.

    1. 원판 $5E40-$5FFF 는 전부 $FF -- 그래서 빈 칸으로 오해했다
    2. Mesen 이 보여준 [$5E40] = $DA 는 쓰인 값이 아니라
       **우리 프리로더의 첫 명령 PHX** 였다 (쓰기 직전 스냅샷)
    3. $825A 를 전 트랙에서 찾았다 -- `92 7E` 가 섹터 선두 +$25A 에 오는
       곳은 Track 02 섹터 339 한 군데뿐
    4. 그 코드가 `LDA $25 / SBC #$N / STA ($7E)` -- $25/$26 기준 음수 오프셋
    5. $25/$26 을 까는 곳을 찾으니 상주 엔진 bank $68 의 $4880
    6. $5C00-$5FFF 를 절대주소로 참조하는 코드는 전 뱅크에 0 건
       -> 바닥은 패치 가능하다

§13 의 가설 열두 개(훅 · 폰트래퍼 · $2200 벡터 · CD IRQ · 뱅크스왑 IRQ 등)는
전부 **증상**을 보고 있었다.  BRK 루프와 IRQ2 는 잘못된 코드를 실행한 뒤의
잔해다.

## 3. 정정 두 가지

### 3.1 "범프 할당기" 가 아니라 스크립트 VM 데이터 스택

    $8D7A  push     PHA / ptr+1 / PLA / STA ($25)
    $8D9E  pop X    LDA ($25) / PHA / ptr-1 / PLA / TAX

`$4880` 이 까는 것은 **스택 바닥**이고 값은 올라갔다 내려갔다 한다.
재는 값은 "할당량" 이 아니라 **최대 스택 깊이**이고, 그걸 좌우하는 것은
목록 길이가 아니라 **스크립트 중첩 깊이**다.

수정과 위험 조건은 그대로다 -- 포인터가 `$5E40` 을 넘으면 죽는다.

### 3.2 PROBE_ARENA 0.1.2 로 잰 값은 무효

`$2025` 와 `$2026` 을 따로 읽었다.  갱신이 `STA $25` -> `STA $26` 두 명령이라
그 사이를 읽으면 (새 하위 + 옛 상위) 라는 없는 주소가 나온다.

    BASE lowered to $5B01 / $5B00     스택 바닥 아래 -- 불가능
    $5D09 -> $5DFF 한 걸음에 246 B    스택이 그렇게 뛸 리 없다

**"최고 $5DFF · 여유 65 B" 를 근거로 판단하지 말 것.**
`PROBE_ARENA_0.1.3` 이 고친 판이다 (쓰기 콜백의 value 를 상위 바이트로 사용).

## 4. 다음 세션 첫 할 일 — 스택 최대 깊이 실측

지금 아는 유일한 실측치는 쇼핑 화면 **579 B** 뿐이다.
게임 전체 최댓값을 모른다.  원판은 1,024 B 를 주고 우리는 704 B 를 준다.

    최대 <  704 B   ->  이 2 바이트가 최종 수정.  끝
    최대 >= 704 B   ->  프리로더를 bank $68 밖으로 빼야 한다 (아래 5절)

### 방법

    빌드      build\patch\0.4.5.3
    스크립트  snatcher_tool\mesen\PROBE_ARENA_0.1.3.lua
              (수집기 runtime_text_audit.lua 와 동시 실행 가능)
    ★ 전원 투입부터.  세이브스테이트로 들어가면 바닥을 못 본다
    출력      dump\probe_arena_0_1_3.tsv

Script 로그에 **최고 깊이 갱신 때만** 한 줄.  조용하면 안전하다는 뜻이다.
새 최고치마다 호출자 PC 와 MPR4/5/6 을 같이 찍으므로 어느 화면이 깊이 파는지
로그만 보고 알 수 있다.  `LEFT` 가 64 B 이하로 떨어지면 경고가 뜬다 --
그때 **그 화면이 어디였는지 기록할 것.**

일부러 가볼 곳: 쇼핑하기 / 인물검색 / 아이템 / 전화번호부 / 세이브·로드 목록 /
조사 메뉴가 긴 방.  나머지는 평소 수집하면서 저절로 쌓인다.

## 5. 704 B 를 넘으면 — 최종 수정 후보

프리로더 448 B 는 전부 실코드다 (테이블·패딩 없음).  상주 오버레이 24 KB 의
빈 공간은 bank $69 에 166 B 뿐이라 그냥 옮길 자리가 없다.

    (a) 해시 루틴($5E7B-$5EF9, 약 127 B)만 bank $69 로 이전
        -> 스택 용량 831 B.  트램펄린($7F88)이 이미 있어 구조 변경 아님.  ★ 유력
    (b) 새 CD-RAM 뱅크 확보 후 본체 전체 이전
        -> 훅과 같은 창(bank $6A)의 스텁 자리가 2 B 뿐이라 까다롭다
        -> 게다가 빈 뱅크가 있는지부터 미확인 ($4893 이 $3F80 으로 계산한다)
    (c) 스택을 다른 영역으로 통째 이사
        -> 절대참조 0 건이라 가능은 하다

## 6. 별건 — MPR 뱅크 스왑 IRQ 가드

**쇼핑 크래시와 무관하다.  섞어서 설명하지 말 것.**

`$7F88` 트램펄린이 MPR5 를 갈아끼우는 창에 TIMER IRQ 가 실제로 들어오는 것이
관측됐었다.  방어는 **이미 들어가 있다** (0.4.5.2/0.4.5.3 바이트 확인):

    7F88  PHP / SEI / TMA #$20 / PHA / LDA #$69 / TAM #$20
          JSR $BCD2 / STA $7FEE / PLA / TAM #$20 / PLP / LDA $7FEE / RTS

`SEI`->`CLI` 가 아니라 `PHP`/`PLP` 다.  진입 시 IRQ 가 막혀 있었으면 그대로
막힌 채 나간다.  남은 확인: 헬퍼 `$BCD2` 의 모든 탈출 경로에서 P 와 MPR 이
복원되는지 (감사 도중 중단됨).

## 7. 오늘 나온 규칙

    디스크에서 $FF   != 빈 공간
    Write 를 못 봤다 != 안전
    Write 를 봤다    -> 그 자리를 쓰는 **루틴을 찾아 범위를 계산**한다

$5E40 하나만 보고 끝냈다면 "$5E40 만 피하자" 가 됐을 것이다.
스택 바닥을 찾았기에 **$5C00-$5FFF 전체가 금지 구역**임을 알았다.

그리고: **프로브가 잰 값을 믿기 전에, 그 프로브가 그 값을 잴 수 있는지 먼저
확인한다.** 0.1.2 는 두 바이트를 따로 읽어서 없는 주소를 만들어냈다.
