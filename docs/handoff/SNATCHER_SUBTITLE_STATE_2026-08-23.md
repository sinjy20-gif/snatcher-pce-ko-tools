## 2. 컷신 자막 — 닫힌 것

전부 실측 근거가 있다. 추정치가 아니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 프레임 훅 | `$2202 → $40A4` (IRQ1/VDC). MPR2=$68 상주 | `PROBE_OPENING_HOOK_0.1.1` |
| 음성 트리거 | `CD_PLAY ← $60E4` | 같은 프로브 |
| 시계 | `CD_SUBQ ← $6119` → 절대 M:S:F (BCD) | CD-DA 는 75섹터/초 하드웨어 시계 |
| 실행 RAM | `$5C40-$5E1F` 480 B | BIOS 폰트 전환으로 비운 글리프 슬롯 3-17 |
| 버퍼 RAM | `$2311` 807 B · `$3468` 664 B | `PROBE_DEAD_RAM_0.1.1` (CD_PLAY 게이트) |
| VRAM | `$7B00` 부터 슬롯 20개 (2,560 B) | 컷신마다 다름. 상수로 박으면 안 됨 |
| SAT | 64 엔트리 전부 사용 가능 | `spritesEnabled=false` + `$1000` 이 전부 0 |
| AC 예약 | `$1C0000` 256 KB | 빌더가 감사. 침범 시 빌드 실패 |
| 케이브 로더 | 80 B 예약 (실측 69 B) | 잔여 71 B |
| 진입 트리거 | 스텁 `$7CEF` (MPR3=$69). 씬 스폰마다 | `PROBE_SUBS_TRIGGER_0.1.0` · 52회 전부 적중 |

## 3. 컷신 자막 — 남은 것 4개

```
1. AC 배치     893 B 를 $1C0000 예약 구역에 굽는다              빌더 스테이지
2. 로더 배선   케이브에 로더 69 B · $7331 표를 스텁→로더→$73BD  빌더
3. $26F9      트랙번호를 읽는다                                 프로브
4. ASCII      팩에 한글 2,350자만 있다. 영문 글리프 추가         글리프 파이프라인
```

### 3번이 왜 필요한가

`CD_PLAY` 적중만으로는 컷신을 식별할 수 없다. **스내처는 BGM 도 CD-DA** 라
플레이 중 BGM 재생이 전부 같은 자리에 걸린다 (프레임 1268·30631·38888·40096
적중 중 오프닝은 1회뿐). 컷신마다 자막을 갈아야 하므로 트랙 번호가 있어야 한다.

`$26F9` 에 트랙 번호가 있다는 것은 이미 확인됐다 (`$C0D7 LDA $26F9`).
다음 프로브에 이것을 넣을 것.

## 4. 게임 내 음성 자막 — 상태

### 4.1 오늘 새로 확정된 것 (2026-08-22~23)

**대사 버퍼는 `$3619` 다.** `PROBE_VOICE_VS_TEXT_0.1.1` 이 값까지 확인했다:

```
OUT  3619  83 6E   ハ        Shift-JIS 그대로
OUT  361B  83 8A   リ
OUT  361D  81 5B   ー        = "ハリー"
OUT  361F  FF      종료
```

**그리고 게임은 음성 재생 중에 텍스트를 아예 만들지 않는다.**

```
음성 구간 14개 · 그중 버퍼 쓰기 있음 0개
버퍼 쓰기   음성 밖 1,223회 · 음성 중 0회
```

훅이 죽어 있던 게 아니다 (1,223회 잡힘). 음성 중에만 0이다.
`PROBE_INJECT_TEXT_0.1.0` 으로 버퍼에 직접 써넣어도 화면에 안 떴다 —
게임이 그때 렌더러를 안 부르기 때문이다.

**결론: 억제 로직을 끄는 문제가 아니다. 스크립트에 그 텍스트가 없다.**

### 4.2 스프라이트 경쟁자가 있다 — 컷신과 다른 점

`CUTSCENE_SUBS §7.3` 이 "SAT 64엔트리 전부 쓸 수 있다" 고 한 것은
**오프닝 한정**이다. 오프닝은 스프라이트를 아예 안 켠다.

일반 대사 장면을 VRAM 덤프에서 재보니 다르다:

| 장면 | 사용 슬롯 | 최대 번호 |
|---|---|---|
| 1인 대사 | 7 | 6 |
| 1인 대사 | 5 | 4 |
| 3인 초상화 | 26 | **27** |

여유는 있다 (64 중 36개). 자막 한 줄에 필요한 것은 슬롯 9~16개.
다만 **"경쟁자 없음" 전제는 여기서 성립하지 않는다.**

화면 배치도 컷신보다 까다롭다. 초상화 위치가 고정이 아니다 —
왼쪽 아래에 오는 장면도, 오른쪽 아래에 오는 장면도 있다.

### 4.3 BIOS 케이브 (`SUBTITEL 0.2.x`) — 미해결

```
0.2.3  팔레트만            PASS
0.2.4  $7B00 에 패턴 업로드  부팅 PASS · 대사 안 나옴
0.2.5  케이브 스택 수정      부팅 FAIL
0.2.6  레지스터 보존 + TAI   부팅 FAIL
```

**버그가 있던 0.2.4는 부팅했는데 고친 판들이 부팅을 못 한다.** 진단이 아직
원인을 못 짚었다는 뜻이다.

확인된 사실:
- 바탕 BIOS 는 무혐의 — `Syscard3_galmuri.pce` 는 형이 플레이하는 파일과 **0바이트 차이**
- 케이브 자리 `$FEC4` 는 원본이 전부 `FF` 인 진짜 죽은 영역 (한도 280 B)
- 훅 2곳은 ADPCM 경로다:
  - `$F61A  STA $180D`  재생 시작 루틴의 마지막 줄
  - `$F6EF  LDA $180C`  상태 폴링 루틴. **`$F6E7 TAX` 가 X 를 반환 레지스터로 쓴다**
- 0.2.5 복원 경로에 `TAI $1A00,$5B80` 가 남아 있었다 — 8/21 에 깨진 것으로 기록해둔
  바로 그 명령. 설치 경로만 고치고 복원은 놓쳤다 (0.2.6에서 수동 루프로 교체)
- HuC6280 블록 전송(`TII/TIN/TAI/TIA/TDD`)은 A·X·Y 를 파괴한다.
  0.2.5 `stat` 은 아무것도 밀지 않고 그것을 돌렸다 (0.2.6에서 PHP/PHX/PHY 추가)

0.2.6 이 여전히 실패하므로 **위 두 수정은 원인이 아니었거나, 원인의 일부였다.**

## 5. 같은 것을 두 번 판 기록

2026-08-22 밤에 아래를 다시 팠다. 전부 8-19 문서에 있던 것이다.

```
프레임 훅이 필요하다        -> $2202 -> $40A4 로 이미 확정
음성 재생 감지              -> CD_PLAY <- $60E4 로 이미 확정
자막 그릴 자리가 없다        -> $7B00 슬롯 20개로 이미 확정
스프라이트로 갈까 BAT 로 갈까 -> 스프라이트 · 한 줄 · 단일버퍼로 이미 확정
```

원인은 단순하다. **문서를 읽지 않고 시작했다.** 그리고 `lua/` 에 프로브가
105개 있는 것도 못 봤다 (`SUBTITLE 0.5.1`~`0.6.1` 만 10판).

교훈을 규칙으로:

```
자막 작업을 재개할 때는 이 문서 -> CUTSCENE_SUBS -> lua/README.md 순으로 먼저 읽는다
새 Lua 를 만들기 전에 lua/ 를 ls 한다
```
