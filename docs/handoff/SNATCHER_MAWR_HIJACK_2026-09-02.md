## 4. ⚠ MAWR 은 읽을 수 없다

HuC6270 에서 MAWR 은 **write-only** 다.  그래서 "빌리기 전 값을 떠뒀다가 되돌린다"
가 원리적으로 안 된다.  `0.4.6.52` 가 상수 `$1000` 을 박은 것이 그 때문일 것이다.

★ 그런데 **이 장면에서는 상수 `$1000` 이 정답이다.**  게임이 line 31 에 `$1000` 을
  잡고 line 202 까지 한 워드도 안 썼다 (`pre` 36 word 는 전부 우리 wipe).
  되돌릴 값이 정확히 `$1000` 이다.

⚠ 다른 장면에서도 그런지는 **안 쟀다.**  범위 확인이 필요하다.

## 5. ★ 0.4.6.52 의 실패를 MAWR 탓으로 돌리지 말 것

09-01 원장은 `.52/.55/.56/.57/.58` 을 전부 "자막 O · 챕터1 X" 로 적었고,
FRAGMENT_TEAR §6 은 그것을 "0.4.6.52 가 헬퍼 8 B 로 고쳤는데 안 실렸다" 로 적었다.
둘 다 부정확하다.

09-01 §5-2 를 보면 그 8 B 의 출처가 나온다:

> `.48`  `18 AD 1E 5D 69 40 85 08 A9 00 69 00 85 09`  y = record+3 을 읽어 +$40 (16bit)
> `.5x`  `64 08 A9 01 85 09`                          y = $0100 상수 (-8 B)
> 그 8 B 로 MAWR 복원을 넣었다
>
> 그 계산이 곧 **자막 세로 자리(위/중간/아래)** 기능이다.  상수로 바꾸면 기능이 죽는다

**MAWR 복원은 단독으로 시험된 적이 없다.**  항상 렌더러의 y 계산을 죽여서 자리를
마련했고, 챕터1 파손이 어느 쪽 탓인지 갈리지 않았다.

★ 다시 할 때는 **y 계산을 건드리지 않는 자리에서** 8 B 를 마련하고, MAWR 복원만
  단독으로 켠 판을 만들 것.

## 9. 오늘 같이 고친 것 — CD-DA 예약 자리 $79xx

이 건과 **별개**다.  같은 날 나왔을 뿐이다.

헬퍼의 복원은 목적지 상위바이트 하나로 지우기/되쓰기를 가른다
(`LDA vram_hi / CMP #$79 / BNE write_chunk`).  `$79` 면 백업을 버리고 0 을 쓴다.
CD-DA 는 되돌릴 원본이 없어서 그렇게 정했다 (0.4.6.58).

그런데 판정이 **매체가 아니라 주소**로 되어 있어서, 자리를 키별로 나눠주자
ADPCM 키도 `$79xx` 를 받게 됐다.  그러면 백업이 멀쩡한데도 blank 로 가서
그 자리가 까맣게 남는다 -- 1 프레임 찢김이 아니라 **지속 손상**이다.

```
고친 곳   tools/build_vram_key_bases.py
          CDDA_RESERVED_HI / is_cdda_reserved()   왜 $79 가 예약인지 주석과 함께
          base_a 가 $79xx 면 B 와 맞바꿈          B 는 같은 측정 · 같은 뱅크
          빌드 관문                                남으면 SystemExit
          override 가 $79 를 지정하면 조용히 안 바꾸고 세운다

결과      키수 1157 -> 1157 · 사라짐 0 · 새 키 0
          base_a 바뀐 키 15 · 전부 순수 A/B 맞바꿈 · 그 외 0
          남은 $79xx 0 · 15 키 뱅크경계 0 · 0x100 정렬 OK
```

### 9-1. ★ 표를 다시 구울 때의 정본 인자

```
python tools/build_vram_key_bases.py --pairs --align 0x100
```

`--align` 을 빼면 기본 `0x20` 이 되어 base 가 전부 밀리고(`51A0` `4EE0` …)
키도 1157 -> 1163 으로 늘어 **2,290 행이 바뀐다.**  오늘 한 번 밟았다.
BUILD_CHAIN §1 에 이 인자가 없으니 다음에 또 밟는다.

백업: `_backup_vram_bases_20260902/`

⚠ 이 수정은 **아직 디스크에 안 실렸다.**  base 즉치값은 네이티브 디렉터리
(route 당 9 B 의 뒤 3 B)에 들어가므로 표만 고쳐서는 반영되지 않는다.
팩 자체는 안 바뀌므로 팩 자리 왕복(BUILD_CHAIN §2)은 안 생길 것이다.
