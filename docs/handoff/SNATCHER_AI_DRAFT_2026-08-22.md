## 2. 이어서 하는 법 — 세 단계

```

(`SPEAKER_STYLE.md` 의 지시).  섞어 돌리면 화면에 한자가 나온다.

## 4. ★ 꼬리행 오염 — 비워뒀다.  소유자가 채운다

짧은 일본어 꼬리(`な。` `ません。` `です。`)에 **그 레코드와 무관한 문장**이 박힌
행이 있었다.  편입이 끌고 온 것이라 보존할 이유가 없다.

```
R07567 L1 <원문 8자>、<원문 9자>   (미번역)
       L2 な。                    >> "가능성도 있겠군."   <- 무관
```

식별 신호는 **"앞줄이 비었는데 뒷줄만 채워져 있다"** 이다 (213 레코드).  다만 그
중 상당수는 정상이다 -- 한국어는 어순이 달라 꼬리줄이 긴 문장을 받는 것이 오히려
정상이고(`ません。` -> "들여보낼 수는 없습니다."), `{EMPTY}` 꼬리도 정상이다.
**단순 길이·중복 휴리스틱으로는 못 가른다.**  실제로 자동 탐지는 166 건을 물어오는데
"어떻게 하시겠습니까?"(17 회) 같은 **짧은 정형구의 정상 반복**이 대부분이다.
레코드 내용과 대조해야 한다.

번역하면서 하나씩 대조해 **실제로 어긋난 72 건만** 골랐고, 2026-08-22 소유자 지시로
고치는 대신 **비웠다** (`ko_text` 공란 · `status` -> `todo`).

```
채울 자리(레코드 문맥째)  snatcher_tool/translation/tail_rows_to_fill_20260822.txt
지웠던 내용 보존           dump/tail_blanked_20260822_092530.tsv
백업                       snatcher_tool/backups/20260822_092530_before_tail_blank_*.tsv
72 건 중 44 건이 검토 O 였다 -- 그 O 는 믿을 수 없는 표시였다는 뜻이다
```

`snatcher_tool/translation/fix_broken_tails_20260822.tsv` 에 내가 만든 교정안 72 건이
그대로 있다.  **참고용이다** -- 적용하지 않았다.

### 도구 버그 (미수정)

`apply_translations.py` 는 마스터를 **줄 단위**로 읽는데, 마스터에는 `ko_text` 안에
진짜 개행이 든 행이 79 개 있다(정식 수단 -- 코덱이 `FD 81 40` 으로 인코딩한다).
그런 행을 배치 대상으로 삼으면 열이 모자라 `IndexError` 로 죽는다.
실제로 `R08291:2` 에서 죽었다.  **쓰기 전에 죽으므로 마스터는 안전하다.**

빈 행을 채우는 평소 작업은 안 걸린다(빈 행에는 개행이 없다).  덮어쓰기가 필요하면
`tools/apply_ko_overwrite.py` 를 쓴다 -- CSV 로 읽고 쓰며 칸수를 줄마다 센다.

```
