# 0.6.1 폐기 — 2026-09-07

## 증상

트랙 20 이후 **모든 ADPCM 자막이 죽는다.** 간헐적이 아니라 그 지점부터 전부.

## 원인

rc9 의 2바이트 변경 `$EEE1  B0 0B (BCS $EEEE) -> EA EA`.

`cdda_wait_stop` 의 철거 사유는 둘이었다:

```
$EEE1  BCS $EEEE      자막 목록을 다 썼다 -> 철거     ← 지웠다
$EEE9  BNE $EEEE      $20A2 != $5E1B     -> 철거     ← 남겼다
```

지우고 나니 철거가 `$20A2` 가 바뀌는 것에만 걸린다. 그것이 안 바뀌면 CD-DA 가
state 2 에 영구히 머문다. state 2 인 동안 CD-DA 가 `$5B80` 임대를 쥐고 있으므로
**그 뒤로 ADPCM 이 영영 슬롯을 받지 못한다.**

보장된 탈출구를 지우고 조건부 탈출구만 남긴 것이 잘못이다.

## 검증이 왜 못 잡았나

메센 `arms=1`, Mednafen 트랙 20 1회, RetroArch 트랙 20 1회 — 셋 다 통과했다.
그러나 셋 다 **트랙 20 장면 자체만** 봤고 **그 뒤를 안 봤다.**

`arms=1` 이 증명한 것은 "재무장이 없다" 뿐이다. "정상 철거된다" 는 증명하지
않았다. 철거 계수 `teardowns=1` 이 같이 나왔지만, 그것은 그 트랙이 끝날 때
`$20A2` 가 바뀌어 철거된 것이라 다음 장면 이후를 말해주지 않는다.

★ 다음에 철거 경로를 건드릴 때는 **그 뒤 장면까지** 진행해서 다음 무장이
   정상으로 일어나는지 확인한다.

## 되돌리기

0.6.1 에서 `$EEE1` (파일 오프셋 `0x02EE1`) 을 `EA EA` -> `B0 0B` 로 되돌리면
rc3 가 바이트 단위로 복원된다. 해시로 확인했다:

```
352A600040B34C1E54999387B36FA8CD5CE52714818152C69FAA3135D6E7BD8A
```

복원본은 `build/patch/0.6.0-rc3-restored/` 에 있다.

## 원래 문제는 아직 안 풀렸다

CD-DA 재무장(트랙 20 자막이 두 번 잡히는 것)은 그대로 남아 있다.
규명 내용은 이 폴더의 `FINDINGS_2026-09-07.md` 에 있고, 그 진단(시계가 둘이다)
자체는 여전히 유효하다. 틀린 것은 **처방**이다 — 철거를 없애는 방향은
`$5B80` 임대 때문에 쓸 수 없다.
