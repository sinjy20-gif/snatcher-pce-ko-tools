# CD-DA 자막 재생 — 2026-09-07 규명 및 확정

rc9 로 해결. 이 문서가 오늘 건의 최종 기록이다.
`build/patch/0.6.0-rc7-gate-edge/FINDINGS_2026-09-07.md` 는 관문 방향을
권하고 있으니 **이 문서로 대체된 것으로 읽는다.**

## 원인 — 시계가 둘이다

| | 무엇이 결정하나 | 트랙 20 실측 |
|---|---|---|
| 철거 | **자막 목록이 떨어지면** | 1,533프레임 = 25.5초 |
| 무장 | **트랙이 재생 중이면** | 음악 1,782프레임 = 29.7초 |

관문(`$F898`)은 `LDA $263C / ORA $2638 / BNE` 로 **"CD-DA 가 켜져 있나"**를
묻는다. 사건이 아니라 상태다. 자막이 떨어져 철거된 뒤에도 트랙은 4.2초가
남아 있으므로 관문은 계속 "응"이라고 답하고, **철거 다음 프레임에 그대로
다시 무장한다.**

    f684  무장 → f2217 철거 → f2218 재무장 → f2466 트랙 끝

트랙 20 만의 문제가 아니다. **자막이 음악보다 먼저 끝나는 트랙은 전부**
이 모양이었다. 트랙 20 에서 눈에 띈 건 남은 4.2초가 두 번째 판의 첫 자막
(12.9초)에 닿느냐 마느냐 경계에 걸려서다. 그래서 메센에서는 두 번째 판이
화면에 안 나오고(4.15초 만에 트랙이 끝난다), Beetle 에서는 나왔다.
**에뮬 차이가 아니라 남은 트랙 시간이 얼마냐로 갈리는 경주였다.**

## 고친 곳 — `$EEDB cdda_wait_stop` 이 기다리지 않았다

`$5CF3` 에 드레인 표시 `#$FE` 가 서면 `$ED70` 이 매 프레임

    LDA $5CF3 / CMP #$FE / BNE $ED7A / JMP $EEDB

로 `cdda_wait_stop` 으로 보낸다. 이름은 "멈추기를 기다린다" 인데 들어오자마자
멈추고 있었다.

```
$EEDB  BD 03 21   LDA $2103,X    쓴 자막 수
$EEDE  DD 04 21   CMP $2104,X    전체 자막 수
$EEE1  B0 0B      BCS $EEEE      -> EA EA 로 제거   ★ 이 2바이트
$EEE3  AD A2 20   LDA $20A2
$EEE6  CD 1B 5E   CMP $5E1B
$EEE9  D0 03      BNE $EEEE      트랙이 바뀌었다 -> 철거 (진짜 종료 조건)
$EEEB  4C 0F EF   JMP $EF0F      계속
```

`$EEEE`(철거)로 들어오는 길은 `$EEE1` 과 `$EEE9` 둘뿐이다. 하나를 지우면
철거 사유가 "트랙이 실제로 바뀌었다" 하나만 남고, 재무장할 기회 자체가
사라진다. **관문은 손대지 않는다.**

`$EEDB` 로 들어오는 길은 `$ED77` 하나뿐이고 드레인 표시가 선 뒤에만 온다.
이 상태에서는 렌더링을 하지 않으므로 목록 끝을 넘어 읽지 않는다.

## rc9

rc3 + 2바이트. `$EEE1` (파일 오프셋 `0x02EE1`) `B0 0B` -> `EA EA`.
길이 불변. `$EEE1/$EEE2` 로 들어오는 분기·점프 0건(상대 분기 포함 확인).

    BIOS SHA-256  D1515996CE5595459BE5591F620D3E273CF1362A31F041F5CB2ADFE6B6FC0B86
    rc3  기준     352A600040B34C1E54999387B36FA8CD5CE52714818152C69FAA3135D6E7BD8A

검증:

| | 오프닝 트랙 17 | 트랙 20 |
|---|---|---|
| Mednafen 1.32.1 | 정상 | **1회** |
| RetroArch / Beetle PCE SuperGrafx | 정상 | **1회** |

Beetle 이 실제 신고 환경이고 거기서 통과했다.

**아직 안 한 것:** rc9 는 메센에서 `lua/CDDA/0.1.0-rearm-gate.lua` 로
재보지 않았다. rc3 가 `arms=2 teardowns=2` 였으니 같은 지점에서 `arms=1
teardowns=1` 이 나와야 한다. 확인해두면 좋다.

## 오늘 바로잡은 기존 기록 둘

1. **`$2638` 은 시작 펄스가 아니라 트랙 내내 서 있는 레벨이다.**
   `docs/handoff/SNATCHER_NATIVE_SUBTITLE_BASELINE_2026-08-30.md` 의
   "`$263C` 와 `$2638` 은 각각 한 프레임 `01` 이 되는 시작 pulse" 는
   `$2638` 에 대해 틀렸다. 실측: `$263C` 는 f684~f687, `$2638` 은
   f688~f2465. `$263C` 만 에지다.

2. **rc3 의 `rearm_guard` 는 무장을 막지 못한다.**
   `cdda_rom_resident.json` 에 `last_raw=$5E1C / end_tick=$5E1D /
   cooldown=$5E1F / frames=120` 으로 선언되어 있으나 검사 코드는
   `$FE97 / $FEA1 / $FEAA` — **cache_save 경로 안**이다. 무장 지점
   `$F9DC` 를 가로막는 자리가 아니다. `SNATCHER_ENV_B_TO_ENV_A_2026-09-07.md`
   의 "120프레임 재진입 방지 판정이 들어 있다" 와 어긋난다.

## 실패한 후보 넷 — 전부 무장 쪽을 막으려 했다

| | 무엇을 했나 | 결과 |
|---|---|---|
| rc4·rc5·rc6 | 관문은 그대로 두고 `$F8DB` 에 `$26F9&$7F` vs `$5E1C` 트랙 걸쇠 추가 | 정당한 무장까지 차단 |
| rc7 | 관문을 `$263C` 에지 전용으로 (`ORA $2638` 3바이트 제거) | 메센 통과(`arms=1`). **Mednafen·Beetle 에서 CD-DA 자막 전멸** |
| rc8 | 관문을 `$20A2` vs `$5E1B` 비교로 교체 (30B, `$FBC3`) | 메센 미측정. **Mednafen·Beetle 에서 CD-DA 자막 전멸** |

**미해결로 남긴 것:** rc7·rc8 이 왜 Mednafen/Beetle 에서 자막을 전멸시키는지
모른다. Mednafen 에서 무장 순간(`$F9DC` store 직전) 메모리를 읽으면
`$263C=01 $2638=00 $20A2=02 $5E1B=17 $26F9=11` 로, `$263C=01` 은 rc7 관문이
통과해야 하는 값이다. 관문 자리로 떨어지는 상대 분기도 0건이라 분기 목적지가
깨진 것도 아니다. rc9 가 관문을 안 지나가므로 지금은 덮어둔다.

다시 잡게 되면 첫 수는 이것이다 — **rc7 을 Mednafen 에 올리고 `$5E1A` 에
쓰기 브레이크포인트를 걸어, 무장(`값 02`)이 아예 안 일어나는지부터 본다.**
안 일어나면 관문이 막은 것이고, 일어나는데 자막이 없으면 관문이 아니다.

## 부수적으로 확인된 것

- **`$20A2` 를 무장 순간에 읽지 말 것.** Mednafen 에서 트랙 17 무장 시점에
  `02` 로 읽혔지만, 출하 중인 rc3 코드 자체가 재생 중 `$20A2 == $5E1B` 에
  의존하고($EEE3) 그게 Beetle 에서 동작하므로, 조금 뒤 트랙 값으로 채워진다.
- **`$26F9` 는 hex, `$5E1B` 은 BCD.** 트랙 17 → `$26F9=$11`, `$5E1B=$17`.
  트랙 20 → `$26F9=$14`, `$5E1B=$20`. 둘을 직접 비교하면 안 된다.
- **무장 진입로가 둘이다.** `$F3A0`(state==1, 관문 우회)와 `$F40D`(관문
  경유). 프로브 9,559프레임에서 `STATE=1` 이 한 번도 안 찍혔다. rc3 에서
  `$FBBD` 의 `LDA #$01 / STA $5E1A` 가 `JMP $FE8F` 로 대체됐기 때문이다.
- **RetroArch / Beetle 은 BIOS 를 system 폴더에서 `syscard3.pce` 이름으로만
  읽는다.** 빌드마다 시스템 디렉토리를 그 폴더로 바꿔 쓰는 방식이 편하다.
  rc9 폴더에는 `Syscard3.pce` 를 같이 넣어두었다.
