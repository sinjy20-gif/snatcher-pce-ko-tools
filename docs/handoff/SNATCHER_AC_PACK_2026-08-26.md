## 1. ★ 문서가 낡아서 헛다리 짚은 것들

오늘 이것 때문에 세 번 돌아갔다.  **먼저 고쳐 둔다.**

### 1-1. `$5FAD` 의 `CMP #$nn` 은 타이밍 예산이 아니다

해시 테이블 **최대 탐색 횟수**다.  `runtime_layout.json` 과 정확히 일치한다:

```
             maximum_successful_probes    디스크 $5FAD
0.4.5.6              11                     0x0B = 11
0.4.5.7              (46)                   0x2E = 46
0.4.5.9              45                     0x2D = 45
```

**낮추면 그 거리 너머 레코드를 영영 못 찾는다.**  0.4.5.6 값(11)으로 되돌린
시험 디스크를 구웠다가 더 망가뜨렸다.  건드리지 말 것.

### 1-2. "이른 기회가 없다" 는 `$66E5` 에 한해서만 참이다

`_archive/build_records/DELETED_BUILDS_2026-08-13.md` 의 이 항목:

```
기존 훅으로 로딩을 앞당기려 하지 말 것
  $66E5 는 대사창이 살아있을 때만 발동한다.  챕터1 오프닝은 그래픽이라 훅이 없다.
  초기화는 프레임 3330(약 55초, 접수처)에 일어난다.  그보다 이른 기회가 없다.
```

**CD-RAM 오버레이 훅 이야기다.**  BIOS 케이브(`$FEC4`)는 `$E000-$FFFF` 가
`MPR7=$00` 으로 항상 고정이라 부팅부터 살아 있다.  자막 엔진이 실제로 그 자리를
쓰고 오프닝 전에 AC 세팅을 끝낸다 -- 그러므로 **더 이른 자리는 있다.**

### 1-3. "BIOS 케이브 부팅 FAIL" 은 해결됐다

`SNATCHER_SUBTITLE_STATE_2026-08-23.md §4.3` 이 `0.2.5/0.2.6 부팅 FAIL` 로 적어 둔
것은 **낡았다.**  소유자 확인: 케이브에서 부팅 안 죽는다.  자막 엔진도 올라간다.

### 1-4. 비용 모델 (이건 맞는 기록이다)

```
틀림: 시간 = 호출수 x 188ms + 바이트/150KB/s
맞음: 시간 = 바이트 / 34 KB/s        (호출 수는 거의 무관)
```

**총 바이트가 같으면 나눠도 총 시간이 같다.**  나누기는 시간을 줄이는 수단이
아니다.

마스터의 `pack` 열이 곧 장소다 (소유자 확인).  화자 분포가 그대로 증명한다:

## 4. ★ `{X:xx}` -- 열쇠 왕복 (이건 무조건 유지)

빌딩 앞 간판이 한글로 안 뜨던 원인.

```
실기 바이트   ... 81 40 81 40  FB  06 03  82 69 ...   39 B
빌드 (전)     ... 81 40 81 40  7B 58 3A 46 42 7D  06 03 ...   44 B
                              ^^^^^^^^^^^^^^^^ "{X:FB}" 를 글자로 인코딩
```

`FB` 는 cp932 에 없는 바이트라 옛 `decode` 가 **원문을 통째로 버렸다**
(`return ""`).  버리지 않으려고 `{X:FB}` 표기로 남겼는데, 인코더가 그 토큰을
몰라서 ASCII 여섯 글자로 나갔다.  열쇠가 어긋나 런타임 조회가 미스.

미스가 나면 해시 탐색 45 칸을 다 훑으므로 **그 자리 로딩이 길어진다.**
고친 뒤 빌딩 앞 로딩이 눈에 띄게 줄었다 (소유자 확인).

고친 곳 셋:

```
extraction/translation/layout_markup.py        X_TOKEN_RE · x_parameter · 토큰 자르기
extraction/translation/game_text_codec.py      ko_text 인코딩 -> 원시 바이트 (칸 0)
extraction/translation/source_text_markup.py   ★ jp_text -> 열쇠 바이트.  여기가 진짜
                                                TOKEN_RE 에 X: 를 넣어야 잘린다
tools/rebuild_runtime_context.py               decode 가 실패를 안 삼킨다
```

⚠ `FB` 가 무엇인지는 **아직 모른다.**  피연산자가 둘이고 값이 이산적이다:

```
FB 03 00  201회 · FB 08 01  173회 · FB 06 01  136회 · FB 05 00  22회 · FB 06 03  4회
첫 피연산자 3·5·6·8   둘째 0·1·3
```

자리 이동(행·열) 같지만 확정은 아니다.  **몰라도 된다** -- 되돌리기만 하면 된다.

### 7-2. 숫자 프레임 필터 (오늘 넣음)

전화번호 입력 화면은 숫자 한 자 누를 때마다 창을 다시 그린다.  그 프레임이
줄마다 잡혀서 한 레코드가 22 줄까지 불어났다.  번역할 글자가 없다.

`tools/merge_missing_text.py` 에 `has_letters()` 를 넣었다 — **줄 단위**로,
토큰·제어바이트·숫자·공백을 뺀 뒤 글자가 0 이면 버린다.

```
전   고유 191 → 추가 191 레코드 · 652 행
후   고유 164 → 추가 163 레코드 · 380 행     버린 줄 251
```

⚠ 레코드 단위로 보면 안 된다.  머리줄(「<원문 5자>」「<원문 8자>？」)에
글자가 있어서 통째로 통과해 버린다.
⚠ 진짜 번호 대사(`<원문 14자>` `０９９０－９３２５１０`)는
글자가 섞여 있어 살아남는다 — 확인함.

### 7-6. 꼬리줄이 남의 번역을 주워 쓴다

「『ガウディ』によるＣＧ合成２Ｄ写真です。」가 렌더러에서 `…写真で` + `す。`
두 줄로 끊긴다.  마스터에 이 레코드가 없어서 꼬리 `す。` 가 다른 레코드의
번역(미카 「일본이 아니기도 하죠....」)을 주워 썼다.

레코드를 붙이면 저절로 낫는다.  `jp='す。'` 인 마스터 행은 96 개고 그 중 54 개가
**각각 다른 번역**을 갖고 있다 — 꼬리줄도 제 번역을 갖는 게 정상이다.
(`{EMPTY}` 로 비우는 게 규칙이 아니다.  한때 그렇게 적었던 것은 취소)

### 7-7. 유사도 자동제안은 안 된다 (해봤음)

### 7-8. 엔딩 크레딧 후 타이틀 복귀 — 다음에 볼 것

소유자 보고: 크레딧 뒤 타이틀로 안 돌아간다.  아직 원본과 비교 안 했다.

우리 빌드엔 타이틀 복귀 경로에 훅이 있다 (`patch_title_cache_wipe.py`,
§8-B 세이브→타이틀→재로드 파손을 잡으려고 넣은 것).  두 갈래:

```
A  크레딧 뒤 복귀가 판정식에 안 걸린다 → wipe 가 안 돌아서 멈춘다
B  걸리는데 시점이 나빠 크레딧 상태를 지운다
```

가르는 법 — **원본 재주행 없이** 된다:

```
1  크레딧 직전에 BRAM 세이브 + 세이브스테이트 둘 다
2  우리 빌드: 스테이트로 크레딧 반복 재현 + wipe 훅에 로그
3  원본 디스크: BRAM 만 옮겨서 얹고 방치 (그 뒤는 전부 음성이라 알아서 간다)
```

⚠ 세이브스테이트는 디스크 이미지가 다르면 **못 얹는다** (메모리 스냅샷).
원본 비교는 반드시 BRAM(게임 내 세이브)으로.
⚠ 그 구간이 음성밭이니 방치할 때 **수집기를 켜 두면** 챕터 3 음성이 통째로 긁힌다.
