# 프리로더 이전 설계 — 작은 트램펄린 + 뱅크드 프리로더

기준일: 2026-08-20
직전 문서: `SNATCHER_SHOP_CRASH_2026-08-19.md` (원인 규명 완료)
상태: **설계 확정 · 구현 미착수**
방침: "480 B 짜리 영구 공터를 정적으로 증명한다" 를 **폐기**하고,
      "20~40 B 짜리 확실한 트램펄린 자리 + 큰 코드는 뱅크드" 로 바꾼다 (소유자 지시)

---

## 0. 한 줄 요약

**트램펄린 자리를 찾을 필요가 없다.  이미 있다.**
뱅크 6A 패딩 `$7F9F-$7FEB` **77 B 가 `EA`(NOP) 로 비어 있다.**
같은 패딩 블록이 폰트 래퍼와 헬퍼 트램펄린을 몇 달째 무사히 이고 있다.

---

## 1. 실측 — 0.4.5.2 이미지에서 직접 뜬 뱅크 6A 패딩

`build/patch/0.4.5.2` 트랙02 의 ISO `0x081750-0x0817FF` 를 역어셈블한 결과다.
추정이 아니라 출하 이미지의 바이트다.

```
$7F50-$7F85   54 B   폰트 래퍼        LDA $F9 / CMP #$F0 ... JMP $69C2
$7F86-$7F87    2 B   $FF $FF
$7F88-$7F9E   23 B   헬퍼 트램펄린    ★ 우리가 이미 쓰는 패턴
$7F9F-$7FEB   77 B   EA EA EA ...     ★★ 전부 NOP.  비어 있다
$7FEC-$7FFF   20 B   전용 상태        00 x20
```

`$7F88` 트램펄린의 실제 바이트 (이 구조를 그대로 복제하면 된다):

```
7F88  08        PHP
7F89  78        SEI
7F8A  43 20     TMA #$20        현재 MPR5 저장
7F8C  48        PHA
7F8D  a9 69     LDA #$69
7F8F  53 20     TAM #$20        $A000-$BFFF <- 뱅크 69
7F91  20 d2 bc  JSR $BCD2       헬퍼
7F94  8d ee 7f  STA $7FEE       결과 A 보관
7F97  68        PLA
7F98  53 20     TAM #$20        MPR5 원복
7F9A  28        PLP
7F9B  ad ee 7f  LDA $7FEE
7F9E  60        RTS
```

**23 B.**  필요한 트램펄린 두 개(프리로더용·꼬리간격 헬퍼용)를 넣고도 남는다.

### 왜 이 자리는 안전한가 — 구조적 근거

`$4000-$5FFF`(뱅크 68)와 성격이 다르다.

```
뱅크 68   부팅 때 한 번 적재되고 그 뒤로는 게임의 작업 RAM.
          $5BB3-$5FFF 의 $FF 는 힙이다.  $825A 가 거기에 쓴다
뱅크 6A   $6000 창에 페이징되는 **코드 오버레이**.  디스크에서 다시 실려온다.
          게임은 실행만 하고 스크래치로 쓰지 않는다
```

우리 훅 `$66E5` 자체가 뱅크 6A 에 있으므로 **훅이 도는 순간 이 뱅크는 반드시
매핑돼 있다.**  트램펄린이 사라질 수 없다는 것이 경로와 무관하게 성립한다.

## 2. 설계

```
$66E5   JSR $7F9F          (3 B.  지금과 같은 모양)
          |
          v
$7F9F   프리로더 트램펄린 (뱅크 6A · 상주 보장)
          PHP / SEI
          TMA #$20 / PHA              MPR5 저장
          LDA #<엔진뱅크> / TAM #$20   $A000 <- 엔진 뱅크
          카나리아 검사 ($A000 의 매직)
             불일치 -> 엔진 재적재 (§4) -> 재검사 -> 그래도 불일치면 포기
          JSR $A003                   프리로더 본체
          STA $7FEE / PLA / TAM #$20 / PLP / LDA $7FEE
          RTS
```

### 2.1 창은 MPR5 를 쓴다 — 이유가 있다

프리로더는 내부에서 `JSR $7F88` 로 헬퍼를 부른다.  `$7F88` 은 **뱅크 6A 에**
있으므로 프리로더가 어느 창에 있든 도달 가능하고, 끝날 때 `PLA / TAM #$20` 로
**저장해 둔 값(=우리 엔진 뱅크)을 그대로 되돌려 놓는다.**  즉 기존 트램펄린을
한 바이트도 안 고치고 중첩이 성립한다.

또 하나: 헬퍼는 지금도 `$A000`(MPR5) 에서 실행되는 채로 BIOS `CD_READ` 를
부르고 살아 돌아온다.  **MPR5 는 BIOS CD 읽기를 건너서 보존된다는 것이 이미
몇 달치 실측으로 증명돼 있다.**  다른 창을 고르면 그 증명을 새로 해야 한다.

### 2.2 옮기는 것 / 안 옮기는 것

```
옮긴다   프리로더 434 B      $5E40 -> 엔진뱅크 $A003
         꼬리간격 헬퍼 32 B  $5E20 -> 엔진뱅크
안 옮긴다 폰트 래퍼 $7F50     이미 뱅크 6A
         헬퍼 트램펄린 $7F88  이미 뱅크 6A
         전용 상태 $7FEC      이미 뱅크 6A
         레코드 캐시 $5B80-$5E1F   ★ §5 참조
```

이전 후 뱅크 68 의 `$5E20-$5FFF` **480 B 를 게임에 돌려준다.**

### 2.3 공간 회계

```
$7F9F  프리로더 트램펄린 + 카나리아 + 재적재 유도    약 40 B
$7FDx  꼬리간격 헬퍼 트램펄린                        약 23 B
                                                   ----------
                                          합계 약 63 B  <= 77 B  OK
```

여유가 모자라면 `$7F86-$7F87` 2 B 와 뱅크 69 케이브 잔여를 쓴다
(케이브: 헬퍼 631 B 가 `$BCD2-$BF48`, `$BFE0-$BFF0` 17 B.
**여유 `$BF49-$BFDF` 151 B + `$BFF1-$BFFF` 15 B**).

## 3. 엔진 뱅크 후보 — $78 (예비 $79 · $7A)

세 갈래의 독립된 근거가 같은 곳을 가리킨다.

### 3.1 게임이 한 번도 매핑하지 않는다 (런타임)

`dump/bank_usage_220001.tsv`, 7,200 프레임 세션.  뱅크 `$68-$87` 중
**매핑된 적이 전혀 없는 것은 `$78` · `$79` · `$7A` 셋뿐이다.**
나머지 29 개는 전부 어느 창엔가 걸린 적이 있다.

### 3.2 게임의 CD 적재 목적지가 아니다 (정적 · 이번에 새로 확인)

상주 코어(뱅크 68/69/6A) 전체에서 `JSR $E009`(CD_READ) 는 **딱 하나**,
`$54E2` 다.  그 앞의 디스크립터 표 네 개를 전부 해독했다.

```
표 포인터   $54FB -> $5505 / $5535 / $566D / $563D
엔트리      8 B.  b4 + $3F80($68) = 목적지 뱅크
```

전 엔트리의 목적지 뱅크 집계:

```
$6B x1   $6C x4   $6D x106   $7B x1   $7C x1   $7E x33   $82 x7   $85 x2   $86 x1
```

**`$78`/`$79`/`$7A` 는 한 번도 나오지 않는다.**  CD 적재는 MPR 을 거치지 않고
뱅크에 직접 쓰므로 §3.1 의 매핑 감시로는 안 잡히는 경로인데, 그 경로에서도
비어 있다는 뜻이다.

### 3.3 24 KB 연속 구멍

`$78-$7A` 가 연속 3 뱅크다.  단발이 아니라 덩어리로 비어 있다.

### 3.4 그래도 "증명" 이라고 부르지 않는다

오버레이 코드가 자기 로더를 들고 있을 가능성을 정적으로는 못 닫는다.
그래서 §4 의 자가복구를 **반드시** 같이 넣는다.

## 4. 카나리아 + 자가복구 — 다섯 번째가 와도 크래시가 아니다

이번 사고의 교훈은 "자리를 잘 고른다" 가 아니라 **"틀렸을 때 어떻게 죽느냐"**
였다.  그래서 자리 선정과 무관하게 실패 양상을 바꾼다.

```
지금      밟힘 -> $00 = BRK -> 폭주 -> BIOS CD 잠금 교착 -> 진행 불가
바꾼 뒤   밟힘 -> 매직 불일치 -> 그 프레임은 일본어 -> 게임은 계속 돈다
                             -> 다음 기회에 엔진 재적재 -> 저절로 복구
```

재적재 경로는 새로 만들 게 없다.  BIOS `CD_READ` 목적지 타입 `$04`(뱅크 지정)
가 이미 이 프로젝트에서 검증돼 있다 (`manifest.json`:
`"transfer_mode": "BIOS CD_READ destination type $04, bank $40"`).
엔진 이미지 1 섹터를 붙임 트랙에 싣고 목적지 뱅크만 `$78` 로 주면 된다.
BIOS 가 뱅크 매핑을 알아서 하므로 MPR 곡예가 필요 없다.

**따라서 `$78` 판단이 틀리더라도 최악은 "렌더마다 CD 한 번" 이지 정지가 아니다.**

## 5. 이번에 안 옮기는 것 — 레코드 캐시 $5B80-$5E1F

캐시는 옮길 수 없다.  게임 렌더러가 `$03/$04` 를 역참조해 텍스트를 읽으므로
**치환 텍스트는 렌더 중 항상 매핑된 창에 있어야 한다** (`$2000-$3FFF` 또는
`$4000-$5FFF`).  뱅크드로 못 만든다.

다만 위험도가 다르다.

```
프리로더가 덮이면   코드를 실행한다 -> BRK -> 정지          ★ 이번 크래시
캐시가 덮이면       데이터를 읽는다 -> 글자 깨짐 / 일본어    복구 가능
```

캐시에는 프리로더가 이미 매직(`SDR4`)을 검사하고 있으므로, 이번 변경으로
**진행불가 등급의 위험은 사라지고 화면 등급의 위험만 남는다.**
캐시를 WRAM 냉구역으로 옮기는 것은 별건으로 뒤에 다룬다
(후보: `$2311-$2637` 807 B · `$3468-$36FF` 664 B — 둘 다 컷신 한정 측정이라
그대로 믿으면 안 된다).

## 6. 구현 순서

```
1. 상수 추가        ENGINE_BANK=$78 · ENGINE_BASE=$A000
                    PRELOAD_TRAMP=$7F9F · ADVANCE_TRAMP=$7FDx
2. 프리로더 origin 을 $5E40 -> $A003 으로.  어셈블러가 라벨을 재배치한다
3. 꼬리간격 헬퍼를 엔진 뱅크로
4. 트램펄린 두 개를 뱅크 6A NOP 자리에 emit
5. 훅 두 개의 목적지 변경   $66E5 -> $7F9F,  $674A -> ADVANCE_TRAMP
6. 엔진 이미지 1 섹터를 붙임 트랙에 추가 + 재적재 루틴 (뱅크 69 케이브 여유에)
7. $4000-$5FFF 를 빌더 금지구역으로 등록 (감사 실패로 만든다)
8. 조이 디비전 「쇼핑하기」 재현 + 저장/로드/타이틀 회귀
```

`build_direct_overlay_patch_ui.py` 의 `RUNTIME_START` 하나가 프리로더 origin ·
훅 오퍼랜드 · 패치 대상 ISO 오프셋을 전부 몰고 다니므로 2·5 는 기계적이다.
새로 쓰는 코드는 **트램펄린 두 개와 재적재 루틴뿐**이다.
