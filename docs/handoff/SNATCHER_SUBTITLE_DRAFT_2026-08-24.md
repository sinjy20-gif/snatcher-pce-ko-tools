# 번역 초안이 들어갔다 — 그리고 ADPCM 열쇠가 막혔다 (2026-08-24)

`6_LIVE.md` 다음이다.  그 문서는 **지금 도는 것**과 **Lua 를 걷어내는 순서**를
다뤘고, 이 문서는 **자막에 넣을 글**과 그것을 넣다가 드러난 **열쇠의 한계**를
다룬다.

> 문서는 날짜순으로 볼 것.  앞 문서의 결론을 뒷 문서가 뒤집은 적이 여러 번 있다.

---

## 1. 무엇이 들어갔나

```
CD-DA   대사 클립 223 개 중 194 개  (조각 319)   비운 29 개는 §3
ADPCM   대사 이벤트 59 개 중 56 개  (조각 113)   나머지 3 개는 비명·무음
```

팩이 8,808 B 에서 **57,894 B** 로 늘었다 (AC 예약 256 KB 의 29 %).
글리프 116 자 -> 523 자.  613 조각이 다 차도 예약 안에 든다는 §2.5 의 어림이
실측으로 확인된 셈이다 -- 194 클립에 33 KB 를 썼으니 613 조각이면 ~110 KB 다.

```
초안        drafts/cdda_batch01..05.txt · drafts/voice_batch01.txt
넣는 도구   tools/draft_subtitles.py
검수 메모   drafts/DRAFT_NOTES_2026-08-24.md   ★ 추정으로 옮긴 곳이 여기 다 있다
```

### 넣는 도구를 왜 새로 만들었나

`tools/apply_translations.py` 의 검사를 여기 쓸 수 없다.  정적 텍스트는 **칸 수**
(18 칸)로 세지만 자막은 **픽셀 폭**(192 px)이다 -- Galmuri9 는 비례폭이라
`한`(11 px)과 `1`(5 px)이 같은 한 칸이 아니다.

그리고 자막은 시각을 갖는다.  한 클립을 몇 조각으로 나누느냐가 곧 화면이 몇 번
바뀌느냐다.  그래서 **조각 수는 초안이 정하고** 도구가 클립 길이를 그만큼 자른다.

실측 최대 폭은 184 px 였다.  192 px 한계에 여유가 있다 -- 19 자 어림보다 조금
더 들어간다.

## 2. ★ ADPCM 지문이 이벤트를 구분하지 못한다

**초안 56 개 중 31 개가 팩에서 조용히 빠졌다.**  조각으로 세면 119 중 70 이다.
빌더가 세어 보고했고 검증기가 왕복 대조에서 다시 잡았다.

`6_LIVE.md` §5 가 "번역이 늘면 충돌이 생길 수 있다" 고 적어 둔 그것이 실제로
일어났다.  다만 **정도가 예상과 다르다** -- 드물게 겹치는 것이 아니라 열쇠가
애초에 이벤트를 구분하지 못한다.

### 왜 그런가

열쇠는 `(읽기주소 + 길이) & FFFF` 와 재생률이다.  그 합이 안 변하는 것은 맞다.
그런데 **그 합이 버퍼의 끝 주소**라, 같은 크기 등급의 음성이 전부 같은 값을 낸다.

```
5800 률 0E   6 이벤트가 같은 열쇠
   0066+579A  <원문 9자>、<원문 9자>
   0069+5797  <원문 8자>、ミカ
   0069+5797  <원문 16자>
   0061+579F  なるほど <원문 9자>
   0058+57A8  そうか <원문 5자>
   0062+579E  <원문 17자>

FFFF 률 0E   8 이벤트가 같은 열쇠   <- 긴 음성이 전부 여기로 감긴다
```

56 이벤트가 **25 열쇠**로 뭉갠다.  값들이 전부 `$0800` 의 배수인 것을 보라 --
열쇠가 나르는 정보는 "이 음성이 몇 KB 짜리인가" 뿐이다.

같은 순위(대사끼리)면 빌더가 먼저 온 것을 남긴다.  그래서 뒤에 온 31 개가
**소리 없이** 사라졌다.  실기에서는 "자막이 안 뜬다" 로만 보인다.

### 되는 길이 하나 보인다 — `sector`

`voice_events.tsv` 에 이미 있는 열이다.  음성 데이터가 실린 디스크 LBA 다.

```
내 초안 56 이벤트     sector 56/56 서로 다르다
ADPCM 전체 644 행     sector 537 개 서로 다르다
(sector, 끝주소) 짝    543 개
```

끝 주소와 달리 **음성마다 다르다.**  다만 아직 확인 안 된 것이 있다:

```
1  재생 시작 순간에 런타임이 이 값을 볼 수 있는가
   ADPCM 은 CD 에서 먼저 읽어 두고 나중에 재생한다.  재생 시점에는
   currentSector 가 이미 지나가 있을 수 있다
2  같은 음성을 다시 틀 때도 같은 값인가
   끝 주소가 "합만 안 변한다" 였던 것처럼, 여기도 재 봐야 안다
```

**둘 다 Lua 로 재는 것이 먼저다.**  `PROBE_SUB_PACK` 에 ADPCM 시작 프레임의
`cdrom` 상태를 같이 찍는 판을 하나 올리면 한 번에 답이 나온다.
겹치는 6 이벤트(위 `5800` 표)가 한 장면에 다 나오므로 접수처~국장실 한 바퀴면
표본이 모인다.

> 재기 전에는 **아무것도 고치지 말 것.**  지금 확실한 것은 "끝 주소로는 안 된다"
> 까지고, "sector 로 된다" 는 아직 후보다.

### 그때까지 CD-DA 는 멀쩡하다

CD-DA 열쇠는 LBA 구간이라 겹침이 없다 (327 항목 · 겹침 0).
**컷신 자막은 지금 그대로 실기에서 볼 수 있다.**  막힌 것은 게임 중 음성뿐이다.

## 3. 원문이 whisper 전사뿐이라는 것

번역을 넣으면서 드러난 두 번째 것이다.  CD-DA 도 ADPCM 도 원문 대본이 없고
whisper 가 옮긴 것뿐인데, **그 전사가 고르지 않다.**

```
멀쩡하다        트랙 01 · 04 · 08 · 10 · 14 · 16 · ADPCM 대부분
알아볼 만하다   낱말 몇 개가 틀렸다 -- 문맥으로 복원했다.  DRAFT_NOTES §1 에 목록
무너졌다        트랙 11 · 12 의 절반.  한 어절만 남았다 ("あんたの" · "わしは")
```

그래서 29 클립을 **비워 뒀다.**  지어내는 것보다 비는 편이 낫다 -- 비어 있으면
다음 사람이 채울 자리라는 것을 알지만, 지어낸 것은 검수에서 걸러낼 방법이 없다.

```
전사가 무너져 비움   21 클립  (트랙 11·12 가 대부분)
비명이라 뺌           8 클립  (0.5~0.9 초.  연달아 뜨면 깜빡이기만 한다)
```

**트랙 11·12 는 다시 전사하는 편이 빠르다.**  지금 전사로는 채울 수가 없다.

길이가 전사와 안 맞는 클립도 따로 적어 뒀다 (`DRAFT_NOTES` §4).
`c16_011` 은 57.8 초 클립에 전사가 한 줄뿐이다.

## 4. 1 섹터 겹침을 고친 것

검증기가 CD-DA 구간 겹침 1 건을 잡았다.  같은 클립의 이웃 조각이 1 섹터
겹쳤다 -- 빌더가 `int(초 x 75)` 로 되돌리는데 초를 소수로 적으면 부동소수가
한 눈금 모자라게 떨어진다.

```
609 / 75 = 8.12        인데      8.12 x 75 = 608.9999999999999
```

`draft_subtitles.py` 가 조각 경계를 **섹터 눈금 위**에 잡고 마이크로초 하나를
얹어 적는다.  얹는 양은 섹터의 1/13000 이라 시각에는 영향이 없고, 되돌린 값이
정확히 맞는다.  겹침 0 이 됐다.

`math.ceil` 로는 안 된다 -- 딱 떨어지는 값은 올림이 안 되니까 그대로 남는다.
