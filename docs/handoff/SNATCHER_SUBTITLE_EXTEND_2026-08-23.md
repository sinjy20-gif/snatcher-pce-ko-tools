## 1. SATB 조립 전체 지도

Track02 섹터 251 (2048 B/섹터, `$6000` 베이스) 을 정적 디스어셈블해 전부 폈다.
`tools/disasm_huc6280.py --bank A` 로 재현된다.

```asm
6000  JSR $476E
6008  ST1 #$00 / ST2 #$10     MAWR = VDC 워드 $1000 = SATB
600C  JSR $4763               (reg 2 = VWR 로 보인다)
600F  $12/$13 = $3E40/$3E60 - $0020        카메라 원점
601E  LDA #$3F / STA $17      ★ $17 = 전역 슬롯 예산 63
6022  객체 루프 A   X=$00..$1F
        $2A40,X 살아있고 $3000,X bit1 꺼짐 -> JSR $63CB
        BMI 로 돌아오면 예산 소진 -> $6072
603D  JSR $6075               루프 A 뒤 디스패처 (JMP ($2000))
6040  LDA $17 / BMI $6072
6044  객체 루프 B   X=$20..$3F   같은 구조
606F  JSR $60A6               ★ 남은 칸 0 채우기      <- 우리가 가로챈 자리
6072  JMP $43BE               ★ 조립 전체의 끝        <- 여기서 패치를 거둔다

63CB  객체 하나의 원점을 zp 에 깐다
        $08/$09 = $2880,X / $28C0,X - $12/$13     Y 원점
        $0A/$0B = $27C0,X / $2800,X + $0020       X 원점 (SAT +32 바이어스)
        $0C = $2940,X   $0D = $2900,X             플립
        $0E = $2980,X   $0F = $0E & $0F           속성원본 / 팔레트

6459  LDA ($10) / STA $16     ★ $16 = 리스트 머리의 개수 바이트
645D  INC $10                 개수 바이트를 건너뛴다
6463  엔트리 파서 (아래 §2)
6500  zp $00-$07 을 VWR 로 푸시 (STA $0002 / STA $0003 교대, 8 바이트)
6512  DEC $17 / BMI $6527     전역 예산 소진
6520  DEC $16 / BEQ $6527     이 리스트 소진
6524  JMP $6463               다음 엔트리
6527  RTS

60A6  LDX $17                 ★ 0 채우기.  MAWR 현재 위치에 그대로 쓴다
60AA  ST1 #$00 / ST2 #$00 x4  = 4 워드 = 슬롯 하나
60BA  DEX / BPL $60AA         $17+1 칸
60BD  RTS
```

`$60A6` 이 BREAKTHROUGH §2 의 *"게임은 안 쓰는 슬롯도 0 으로 채우며 64 칸 전부를
매 프레임 다시 쓴다"* 의 정체다.  **`ST1`/`ST2` 가 MAWR 현재 위치에 쓴다**는 것이
설계 전체를 좌우한다 (§4.1).

## 2. 레코드 형식 — 5 바이트 고정

`$6463` 파서를 따라가면 정상 경로에서 Y 가 항상 5 로 끝나고, `$6516 TYA / ADC $10`
이 그만큼 포인터를 전진시킨다.

```
[0]  attr 상위 바이트 (크기·플립).  ★ bit7=1 이면 재연결 레코드 (아래)
[1]  Y 오프셋 (부호 8 비트)  ->  zp $08/$09 원점에 더해 SAT word0
[2]  X 오프셋 (부호 8 비트)  ->  zp $0A/$0B 원점에 더해 SAT word1
[3]  패턴 하위 바이트        ->  zp $04
[4]  bit7=우선순위 · bits6-4=패턴 상위 · bits3-0=팔레트   ($0E=0 일 때)
```

`$0E = 0` 이면 `$64F8 LDA ([10]),Y / AND #$8F` 경로를 타서 attr 이 `[4] & $8F` 가 된다.
가장 단순한 경로이므로 우리는 이것을 쓴다.

**재연결 레코드** (`[0]` bit7 = 1) — 3 바이트:

```asm
646C  LDA ($10),Y  ->  임시        [1] = 새 포인터 하위
6471  LDA ($10),Y  ->  $11         [2] = 새 포인터 상위
6477  STA $10
6479  BRA $6463                    파서를 다시 돈다
```

**`$16`·`$17` 을 안 깎는다.**  즉 리스트는 공짜로 아무 데나 이어붙일 수 있다.
BREAKTHROUGH §6 의 *"목록이 어디에 있고 뒤에 여유가 있나"* 는 문제가 아니다 —
우리가 소유한 RAM 으로 이어달리면 된다.  (이번 구현은 아직 안 썼다. 9 글자가
원점 하나의 ±127 안에 들어가서 필요가 없었다.)

패턴 번호: SAT word2 `W2` -> VRAM 워드 `= (W2 >> 1) * 64`.  역으로 워드 `$7900`
이면 `W2 = ($7900 >> 6) << 1 = $3C8`.

## 3. 뚫은 방법

### 3.1 후킹 지점은 `$606F` 다 — `$6072` 가 아니다

```
606F  JSR $60A6   ->  JSR $5C20        (스텁)
스텁: zp $08-$0F 원점만 세우고  JSR $6463  ->  JMP $60A6
```

`$60A6` 의 RTS 가 `$6072` 로 돌아가므로 원래 흐름 그대로다.

여기서 **MAWR 은 이미 다음 빈 슬롯에 정확히 서 있다** — 원본 게임의 0 채우기가
그 전제로 동작하니 보장된 사실이다.  우리가 N 칸 밀면 MAWR 이 4N 워드 전진하고,
같은 푸시가 `$17` 을 N 만큼 깎으므로 `$60A6` 이 정확히 N 칸 덜 채운다.  **저절로 맞는다.**

```
★ 스텁의 VDC 접근 0 회.  MAWR 도 레지스터 래치도 안 건드린다.
```

### 3.2 패치는 프레임 밖으로 안 내보낸다

```
601E  무장   지문 5 개 확인 후 패치를 심는다
606F  스텁   푸시
6072  회수   무조건 원본 20 A6 60 으로 되돌린다
```

`$601E`→`$6072` 는 CD 접근이 없는 직선 코드라 그 사이에 오버레이가 갈릴 수 없다.
`$6072` 는 예산 소진 조기 탈출(`$6034`/`$6066` BMI)로도 반드시 지나므로 스텁이
안 불린 경우까지 회수된다.  회수 시점에 `$606F` 가 우리 패치가 아니면 **손대지
않고 `회수실패` 로 센다** (남의 코드에 다시 쓰지 않는다).

**오버레이 지문 5 개** — 하나라도 어긋나면 아무것도 안 쓴다:

```
$601E = A9 3F 85 17     $6463 = C2        $6500 = 82 B5 00
$60A6 = A6 17           $6072 = 4C BE 43
```

### 3.3 스텁 (6280, 65 B, `$5C20-$5C60`)

```asm
5C20  PHP / SEI               IRQ 엔진이 게임 MAWR 을 못 뺏게
5C22  LDA $6500 / CMP #$82    스텁 자신도 오버레이를 확인한다
      BNE exit
5C29  LDA $17 / BMI exit      예산 없음
5C2D  LDA #$3F / SEC / SBC $17    A = 게임이 쓴 슬롯 수
      CMP #$37 / BCS exit     ★ 자리가 9 칸 안 남으면 안 민다
      $08/$09 = $00F4         Y 원점 = 180+64
      $0A/$0B = $0088         X 원점 = 104+32 (9 글자의 가운데)
      $0C..$0F = 0
      $10/$11 = $5C80         리스트
      $16 = 9
5C5A  JSR $6463               ★ 게임 손을 빌린다
5C5D  PLP / JMP $60A6
```

리스트는 `$5C80-$5CAC`, 5 B × 9.  X 오프셋 `-64..+64` (16 px 간격),
패턴 워드 `$7900`~`$7B00` ($40 간격).  엔진($5B80+0x98)과 안 겹친다.

## 4. 실패 세 번과 각각이 가르친 것

### 4.1 `$6072` 에서 MAWR 을 만졌다 — 화면이 검어졌다

0.1.1 은 `$6072` 에 붙어 MAWR 을 `$1000+used*4` 로 **되돌려 놓고** 나갔다.
그 시점의 MAWR 은 이미 0 채우기가 끝나 `$1100` 이었다.  MAWR 은 쓰기 전용이라
복구가 안 된다 (BREAKTHROUGH §1.3).

```
푸시는 완벽했다:  생존 666/666 · 지워짐 0
그런데 화면이 검고 UI 가 안 돌아왔다.  스프라이트뷰·타일뷰는 정상.
```

**VRAM 이 멀쩡한데 화면이 검으면 VDC 레지스터를 의심한다.**
`$6072` 에서 MAWR 을 건드리는 설계 자체가 틀렸고, `$606F` 로 옮겨 MAWR 을
아예 안 만지는 것이 답이었다.

### 4.2 지문 게이트는 "쓰기 전"만 막는다 — "이미 쓴 것"은 못 거둔다

0.1.2 는 지문 5 개를 확인하고 썼다.  그런데도 UI 가 깨졌다.

```
[프레임 555]  $606F = 62 20 1B E0 C9 00   -> 디스크 섹터 255 에 실재.  정상 거부
[프레임 1585] $606F = E6 20 20 5C 4C BE   -> ★ 디스크 어디에도 없다
                                             20 20 5C 가 우리 패치다
```

오버레이가 갈렸는데 우리 패치가 CD-RAM 에 남아 있었다.  남의 오버레이가 그
`JSR` 을 실행 -> 우리 스텁 -> `$6500` 지문 불일치 -> `JMP $60A6` -> **그 오버레이의
엉뚱한 코드로 점프.**  0.1.3 의 무장/회수 구조가 이것을 끝냈다.

> **관측값이 디스크에 있는지 확인하면 "남의 코드"와 "내 잔재"가 갈린다.**
> 프레임 555 와 1585 를 가른 것이 그 검색이다.

### 4.3 확인 없이 덮어썼다 — 게임이 즉사했다

0.1.0 은 `$6072` 가 우리 패치가 아니면 그냥 덮어썼다.  다른 오버레이가 올라온
프레임에도 3 바이트를 박았다.

```
설치 4 · 푸시 0     스텁은 한 번도 안 불렸는데 패치는 네 번 했다
```

메모리에 규칙으로 적혀 있던 것을 어긴 것이다.  **CD-RAM 은 장면마다 갈린다.
주소가 같다고 같은 코드가 아니다.**

## 6. 이전 문서(BREAKTHROUGH)의 정정

1. **§2 의 SAT_SURVIVE 수치는 중간 스냅샷이다.**  인용된 `쓰기 2,068 · 생존 1 ·
   지워짐 359` 는 프레임 359 시점의 줄이고, 덤프 최종 정리는
   `쓰기 6,776 · 생존 1 · 지워짐 893` 이다.  결론(생존율 0%)은 안 바뀐다.
   같은 잘못된 인용이 `PROBE_SAT_HIJACK_0_1_0.lua` 헤더에도 박혀 있다.

2. **§4 의 두 줄은 덤프로 확인이 안 된다.**  `$6527 15,600 회 적중` 은
   `probe_sat_after_push` 출력이 `dump/` 에 없고, `슬롯 0~13 (장면따라 최대 27)`
   의 **27** 도 남아 있는 덤프(0~13, 0~14)에 없다.

3. **§6 의 계획은 세 군데가 틀렸다.**  아래가 실제다.
   - *"`$16`/`$17` 을 하나 늘린다"* — `$16` 은 리스트 머리에서 읽어오므로 늘릴
     대상이 아니고, `$17` 은 전역 예산이다.  **우리 리스트를 따로 태우면 된다.**
   - *"목록이 어디에 있고 뒤에 여유가 있나"* — 재연결 레코드가 공짜라 무관하다.
   - *"`$16` 과 `$17` 의 역할 구분" 미상* — 위 §1 에 확정.

4. **§0/§3 의 히잭 결과는 스크린샷으로 확인됐다.**  `poc_patterns.bin` 앞 16 B 가
   `probe_subs_verify` 의 VRAM `$F200` 과 16/16 일치하고, 렌더한 모양이 화면의
   두 획과 같다.  다만 `PROBE_SAT_HIJACK` 은 `scriptEnded` 에만 TSV 를 쓰므로
   레포에 산출물이 없다.  0.1.x 는 300 프레임마다 흘려 쓴다.
