## 1. 오늘 확정된 것

### 1-1. 국장실 뒷화면 · 떨림 (닫힘)

원인은 상주부 `$7F4A` 의 `SEI` 창이었다.  한 바이트를 `NOP` 으로 바꾸자 둘 다 사라졌다.
빌드에 반영돼 있고 사용자가 확인했다.

왜 그것이 원인인지는 이번에 숫자로 닫혔다.

```
RCR 이 쓰이는 줄 = SEI 창이 닫히는 줄 + 1      표본 18, 예외 0
분할선은 화면줄 7 · 135 · 148
SEI 있을 때  창 120~174 줄 -> 135 를 줄143~199 에 쓴다  분할선을 넘긴다
SEI NOP 후   지연 6~7 줄   -> 줄38~39 에 쓴다           여유 128 줄 안
```

상세: `SNATCHER_DIRECTOR_FLICKER_BISECT_2026-08-29.md` §7-F · §7-G · §0-0

### 1-2. SEI 제거의 잔여 위험 (기각)

IRQ 가 helper 한복판에 실제로 떨어진다 (`PC $4775`, IRQ1 핸들러 안).
그런데 데이터는 멀쩡하다 -- 게임의 VDC 선택 래치 평상시 값이 `$02` 라 우연히 맞는다.

```
SAVE 18 회 · RESTORE 18 회 · 불일치 0/2432
복원 직전 더럽힘 1410~1440/2432   <- 비교 대상이 실제로 바뀐다는 증거
```

### 1-3. CD-DA 네이티브 + BIOS 자리 회수

`0.4.6.24` 가 BIOS 에서 elapsed 를 2,683 프레임과 비교하던 25 B 를 엔진으로 옮겼다.
엔진은 이미 종료를 알고 있었고(`X == 3`), 그 자리에서 X 가 3 이므로 **`STX $7FDF` 3 B**
로 끝났다.  엔진의 남는 패딩이 정확히 3 B 라 슬롯도 안 키웠다.

```
0.4.6.25-cdda17-state3   decision 51/76 B   실기 PASS (자막이 정상적으로 사라짐)
```

### 1-4. ADPCM 키의 네이티브 출처 (측정 완료) — ⚠ 이후 폐기됨

> 이 절의 결론(6 B 키를 콘솔에서 만든다)은 같은 날 밤 **불필요해졌다.**
> BASELINE §12 -- 시작 LBA 3 B 로 식별한다.  아래 `9/9 항상 $00` 도
> 팩 902 키 중 160 개(17.7%)에서 틀린다 (§12.5).

Lua 는 `emu.getState()` 로 키를 만든다 -- 네이티브에는 없다.  그러나 게임이 그 값을
**평범한 RAM 에 복사해 둔다** (0.5.28 로 셋업 루틴 전문을 디스어셈).

```
key[0] = $22A6   finish 하위 (실측 9/9 항상 $00)
key[1] = $22A7   finish 상위
key[2] = $22AA   rate
key[3..5] = ADPCM RAM 3 곳     <- 아직 미해결
```

그리고 이 세 주소는 **이미 쓰던 것**이다.  `0.4.31` 이 기존 네이티브 게이트를
열려고 위조하던 바로 그 값이다.

## 3. ✗ 폐기 — 이 절의 계획은 더 이상 유효하지 않다

> **2026-08-30 밤 갱신.  BASELINE §12 를 볼 것.**
>
> 아래 §3 은 `$180D` / `$22A7` 기반 ADPCM 게이트를 고치는 계획이었다.
> 그 접근 자체가 폐기됐다.  음성의 **시작 LBA 3 바이트**가 SCSI CDB
> (`$224D-$224F`)에 그냥 있고, 그것이 902 음성을 갈라낸다.
>
> ```
> 자막 대상 음성 커버리지    27 / 27   (0.5.34 실측)
> 파생 시작LBA 고유값        1053 / 1055 행 · 충돌 2
> 전부 AD_TRANS 직전 명령 (뒤로0)
> ```
>
> 그래서 아래의 것들이 전부 필요 없어졌다 -- ADPCM RAM 3표본 샘플링,
> 재무장 가드(`STZ $22A7`), 스크래치 RAM 3 B, 76 B decision 예산 압박.
>
> ★ 그리고 기존 게이트 첫 줄 `LDA $22A6 / BNE idle` 은 팩 902 키 중
>   **160 개(17.7%)를 원천 차단**한다 (key[0]=$FF).  §12.5.
>
> 다음 작업은 BASELINE §12.7 에 있다.

## 3. ★ 내일의 첫 작업 — 안 재고 넣어서 깨진 것

`0.4.6.26` 에 ADPCM 감지기를 넣었더니 크래시했다.  decision 75/76 B 로 정적
빌드·디스어셈은 통과했다.

```
FRAGMENT WIPE #77 ... #326  전부 "0칸 · 0칸"   게이트가 매 프레임 열린다
PATCHED base=$1600                            키 기반이 아니라 고정 기본값
```

원인은 **검증하지 않은 가정** 하나다.

```asm
LDA $180D / AND #$20 / BEQ idle      "재생 중이면 통과"
```

여기에 "음성이 끝나면 이 비트가 0 이 된다" 를 얹었는데 **한 번도 재지 않았다.**
기존 게이트는 `CMP #$68` 로 음성 하나만 받아 이 문제가 안 드러났다.

### 재야 할 것

음성 한 개 동안 프레임 단위로:

```
$180D bit $20    시작 · 유지 · 종료에서 어떻게 변하는가.  조각 사이에 0 이 되는가
$22A7            음성이 끝난 뒤에도 값이 남는가
$22A6 / $22AA    같은 구간에서의 움직임
$7FDF            state 가 실제로 몇 번 1 이 되는가
```

이 그래프가 나오기 전에는 넣지 않는다.

되돌리기: `0.4.6.22` + `0.4.93`.  `0.4.6.25`(CD-DA 단독)는 실기 PASS 라 유효하다.
