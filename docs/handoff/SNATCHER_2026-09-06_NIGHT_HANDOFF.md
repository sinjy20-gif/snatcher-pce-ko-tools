## 0. 한 문단 요약

트랙 3 국장실 "진행 불가" 를 하루 종일 쫓아 **원인 사슬을 끝까지 측정으로 닫았다.**
원인은 자막 시스템이 게임의 스크립트 VM 스택 671 B 를 빌린 채 안 놓는 것이고,
게임이 방을 되찾는 35.37 초에 우리 코드가 망가지면서 종료 경로가 끊겨 **영영 반납이
안 되는** 구조였다.  0.5.12 로 종료 경로를 고쳐 **진행 불가는 풀렸다**(실기 UI 복귀
확인).  그러나 국장실 스프라이트·초상화는 여전히 안 나온다 -- 그건 증상이 아니라
**병 자체**(30 초간의 점유)이고, 0.5.12 는 그걸 안 건드린다.

그래서 소유자 판단으로 **CD-DA 전용 설계**로 방향을 틀었다.  설계는 §47~§49 에
정적 측정만으로 밑그림이 다 나왔고, 막힌 데가 없다.

## 1. 오늘 측정으로 닫은 사슬 (전부 실기 로그)

```
35.37초  게임 pc=$8D8B 가 $5B81~$5BA1 (33 B) 를 자기 값으로 덮는다
         ★3 주행 모두 무장 +2,122 프레임 = 프레임 단위로 재현된다
         -> 렌더러 entry(+3~+8)의 `BMI -> RTS` 안전장치가 사라진다
         -> `ready=$FE` 로 렌더러를 못 멈춘다.  push(+277)가 매 프레임 01 로 되돌린다
64.88초  트랙 끝.  cdda_finished 가 `ready` 를 보는데 항상 01 -> STATE=3 을 못 쓴다
66.0초   디스패처($F3BA)가 안 불리기 시작 (CD 가 멈추면 BIOS 가 그 경로를 안 돈다.
         ★결함이 아니라 정상 동작으로 보인다) -> 기회의 창이 닫힌다
이후     STATE 02 고착 -> 반납 판정($FCD1)이 아예 안 돈다 -> 671 B 미반납
         -> 게임 VM 스택에 우리 렌더러가 남는다 -> 국장실 진행 불가
```

핵심 숫자: `$7F82` 가 서명이 깨진 채 `JSR $5B83` 을 **1,524 회** 불렀다.
0.5.11 에서 트랙 3 의 `RESTORE` 는 **0 회**였다 (ADPCM 은 8/8 정상).

## 2. 0.5.12 — A안.  무엇을 고쳤고 무엇을 못 고쳤나

### 고친 것 둘 (같이 넣어야 한다.  하나만 넣으면 한 칸 더 가서 같은 자리에 선다)

```
① cdda_finished 가 `ready`(슬롯 안) 대신 `part`/`count`($2100 대역) 를 본다
     $EF0B  BD 03 21  LDA $2103,X     S_PART
     $EF0E  DD 04 21  CMP $2104,X     S_COUNT
     $EF11  F0 02     BEQ $EF15       part == count -> 옛 경로 (회귀 최소화)
     $EF13  B0 0A     BCS $EF1F       ★part >  count -> STATE=3
② 반납 소유 표식  $5B83/$AD  ->  $5B80/$53
```

### 실기 결과

```
0.5.11   FINISHED 10 회 · ready=01 전부 · STATE3 0 회 · RESTORE 0 회
0.5.12   FINISHED  1 회 ·               ★STATE3 1 회 · RESTORE 8 회
         STATE 02 -> 03 -> 00 · UI 복귀 ★소유자 확인
```

### ⚠ 못 고친 것 · 새로 생긴 결함

```
국장실 스프라이트·초상화   그대로 안 나온다.  35.37~64.9 초의 30 초 점유가 원인
철거 안전 조건             FINISHED 진입 때 ready=01 = 우리 칸이 SAT 에 살아 있었다.
                           "직전 프레임에 ready 를 내렸다" 는 전제가 손상 뒤엔 거짓.
                           보장 없이 철거했다 (§35-4 가 경고한 지우기 노이즈 위험)
★복원 8 회                 게임 pc=$BE50 이 $5B80 에 $53 을 쓴다.  게이트가 오인해
                           묵은 스냅샷을 살아 있는 게임 데이터 위에 7 번 더 덮었다.
                           게이트는 값이 아니라 **1 회성 표식**이어야 한다
자막                       35.37 초 이후 여전히 쓰레기
```

> **0.5.12 는 출하물이 아니라 측정 결과다.**  §37 의 "다음 신규 빌드는 0.5.11 부터"
> 규칙에 따라 0.5.11(§39 시험판) 다음 번호를 썼다.

## 3. ★결정 — CD-DA 전용 설계로 간다

소유자:

> "3종류의 엔진이 각각 자기 자리에 나왔다 들어왔다를 반복하는 구조임.
>  자리가 없기 때문이지 -- 공존할 수 있는 자리가 없어서 매번 AC에서 엔진을
>  통째로 복사해서 램에 넣고 돌린 거야."
> "결국 ADPCM의 설계를 물려받아서 그런 거군.  CD-DA만의 설계를 다시 하는 게 낫겠네."
> "이건 설계부터 다시 뜯어고쳐야 할 문제 같은데."

### 3-1  근거가 된 실측 (§47~§49)

```
렌더러 618 B = 코드 326 B + 데이터 292 B      ★RAM 이 필요한 건 292 B 뿐이다
뱅크1 여유 970 B 중 $FD1F-$FFD9 699 B         코드 ~350 B 가 349 B 남기고 들어간다
  근거: 그 블록 앞쪽 165 B 에서 우리 반납 처방이 2026-09-01 부터 실제로 실행 중
        ("FF 라서 비었다" 가 아니다 -- 이웃에서 코드를 돌려 검증한 자리다)
게임이 실제로 쓰는 곳은 바닥 33 B ($5B81~$5BA1) 뿐   3 주행 일관
무장 자리는 원래 둘이다  start_cdda $F80E / start_adpcm $FA38
  ★둘 다 STATE=1 을 써서 매체 구분을 버린다 -> 그래서 디스패처가 슬롯을 킁킁댔다
```

### 3-2  최종 모양

```
무장   $F80E  cdda_state = 1                      STATE $7FDF 를 안 쓴다
판정   $F3BA  LDA cdda_state / BNE -> JSR $ECF9   슬롯을 안 읽는다
스케줄러  $ECF9  674 B  ROM                        지금 그대로
렌더러    $FD1F  ~350 B ROM  ★새로 옮긴다          복사 없음 · 손상 없음
데이터    $5CF3  295 B  RAM  게임 스택 꼭대기      ★371 B 를 게임에 돌려준다
상태      $5E1A         RAM  ADPCM 이미지($5B80-$5E19) 밖이라 안 지워진다

사라지는 것
   상주부의 CD-DA 복사        arm 마다 15,203 cyc (33.4 줄) · 그중 ★8.9 줄이 원자적 차단
   cpu_cache 스냅샷/복원
   $5B80 매직 · $5B83 서명 · $5E1E 매체 지문
   = §42~§46 이 다룬 문제 전부
```

### 3-3  네 제약의 상태

```
① 사이클      ★해소.  치르는 값 구간마다 +171 cyc(0.38 줄, 분산)
                       받는 값 arm 마다 -15,203 cyc(33.4 줄, 8.9 줄은 원자적)  = 60 배 남는다
② 초기화      ~20 B.  자리 있다
③ 디스패처    ★해소.  무장 자리가 원래 둘이니 신호를 안 버리면 된다
④ ADPCM 충돌  ★"무너짐" -> "복구 가능".  날아가는 건 캐시뿐이고 권위 상태는
                슬롯 밖($2100 + S_* · AC_SCHED $1F2710)에 있다 -> 다시 심으면 된다
                ⚠ 트랙 3 은 안 겹쳤다(측정).  나머지 미측정 -- 다만 게이트에서 내렸다(§50)
```
