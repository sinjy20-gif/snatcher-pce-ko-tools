## 1. GFX native — ★여기가 제일 유망하다

### 어디까지 왔나

목표는 **헌정(dedication) 화면 한 장**이다. 150 개가 아니라 통틀어 30 개 미만이고,
지금은 그중 한 장만 본다.

```
Lua 경로  lua/GFX/0.3.0-inject-dedication.lua   ★동작 확인됨 (09-05)
네이티브   r1 r2 r3 r4 전부 실패.  r4 는 09-09 실기에서 부팅부터 배경 전부 깨짐
```

### r1~r4 가 왜 다 실패했나 — 구현이 아니라 **식별 전략**이다

공용 타일 업로더 `$725C` 에 훅을 걸고 "지금 올라가는 게 그 화면인가" 를
**추측**한다. 타일 지문은 내용이라 재사용되고, CD-DA 트랙은 화면이 아니라
주변 상황이다.

⚠ **문서 정정 (09-09).** 어젯밤 인계서는 r3 오탐 장면을 "첸슈호 대화 종료
부근" 이라고 적었는데 **틀렸다.** 캡처 실물을 열어보니 `037` 에
「初めから」「<원문 8자>」가 그대로 보인다 — **타이틀 / 시작 선택 화면**이다.
첸슈호는 같은 시기 CD-DA 작업 이야기가 섞인 것이고 거기서 GFX 오염은 없었다.

이 정정이 r4 의 근거를 무너뜨린다. r4 는 "오탐이 게임 후반이니 CD-DA 트랙
문(`$263B == $17`)으로 막는다" 였는데, 실제 오탐 자리가 **부팅 직후**다.
그 시점 `$263B` 는 게임 드라이버가 아직 안 채운 **쓰레기값**이라 문이 열려 있다.
실기 결과와 정확히 맞는다.

### 디스크 바꿔치기 길은 닫혀 있다 (09-09 실측)

원본 그래픽을 디스크에서 직접 바꾸면 런타임 코드가 0 이라 오탐이 원리적으로
불가능하다. 그래서 제대로 찾아봤다 — 헌정 VRAM 덤프의 타일 `$16A` 부터
**연속 8 장(256 B)** 을 네 형태로 트랙 01·02·24 전수 검색:

```
raw · swap16 · planes · half01   ->  세 트랙 모두 0 곳
```

압축이거나 다른 인코딩이다. **런타임 주입이 유일한 길이고, 문제는 장면 식별 하나로
좁혀진다.**

### ★ 게이트 후보 — 찾았다

압축이면 게임은 그 화면을 그릴 때 **디스크의 특정 자리를 반드시 읽는다.**
`CD_READ ($E009)` 를 걸고 제로페이지를 통째로 떴다.

```
⚠ HuC6280 의 zero page 는 $2000-$20FF 다 ($0000 이 아니다).
  0.4.0 은 $00F8 을 읽어 I/O 의 FF 만 봤다.  0.4.1 에서 고쳤다.
```

7,200 프레임 주행(부팅 → 타이틀 → 헌정) 결과:

```
CD_READ 239 회 · 호출자 5 개
    $BEAA 225   상시 스트리밍 ($20F8=4 섹터 · $20FD:$20FE 가 4씩 증가 = 위치 필드)
    $54E4   7   ★드물다
    $BEED   5 · $2CC9 1 · $30CB 1

헌정 타일 업로드 직전의 읽기
    f4670  호출자 $54E4  ·  $20FD:$20FE = 03 5A  ·  섹터 100 장
    ★전체 239 읽기 중 이 위치를 읽은 건 이 한 번뿐
```

`$20FD:$20FE` 는 스트리밍에서 섹터 수만큼 정확히 증가하던 **위치 필드**다.
타일 지문처럼 '내용' 이 아니라 '디스크상의 자리' 라서 다른 화면이 우연히 같은
값을 쓸 이유가 없다. r3/r4 가 쓰던 신호와 성격이 근본적으로 다르다.

### 남은 문제와 다음 한 걸음

읽기(f4670)와 업로드(f6260)가 **1,590 프레임(26 초)** 떨어져 있다. 그 사이
공용 업로더가 수천 번 돈다. 그래서 무장만으로는 어느 업로드가 헌정인지 못 정한다.

**`lua/GFX/0.4.2-gate-window.lua` 를 한 번 돌리면 갈린다.**
같은 구간(부팅 → 타이틀 → 헌정)을 지나면 된다.

```
무장 후 첫 덩어리     -> 지문 아예 불필요.  "무장 -> 첫 덩어리" 로 끝
항상 n 번째           -> 덩어리 세서 n 번째에 주입
순번이 흔들림         -> 무장 + 지문 병용 (그래도 r3 보다 훨씬 좁다)
무장이 안 걸림        -> 위치값이 주행마다 다르다.  다시 봐야 한다
```

첫 번째가 나오면 타일 지문을 완전히 버릴 수 있고, r3 가 타이틀에서 깨진 것
같은 오탐이 **원리적으로** 불가능해진다.

곁가지: 0.4.0 주행에서 **타이틀에선 지문이 한 번도 안 잡혔다** (적중 16 회가
전부 헌정 한 프레임, 호출자 `$70EC`). r3 가 타이틀에서 깨진 게 지문 오탐이
아닐 수도 있다 — 게이트가 서면 그것도 같이 갈린다.

## 2. ADPCM 다음 대사가 안드로이드에서만 일본어 — ★접었다

정본: `docs/handoff/SNATCHER_ANDROID_ADPCM_GATE_2026-09-08.md`

```
ADPCM 음성 바로 다음 대사 하나만 치환이 안 되고 일본어로 뜬다
PC (메센 · RetroArch · CUE 든 CHD 든)  항상 나온다
안드로이드 (PCE Fast · SuperGrafx · GearFX)  처음부터 한 번도 안 나왔다
```

빌드는 변수가 아니다 — 반환 로직을 넣기 전 판에서도 안 됐다.

### 지운 가설 다섯

| 가설 | 왜 아닌가 |
|---|---|
| 자막 팩 불일치 | 트랙 02 가 네 판 전부 `6f12fe002bc2c798` 동일 |
| CHD 가상 프리갭이 LBA 를 민다 | PC 에서 CHD 로 정상 동작 |
| 반환 로직 회귀 | 넣기 전 판도 안드로이드에선 실패 |
| 스프라이트 한도 | PC GearFX 는 `no_sprite_limit = Disabled` 인데 정상 |
| `$180D`/`$180C` 종료 신호 | 둘 다 무력화해도 증상 그대로 (아래) |

### ★죽은 코드에 시간을 썼다 — 다음 사람은 피할 것

매니페스트의 `subtitle_trigger_consume: "STZ $22A7"` 을 믿고 `$FED7` 에 프로브를
걸었다. **진입 0.** 그 블록은 `direct_return_patch` 가 `$FEC9` 에 무조건 RTS 를
박아 도달 불가다 (`legacy_fec7_fallthrough: false` 가 그 뜻이었다).
뱅크1 `$FC38` 도 같은 식으로 헛짚어 또 진입 0.

**교훈: 문서·매니페스트의 주소가 살아 있다는 보장은 없다. 코드 주소에 걸기 전에
그 경로가 실제로 도는지부터 확인할 것.** 제일 싼 방법은 **하드웨어 레지스터에
걸고 PC 로 역추적**하는 것이다.

### 살아 있는 자리와 메센 기준선

`0.5.194` 로 `$1800-$180F` 읽기를 전수로 떴다 (3,632 프레임).

```
$180D 를 읽는 PC     $F6EB  4,017 / 4,383   ← 압도적 1 등
$180D 값             $00 3,092 · $60 1,275
비트5 하강           4 회, 전부 $60 -> $00
$180C 값             $01 91,837 · $05 21,742 · $08 943
```

`$F6E8` 은 시스템카드 **AD_STAT** 이다 (점프테이블 `$E045 -> $F6DB`).
**원본 일본판 BIOS 와 바이트가 완전히 같다 — 우리 코드가 아니다.**

### 시험한 것과 결과

`$180D` 는 ADPCM 주소 제어 레지스터로 실기에서 쓰기 전용이라 읽기 값이 구현마다
다를 수 있다. 그래서 AD_STAT 이 `$180C` 비트3 만 보도록 1 바이트만 바꿔 구웠다
(`$F6EE 05 -> 00`, `BNE +5 -> BNE +0`).

```
0.6.3-diag-adstat-180c   안드로이드 결과: 여전히 안 나온다
```

**AD_STAT 의 두 갈래를 다 건드렸는데 증상이 안 변한다** → 우리 엔진의 종료
판정이 AD_STAT 을 안 탈 가능성이 높다.

⚠ 구멍: `0.5.194` 는 `$F6E8` 이 **누군가에게** 4,017 회 불린다는 것만 보였다.
**그게 우리 엔진인지 게임 자신인지 확인한 적이 없다.**

### 다시 열 때 여기서부터

1. ★ `$E045` 에 걸고 **호출자 PC** 를 뜬다. 우리 엔진이 목록에 없으면
   이 경로 전체가 무관하다. BIOS 안 호출자는 `$F407` · `$F5C6` · `$F61F`.
2. 없으면 반대로 — 자막이 살아 있는 동안 **우리 엔진이 읽는 것**을 훑는다.
   (`$7FDF` 는 `$6000-$7FFF` 라 뱅크 종속이다. 그냥 읽으면 `$00` 만 나온다.)
3. 그래도 안 잡히면 **Mednafen 단독판 + 디버거**로 Beetle 계열을 PC 에서
   재현하는 쪽이 기기보다 빠르다.
