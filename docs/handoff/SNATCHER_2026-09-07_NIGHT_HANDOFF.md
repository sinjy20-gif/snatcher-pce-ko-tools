## 3. 확정된 사실 — 이건 유효하다

### 재무장의 기계적 원인

시계가 둘이고 서로 안 맞는다.

| | 무엇이 결정하나 | 트랙 20 실측 |
|---|---|---|
| 철거 | 자막 목록이 떨어지면 | 1,533 프레임 = 25.5초 |
| 무장 | 트랙이 재생 중이면 | 음악 1,782 프레임 = 29.7초 |

관문 `$F898` 은 `LDA $263C / ORA $2638 / BNE` — **"CD-DA 가 켜져 있나"** 를
묻는다. 사건이 아니라 상태다. 자막이 떨어져 철거된 뒤에도 트랙이 4.2초
남아 있으므로 다음 프레임에 그대로 재무장한다.

```
f684 무장 → f2217 철거 → f2218 재무장 → f2466 트랙 끝
```

트랙 20 만의 문제가 아니다. **자막이 음악보다 먼저 끝나는 트랙은 전부** 이렇다.
메센에서 안 보였던 것은 재무장 뒤 4.15초 만에 트랙이 끝나는데 두 번째 묶음의
첫 자막이 12.9초 뒤라서다. **에뮬 차이가 아니라 남은 트랙 시간이 얼마냐로
갈리는 경주다.**

## 5. 아직 모르는 것 — 다음에 여기부터

### rc7·rc8 이 왜 CD-DA 자막을 전멸시키는가

관문을 서로 다른 방식으로 바꾼 두 빌드가 **똑같이** Mednafen·Beetle 에서
자막을 전부 잃는다. 그런데 Mednafen 에서 무장 순간(`$F9DC` store 직전)
메모리를 읽으면:

```
$263C=01   $2638=00   $20A2=02   $5E1B=17   $26F9=11   $5E1A=FF   $5E19=00
```

`$263C=01` 은 rc7 관문이 **통과해야 하는** 값이다. 앞뒤가 안 맞는다.
관문 자리로 떨어지는 상대 분기도 0건이라 분기 목적지가 깨진 것도 아니다.

**다음 수:** rc7 을 Mednafen 에 올리고 `$5E1A` 에 쓰기 브레이크포인트를 걸어
**무장(값 02)이 아예 안 일어나는지**부터 본다. 안 일어나면 관문이 막은 것이고,
일어나는데 자막이 없으면 관문이 아니다. 이것 하나로 갈린다.

### 처방의 제약 — 오늘 배운 것

**철거를 늦추는 방향은 쓸 수 없다.** CD-DA 상태 `$5E1A`/`$5E1B` 가 ADPCM
엔진이 쓰는 `$5B80`–`$5E1E` 안에 있다. CD-DA 가 늦게까지 붙들면 ADPCM 이
슬롯을 못 받아 굶는다. 그것이 0.6.1 이 죽은 이유다.

"ADPCM 과 CD-DA 는 동시에 성립하지 않는다" 는 설계 전제가 성립했던 것은
**CD-DA 가 자막을 다 쓰면 곧바로 내려갔기 때문**이다. 그 조기 철거가 전제를
지탱하는 장치였다. 지우면 전제가 무너진다.

### 참고 — `$20A2` 를 무장 순간에 읽지 말 것

Mednafen 에서 트랙 17 무장 시점에 `02` 로 읽혔다. 그러나 rc3 코드 자체가
재생 중 `$20A2 == $5E1B` 에 의존하고($EEE3) 그것이 Beetle 에서 동작하므로,
조금 뒤 트랙 값으로 채워진다. 또한 `$26F9` 는 hex, `$5E1B` 은 BCD 다
(트랙 17 → `$26F9=$11`, `$5E1B=$17`). 둘을 직접 비교하면 안 된다.

## 6. 검증 설계에 대한 교훈 — 이게 오늘 제일 비싼 값

`arms=1` 을 합격으로 잡았다. 메센·Mednafen·RetroArch 세 환경에서 통과시켰다.
그런데 셋 다 **트랙 20 장면 자체만** 봤고 **그 뒤를 안 봤다.**

`arms=1` 이 증명한 것은 "재무장이 없다" 뿐이다. **"정상 철거된다" 는 증명하지
않았다.** 철거 경로를 건드려 놓고 철거의 정상성을 판정 기준에 안 넣었다.

★ 철거·해제·정리 경로를 건드릴 때는 **그 뒤 장면까지 진행해서 다음 무장이
   정상으로 일어나는지**를 판정에 넣는다. 고친 그 장면만 보면 안 된다.

★ 보장된 탈출구를 지우고 조건부 탈출구만 남기지 않는다. rc9 는 `$EEE1`(항상
   성립)을 지우고 `$EEE9`(`$20A2` 가 바뀌어야 성립)만 남겼다. 그것이 안 바뀌는
   상황에서 CD-DA 가 영구히 state 2 에 머문다.

### 671 B 복사가 넷이다

```
① AC $1FE400 → AC $1F1F00     11,141 cyc  1.556 ms  프레임의 9.3%   첫 1회만
① 서명 일치(검사만)                89 cyc  0.012 ms         0.07%   이후 전부
② RAM $5B80  → AC $1F0E00      4,099 cyc  0.573 ms          3.4%   매번  TIN 블록전송
③ ???        → RAM $5B80          미측정                            매번  ← 다음에 잴 것
④ AC $1F0E00 → RAM $5B80      11,094 cyc  1.550 ms          9.3%   매번  손루프
```

**rc3 의 재사용 패치는 ① 하나만 건너뛴다.** ②③④ 는 대사마다 그대로 일어난다.
무장 프레임 부하는 15,240 → 4,188 cyc (12.8% → 3.5%). 한 프레임의 9.3% 를
대사당 한 번 아끼는 크기라 체감으로 잡히지 않는다.

같은 671 B 인데 ② 는 6.1 cyc/byte(TIN 블록전송), ④ 는 16.5 cyc/byte(손루프)다.
HuC6280 에 "소스 고정 → 목적지 증가" 블록전송이 없어 루프가 불가피하다.
8배 언롤이면 11,094 → 약 7,200 이다.

### AC 배치

```
$1F0E00   cpu_cache (게임 데이터 대피)   671B
$1F1C00   subtitle_helper                448B → $1F1DBF
$1F1DC0   CD-DA cache_data               295B → $1F1EE6
$1F1F00   ★엔진 활성 슬롯               671B → $1F219E   (서명 $1F219A-$1F219E)
              부팅 때 subtitle_renderer 666B 가 여기 올라간다
$1F2800   adpcm_native_bundle          54016B → $1FFAFF   (마스터 $1FE400 이 이 안)
```

BIOS 전체에서 `$1F1F00` 에 쓰는 코드는 `$F6B4`(복사 루틴 자신) 하나뿐이다.
그래서 대사가 아무리 지나가도 슬롯은 안 깨지고 `REUSE` 가 계속 나온다
(실측: f9005 → f13026, 4,000 프레임 = 67초를 건너뛰고도 유지).

### `$FC7A` 의 `$5B83 == $AD` 는 죽은 가지다

18회 전부 거짓이었다. 엔진이 매번 사라지니 성립할 수 없다. 이득은 0인데,
게임 데이터의 그 자리가 우연히 `$AD` 면 대피를 건너뛰고 낡은 AC 내용을
덮어쓴다 — **대사당 256분의 1의 데이터 파괴.** 정식 빌드에서 뺄 후보다.
`$5B81/$5B82` 의 `55 42` 를 같이 보면 3바이트가 되어 1,600만분의 1이 된다.

### `$5B80` 슬롯 갈아끼우기 (0.7.0 초벌)

`$5B80` 을 거쳐가는 것이 최소 셋이다.

```
53 55 42 AD F9 5C   ADPCM 엔진 (Track 24 블롭과 일치)
53 55 42 AD 30 5D   또 다른 엔진
53 44 52 34 xx xx   "SDR4" — 대사 쪽. 대사 구간에 계속 나온다
```

대사 쪽이 더 비싸다. `53 44 52 34 05 04` 버스트가 콘솔에만 12회, 각
**19,456 cyc (2.72 ms, 프레임의 16.3%)** 다. f5503~f5510 구간은 8프레임 안에
세 번 연속이다.

**⚠ 0.7.0 에는 결함이 있다.** 감시창이 `$5B80`–`$5B85` 6바이트뿐이라 671 B
복사의 앞 6바이트만 지나간다. 그래서 나온 `80 cyc`, `106 cyc` 는 복사 전체가
아니라 앞 6바이트 구간이다. **③ 의 비용은 이 로그로 못 잰다.** 또한
`ENGINE_IN` 분류는 첫 바이트가 `53→00` 되는 단일 쓰기를 잡은 것이지 엔진
적재가 아니다.

**0.8.0 에서 고칠 것:** 감시창을 `$5B80`–`$5E1E` 671바이트 전 구간으로 넓힌다.
그러면 복사 한 번에 정확히 671회 쓰기가 잡히고 첫↔끝 간격이 복사 전체 시간이
된다. 버스트 합치는 간격(현재 2000 cyc)도 서로 다른 복사를 뭉치고 있으니
다시 잡는다.

### 소유자 판단 — 다음 표적은 ③

지금은 대사 한 줄마다 `엔진 적재 → 자막 출력 → 엔진 내림 → 정리` 를 반복한다.
연속 ADPCM 구간에서 엔진이 상주하면 ②③④ 를 구간당 한 번만 하면 되고, 두 번째
줄부터 무장 프레임 12.7%, 종료 프레임 9.3% 가 사라진다. ① 이 아끼는 9.3% 보다
한 줄당 2.4배 크다.

내려놓는 자리는 찾았다:

```
$FCAA  LDA $7FDF / BEQ $FCD1        ADPCM 상태 0 → 철거로
$FCD1  LDA $5B83 / CMP #$AD / BNE   엔진이 아직 있나
$FCD8  JSR $FCDF                    복원. 여기가 내려놓는 자리
```

막는 것은 `$5B80` 이 대사와 공유라는 점이다. **그리고 이것은 §5 의 CD-DA
제약과 같은 뿌리다** — 하나의 RAM 슬롯을 셋이 돌려 쓰고 있다.
