# 조이디비전 구매 크래시 — 원인 규명 인계서

기준일: 2026-08-19 (밤)
상태: **원인 확정.** 수정 미착수
증상: 조이디비전에서 "구매하기" 선택 시 **100% 정지.** 리셋도 안 되고 그대로 굳는다.
      게임 진행 불가 (해당 선택을 안 하면 진행이 막힌다)

---

## 0. 한 줄 요약

**게임이 `$5E40` 에 `$00` 을 쓴다.  거기 우리 프리로더가 있었다.**
`$00` 은 `BRK` 라서, 이후 `$66E5` 의 `JSR $5E40` 이 벡터 폭주를 일으키고
BIOS CD 잠금 교착으로 굳는다.

번역 데이터 문제가 전혀 아니었다.  MPR 도 IRQ 도 아니었다.
**남의 자리에 코드를 둔 것**이 전부다.  그리고 이것은 같은 실수의 **네 번째**다.

이 한 줄이 용의자를 최근 변경 수백 건에서 창립 멤버 넷으로 줄였다.

## 2. 결정적 증거 — Call Stack

`$20F5` (제로페이지 `$F5`) 에 Write 브레이크포인트를 걸고 구매를 눌러 잡았다.

```
Function      PC Address   해석
------------------------------------------------------------------
$0686         $FFFE        하드웨어 벡터 영역에서 실행 중.  이미 폭주
$66BD         $66E8        ★ 우리 BODY/UI 훅이 $66E5 다.  바로 그 자리
[irq] $E870   $422F        ★ 여기서 인터럽트가 걸렸다
$924C         $9266
$9269         $92C3
$477F         $8039
$4F64         $4F68
$477F         $45EA
$444E         $4455        게임 코드
```

안쪽 프레임의 **진입점이 `$0686`** 이다.  코드가 있을 수 없는 자리다.
즉 훅이 `$0686` 으로 뛰었고, 거기서부터 쓰레기를 실행하며 `$FFFE` 까지 흘렀다.

### 훅 바이트 — 원본 대조로 확정 (추론 아님)

`build_direct_overlay_patch_ui.py:86` 의 `RENDERER_ENTRY = 0x66E5`, 대상은
`common.bank6a_iso()` 즉 **뱅크 6A** (`BANK6A_ISO_BASE = 0x07F800`, `$6000` 창).
원본 `track02.iso` 와 패치본 트랙02 를 같은 ISO 오프셋에서 떠서 비교했다.

```
        원본                       패치본
$66E0   79 34 8d 78 34 ad 71 34    79 34 8d 78 34 20 40 5e   <<< 여기만 다름
$66E8   85 03 ad 72 34 85 04 b2    85 03 ad 72 34 85 04 b2
```

```
원본  $66E5   AD 71 34   LDA $3471
패치  $66E5   20 40 5E   JSR $5E40      <- 프리로더 호출.  3 바이트 정확히 교체
```

Call Stack 과 교차검증된다.

```
JSR 3 바이트 -> 복귀주소 $66E8      Call Stack 의 그 프레임 PC 가 $66E8   일치
$66BC 가 60 (RTS) -> 함수 시작 $66BD   Call Stack 의 Function $66BD        일치
```

**우리 훅이 스택에 실제로 올라가 있다는 것이 바이트로 확정됐다.**

> 정정: 이 문서 초판은 "훅이 점프 벡터를 읽는다" 고 적었으나 **틀렸다.**
> 간접 점프가 아니라 직접 `JSR $5E40` 이다.  벡터는 존재하지 않는다.

### 사건 순서

```
게임 $444E -> ... -> $924C 정상 진행
  -> IRQ 발생 ($E870)
  -> 그 인터럽트 안에서 렌더러가 돈다
  -> $66E5 의 우리 훅 JSR $5E40 이 실행된다
  -> 그런데 실행이 $0686 진입점으로 흘러간다 (Call Stack 안쪽 프레임)
  -> 폭주 -> $FFFE
  -> 그 와중에 $20F5 를 밟는다
  -> BIOS IRQ 핸들러가 $F5 잠금을 기다리며 영구 대기
```

### 처음 본 화면은 결말이지 원인이 아니었다

최초 캡처는 `PC=$E736`, `BBS0 $F5,$E733` 무한루프, `P=07`(I 플래그 셋),
Call Stack 은 `[bottom of stack]` 뿐이었다.

```
E736  BBS0 $F5,$E733     여기서 뱅뱅
E739  PHA / PHX / PHY
E73C  BSR $E742
E73E  PLY / PLX / PLA
E741  RTI                 <- BIOS 인터럽트 핸들러
```

`RTI` 로 끝나므로 BIOS IRQ 핸들러이고, 입구에서 `$F5` 비트0(CD 작업 잠금)이
풀리기를 기다린다.  폭주한 코드가 그 잠금을 밟아놓아 영영 안 풀린다.
**이건 결과다.  원인은 그 앞의 `$66E5` 다.**

## 3. 왜 이 화면만 죽나

**조이디비전 구매 경로에서만 게임이 `$5E40` 을 밟기 때문이다.**

포인터가 `$2025/$2026` 에서 동적으로 오므로, 그 값이 `$5E43` 이 되는 경로에서만
`-3` 이 우리 프리로더 첫 바이트를 정확히 때린다.  다른 화면에서는 그 포인터가
다른 곳을 가리키니 우리 코드가 무사하다.

```
일반 대화     $2025/$2026 이 다른 값       프리로더 무사      정상
조이디비전    $2025/$2026 = $5E43          $5E40 에 $00 기록  즉사
```

> **초판 정정.**  이 절은 원래 "렌더러가 IRQ 컨텍스트에서 불려 MPR 배치가
> 달라지기 때문" 이라고 적었다.  **§6.8 에서 기각됐다.**  MPR2 는 `$68` 로
> 기대값 그대로였고 MPR3 도 정상이었다.  IRQ 컨텍스트인 것은 사실이지만
> (Call Stack 의 `[irq] $E870`) 그것은 원인이 아니라 동반 상황이다.

**따라서 조이디비전만의 문제라고 단정할 수 없다.**  같은 포인터 계산이
`$5E40` 부근을 가리키는 화면이 더 있다면 지금까지 안 들켰을 뿐이다.
§5.5 의 1 번(포인터 값 범위 측정)이 그래서 먼저다.

## 5. 고치는 방향

### 5.1 당장의 수정

```
1. 프리로더를 $5E40 에서 치운다
2. $4000-$5FFF 전체를 빌더의 금지구역으로 등록한다
```

`$4000-$5FFF` 는 Card RAM 워크램이고 **게임이 동적 포인터(`$2025/$2026`)로
긁는다.**  여기에는 죽은 자리가 없다.  있어 보일 뿐이다.
`$5B80` · `$5E40` 이 여기서 터졌다.

### 5.2 어디로 옮기나 — 판단 기준을 바꾼다

네 번 다 같은 방법으로 골랐고 네 번 다 틀렸다.

```
경험적 안전   "한 판 돌렸는데 안 밟혔다"        <- 지금까지의 방법.  전패
구조적 안전   "원본 이미지에서 이 바이트는 프로그램의 일부가 아니고,
              이 뱅크는 게임이 스크래치로 쓰지 않는 코드 뱅크다"
```

경험적 방법은 **안 가본 경로**를 절대 못 덮는다.  조이디비전 구매를 안 해본
판에서 `$5E40` 은 영원히 깨끗해 보인다.  `PROBE_DEAD_RAM` 이 정확히 그 방법이었고
그래서 이 자리를 통과시켰다.

구조적 안전은 경로와 무관한 성질이라 이 함정이 없다.
**뱅크 69 케이브(`$BCD2`)가 그 예다 — 헬퍼 631 B 가 몇 달째 멀쩡하다.**

### 5.3 관측 단위도 바꾼다

```
주소 감시   $5E40 하나.  그 경로를 안 가면 영원히 깨끗해 보인다
뱅크 감시   "이 뱅크에 쓰기가 한 번이라도 있나"
            -> 한 번의 관측이 8 KB 전체를 커버한다
```

### 5.4 보험 — 카나리아

옮긴 뒤에도 만약을 대비해 진입점에 서명 바이트를 둔다.
목적은 예방이 아니라 **실패 양상을 바꾸는 것**이다.

```
지금      밟힘 -> BRK -> 폭주 -> BIOS 교착 -> 진행 불가.  원인 규명에 하룻밤
카나리아  밟힘 -> 검사 실패 -> 치환 포기, 일본어 출력 -> 게임은 계속 돈다
```

다섯 번째가 오더라도 **진행 불가 버그가 아니라 그 줄만 일본어**로 끝난다.

### 5.5 순서

```
1. $2025/$2026 이 게임 전체에서 갖는 값의 범위를 잰다   <- 먼저
2. $4000-$5FFF 를 금지구역으로 등록
3. 구조적으로 안전한 자리를 고른다 (코드 뱅크)
4. 뱅크 단위 쓰기 감시로 검증
5. 카나리아 추가
6. 옮기고 조이디비전 확인
```

**1 을 건너뛰고 옮기면 다섯 번째가 나온다.**

## 6. 재현 · 계측 절차

```
1. 아무 패치판 로드 (0.4.5.1)
2. Breakpoints: 주소 $20F5, 타입 Write
   (PCE 제로페이지는 $2000-$20FF.  zp $F5 = $20F5)
3. 조이디비전 매장까지 진행 -> 브레이크포인트 켜기 -> 구매
4. Call Stack 확인
```

`$E006`/`$E009` (CD_BASE/CD_READ) 에 Exec 브레이크를 걸어도 **한 번도 안 걸린다.**
CD 호출 없이 굳는다는 뜻이고, 이것이 "CD 읽기가 원인" 가설을 기각한 근거다.

## 6.5 확정 / 미확정 경계 — 여기부터 추측 금지

이 사건은 그럴듯한 가설이 다섯 번 빗나갔다.  그래서 무엇이 바이트로 확정된
것이고 무엇이 아직 아닌지 명시해 둔다.  **미확정 항목을 확정처럼 쓰지 말 것.**

### 확정 (측정으로 닫힘)

```
$66E5 원본 AD 71 34 (LDA $3471) -> 패치 20 40 5E (JSR $5E40)   원본/패치 바이트 대조
복귀주소 $66E8 이 Call Stack 에 있음                            교차검증
함수 시작이 $66BD ($66BC 가 60=RTS)                             교차검증
Call Stack 중간에 [irq] $E870 프레임이 있음                     스크린샷
안쪽 프레임 진입점 $0686, PC $FFFE                              스크린샷
CD_BASE/CD_READ 는 호출되지 않음                                Exec 브레이크 미적중
원본 통과 · 0.2.26 포함 전 패치판 실패                          실기 확인
```

### 미확정 (아직 아무도 안 봤다)

```
폭주 시점에 $5E40 에 실제로 무엇이 있었나
왜 실행이 $0686 진입점으로 흘렀나
MPR 값 -- 한 번도 관측한 적이 없다
```

**§3 의 "IRQ 라서 MPR 배치가 다르다" 는 아직 가설이다.**  가장 유력하지만
관측된 적이 없다.  다음 계측이 이것을 겨냥한다.

### 초판에서 정정한 것

초판은 "훅이 점프 벡터를 읽는데 쓰레기가 나온다" 고 적었다.  **틀렸다.**
간접 점프가 아니라 직접 `JSR $5E40` 이다.  벡터는 존재하지 않는다.
바이트를 안 읽고 쓴 문장이었다.

## 6.6 다음 계측 — 미확정 셋을 한 번에 닫는다

```
1. 브레이크포인트 추가:  주소 $5E40,  타입 Exec
   (기존 $20F5 Write 는 켜둔 채로 둔다)
2. 조이디비전 매장까지 진행 -> 브레이크포인트 켜기 -> 구매
3. 걸리면 캡처 두 개
     a. Disassembly 의 $5E40 주변    우리 프리로더 코드가 맞는지
     b. 하단 탭의 MPR 상태            Card RAM $68/$6A/$6B/$6C/$6D 가 어느 창인지
```

### 판정표

```
$5E40 에 우리 프리로더 코드가 보인다   진입은 정상.  프리로더 내부에서 터진다
$5E40 에 엉뚱한 바이트가 있다          MPR2 가 기대와 다르다.  뱅크 가정 붕괴 확정
$5E40 브레이크가 안 걸린다             JSR 이 도달조차 못 함.  더 앞을 봐야 한다
```

### 참고 — $5E40 이 사는 창

`$5E40` 은 `$4000-$5FFF` = **MPR2** 창이다.
`PROBE_DEAD_RAM_0.1.1` 주석이 "MPR2 는 $68 로 고정이며 항상 매핑된다" 고
적어두었다.  **그 전제가 IRQ 컨텍스트에서도 성립하는지는 확인된 바 없다.**
이번 계측의 핵심이 정확히 그 지점이다.

또 하나: 같은 뱅크가 상황에 따라 다른 창에 걸린다는 것이 이미 관측됐다.
뱅크 6A 는 CD 오디오 드라이버를 볼 때 `$C000` 창이었고
(`SNATCHER_CUTSCENE_SUBS_2026-08-19.md` §6.5), 렌더러 훅 문맥에서는
`$6000` 창이다 (`bank6a_iso` 가 `0x6000` 을 기준으로 변환한다).
**뱅크-창 대응은 문맥마다 다르다.  고정으로 가정하면 안 된다.**

## 6.7 종결 — $5E40 에 우리 코드가 없다 (실측, 2026-08-19 밤)

§6.6 의 계측을 실행했다.  `$5E40` Exec 브레이크가 **걸렸다.**

```
PC       $5E40            JSR 는 정상 도달했다
SP       $C4
스택     E7 66 ...        복귀주소 $66E7 -> $66E8.  JSR $66E5 확정
Call Stack   $5E40 <- $66BD (PC $66E5) <- [irq] $E870 <- $924C <- ... <- $444E
```

그런데 그 자리의 내용이:

```
5E1B  .db $00 $8A $84 $00 $04 $00 $00 $00     <- 위쪽은 통째로 데이터
5E3F  .db $00
5E40  BRK #$00        <- 여기가 JSR 목적지
5E42  BRK #$00
5E44  TXA
5E45  STY $00 [$2000]
5E47  TSB $00 [$2000]
5E49  BRK #$00
```

**프리로더 코드가 없다.  `$00 $00` 이 널려 있고 그것은 `BRK` 다.**

### 폭주 경로가 이것으로 설명된다

```
$66E5  JSR $5E40
   -> $5E40 에 $00 = BRK
   -> BRK 는 $FFF6 벡터로 튄다
   -> 최초 캡처의 PC $FFFE · 진입점 $0686 이 바로 이것
   -> 그 와중에 $20F5 를 밟는다
   -> BIOS IRQ 핸들러가 $F5 잠금 대기 -> 영구 정지
```

초판이 "점프 벡터가 쓰레기" 라고 쓴 것은 틀렸지만, 벡터가 개입한다는 방향은
맞았다.  **간접 점프 벡터가 아니라 `BRK` 벡터다.**

### 확정된 인과

```
조이디비전 구매 -> 렌더러가 IRQ 컨텍스트에서 돈다
                -> $66E5 의 JSR $5E40 실행
                -> 그 순간 $5E40 에 우리 프리로더가 없다
                -> BRK 폭주 -> BIOS CD 잠금 교착 -> 정지
```

### 아직 안 닫힌 것 하나

**왜 없는가**는 아직 모른다.  두 갈래다.

```
A. MPR2 가 이 문맥에서 $68 이 아니다        -> 다른 뱅크가 보이는 것
B. 프리로더가 애초에 적재되지 않았거나 덮였다
```

`$5E40` 은 `$4000-$5FFF` = MPR2 창이고, `$5B80-$5E3F` 가 레코드 캐시다.
`$5E40` 은 그 바로 위다.  캡처에 보이는 `$5E1B` 부근 데이터(`00 8A 84 00 04 ...`)가
레코드 캐시 꼬리처럼 보인다는 점이 **B 쪽 정황**이지만 확정은 아니다.

가르는 방법: 같은 브레이크에서 **MPR 값을 읽는다.**  하단 탭이
`WRAM($F8) / Card RAM($68) / ($6A) / ($6B) / ($6C) / ($6D) / PRG($00)` 이므로
MPR2 가 `$68` 인지만 보면 된다.

```
MPR2 = $68 인데도 코드가 없다   -> B.  적재/덮어쓰기 문제
MPR2 != $68                     -> A.  뱅크 가정 붕괴
```

### 수정의 제약 — 미리 알아둘 것

`$66E5` 에 쓸 수 있는 것은 **3 바이트뿐**이다 (원본 `LDA $3471` 자리).
그래서 "JSR 하기 전에 검사한다" 는 그 자리에 못 넣는다.  검사를 하려면
**항상 매핑돼 있는 곳에 트램폴린**이 필요하다.

A 로 판명되면 트램폴린에서 MPR 저장/설정/복원을 해야 하고,
B 로 판명되면 적재 순서를 고쳐야 한다.  **어느 쪽인지 모르는 채로 고치면 안 된다.**

## 6.8 MPR 판정 — A 기각, B 확정

§6.7 이 남긴 갈래를 닫았다.  MPR 값은 **이미 §6.7 의 캡처에 찍혀 있었다.**
Mesen 하단 바가 곧 MPR 배치다.

```
MPR0  REG ($FF)        $0000-$1FFF
MPR1  WRAM ($F8)       $2000-$3FFF
MPR2  Card RAM ($68)   $4000-$5FFF   <- $5E40 이 여기
MPR3  Card RAM ($6A)   $6000-$7FFF   <- $66E5 가 여기
MPR4  Card RAM ($6B)
MPR5  Card RAM ($6C)
MPR6  Card RAM ($6D)
MPR7  PRG ($00)        $E000-$FFFF   BIOS
```

```
MPR2 = $68     기대값 그대로.        -> A (뱅크 가정 붕괴) 기각
MPR3 = $6A     bank6a_iso 와 일치.   -> 훅이 있는 창도 정상
```

**즉 뱅크 배치는 정상이고, 그 정상적인 자리에 우리 프리로더가 없다.**
§6.7 의 B 로 확정: **적재되지 않았거나 덮였다.**

§3 이 세웠던 "IRQ 라서 MPR 배치가 다르다" 가설은 **여기서 기각된다.**
IRQ 컨텍스트인 것은 맞지만 (Call Stack 의 `[irq] $E870`), MPR 은 안 바뀐다.

### 덤으로 나온 것

`MPR5 = $6C` 다.  **뱅크 69 는 이 시점에 어느 창에도 매핑돼 있지 않다.**
헬퍼 케이브(`$BCD2`, 뱅크 69)가 이 문맥에서 도달 불가라는 뜻이다.
이번 크래시의 호출 경로에는 헬퍼가 없으므로 직접 원인은 아니지만,
수정 설계 때 "헬퍼에 트램폴린을 둔다" 는 선택지가 **여기서는 성립하지 않는다.**

### 다음에 답할 질문

```
$5E40 의 프리로더는 언제 적재되며, 무엇이 그것을 덮는가
   - 부팅 시 적재된 뒤 조이디비전 진입 과정에서 덮이는가
   - 애초에 이 경로에서는 적재된 적이 없는가
```

가르는 방법: `$5E40` 에 **Write 브레이크포인트**를 걸고 부팅부터 돌린다.
마지막 쓰기가 우리 적재인지, 게임의 다른 데이터인지 보면 된다.
`$5B80-$5E3F` 가 레코드 캐시이고 `$5E40` 이 그 바로 위라는 점에서,
**캐시 쓰기가 경계를 넘어 흘렀을 가능성**이 1 순위 후보다.

## 6.9 근본 원인 확정 — $5E40 은 게임이 쓰는 버퍼다 (2026-08-19 밤, 종결)

`$5E40` 에 **Write 브레이크포인트**를 걸어 잡았다.

```
PC     $825A
명령   STA ($7E)  [$5E40] = $DA        A = $00
```

앞 문맥:

```
8243  LDA $25 [$2025] = $43
8245  STA $7E                     포인터 저 = $43
8247  LDA $26 [$2026] = $5E
8249  STA $7F                     포인터 고 = $5E      -> $5E43
824B  LDA $7E
824D  SEC
824E  SBC $80 [$2080] = $03
8250  STA $7E                                          -> $5E40
8252  LDA $7F / SBC #$00 / STA $7F
8258  LDA #$00
825A  STA ($7E)                   $5E40 에 $00 을 쓴다
825C  LDA #$01
825E  JSR $898F
```

**게임 자신의 코드가 `$2025/$2026` 의 버퍼 포인터에서 3 을 빼고 거기에 0 을 쓴다.**
그 결과가 정확히 `$5E40` — 우리 프리로더 첫 바이트다.

호출 문맥 (MPR):

```
MPR0 $FF  MPR1 $F8  MPR2 $68  MPR3 $69
MPR4 $7C  MPR5 $7D  MPR6 $7E  MPR7 $00
```

`$825A` 는 MPR4 = Card RAM `$7C` 에 있는 **게임 코드**다.
Call Stack 은 `$81D4` 계열이 반복된다 (`$825A` <- `$8456` <- `$8488` ...).

### 최종 인과

```
조이디비전 구매 경로
  -> 게임 코드 $825A 가 $5E40 에 $00 을 쓴다  (동적 버퍼 포인터 - 3)
  -> 우리 프리로더 첫 바이트가 $00 으로 덮인다
  -> 이후 렌더러가 IRQ 컨텍스트에서 $66E5 의 JSR $5E40 을 실행
  -> $00 = BRK -> $FFF6 벡터 -> 폭주 (PC $FFFE, 진입점 $0686)
  -> $20F5 를 밟는다
  -> BIOS IRQ 핸들러가 $F5 잠금 대기 -> 영구 정지
```

**MPR 문제도, IRQ 문제도, 적재 실패도 아니었다.
`$5E40` 이 애초에 빈 자리가 아니었다.**

### 이것은 네 번째다

`SNATCHER_SAVELOAD_HANDOFF` 가 이미 `$5B80-$5E3F` 를
"게임이 돌려 쓰는 공용 버퍼" 로 못 박았고, 같은 문서가
`$5B80` · `$BFCF` · `$7FF1` 을 **빈 자리로 봤다가 세 번 틀렸다** 고 적었다.

`$5E40` 은 그 경계 바로 위 한 칸이다.  **네 번째로 같은 실수를 한 것이다.**

프로젝트 규칙("`$FF` 는 빈 공간이 아니다 — 런타임에 죽은 자리임을 증명하고
빌더가 배정하게 할 것")이 정확히 이 사고를 막으려던 규칙이었다.

### 수정 방향

```
1. 프리로더를 $5E40 에서 치운다     <- 근본.  진짜 죽은 자리로
2. 그 자리를 빌더 감사에 등록한다    게임이 쓰는 영역으로 표시
```

**주의: 조이디비전만의 문제가 아닐 가능성이 높다.**
포인터가 `$2025/$2026` 에서 동적으로 오므로, 다른 화면에서도 같은 계산이
`$5E40` 부근을 가리킬 수 있다.  지금까지 안 들켰을 뿐일 수 있다.
옮길 자리를 고를 때 **`$2025/$2026` 이 가리키는 범위 전체**를 먼저 재야 한다.

### 다음 계측

```
$2025/$2026 에 Write 브레이크포인트 -> 이 포인터가 게임 전체에서
어떤 값들을 갖는지 수집 -> 그 범위 전체를 금지 구역으로 확정
```

## 7. 남은 작업

원인 규명은 **끝났다.**  남은 것은 수정이다.  순서는 §5.5 에 있다.

```
1. $2025/$2026 이 게임 전체에서 갖는 값의 범위 측정        <- 반드시 먼저
2. $4000-$5FFF 를 빌더 금지구역으로 등록
3. 구조적으로 안전한 자리 선정 (코드 뱅크.  케이브 계열)
4. 뱅크 단위 쓰기 감시로 검증
5. 진입점 카나리아 추가
6. 옮기고 조이디비전 확인
7. 다른 화면도 전수 확인 (§3 의 경고)
```

### 하지 말 것

```
"한 판 돌려보고 안 밟혔으니 여기 두자"   <- 네 번 다 이 방법으로 틀렸다
$4000-$5FFF 안에서 자리 물색              <- 여기엔 죽은 자리가 없다
1 번을 건너뛰고 옮기기                    <- 다섯 번째가 나온다
```
