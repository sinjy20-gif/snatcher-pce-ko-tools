# 그림 흔들림 재진단 — 2026-09-08

기존 `SNATCHER_SHAKE_ROOT_2026-09-08.md`는 동적 UI 전개 비용을 정확히 찾았지만,
그 비용과 화면 흔들림의 인과관계는 확정하지 못했다.

## 첫 인과 시험 — noexpand

`build/patch/noexpand/`

```
$5F31  JSR $7F88  ->  LDA #$01 / NOP
```

인계서의 `$5F34`는 실제 호출 opcode가 아니라 호출 뒤 `CMP #$00`의 주소다.
실제 JSR은 `$5F31`이다.

이 패치는 한국어 동적 UI 헬퍼, 그 AC 레코드 전개, 뒤의 VDC 글자 출력을 함께
막는다. 일본어 원본 글자는 게임 자체 경로라 그대로 나온다.

소유자 실기 결과:

```
흔들림은 여전히 발현한다.
다만 0.6.2보다 눈에 띄게 덜하다.
```

판정: 동적 글자 경로는 흔들림에 일부 기여하지만 단독 원인은 아니다. 기존 문서의
“뿌리 원인 확정” 판정은 철회한다. 복합 원인 또는 더 아래의 공통 경로가 남아 있다.

### 정정 — noexpand는 AC 0회가 아니었다

소유자 Event Viewer 사진에서 Arcade 접근이 프레임당 1회 남았다.

```
scanline 38 · PC $F42C · Register (R) $1A00 · value $A0
```

이는 UI 헬퍼가 아니라 BIOS ADPCM 자막 디스패처의 `arm_idle`이다. 매 프레임
AC `$1F2700`을 읽어 새 음성 표식 `$A1`이 왔는지 확인한다. 따라서 noexpand가
증명한 것은 “한국어 동적 UI 경로를 끄면 덜 흔들린다”까지이며, AC 전체 무죄는
아직 증명하지 않았다.

`build/patch/zeroac/`은 state 0에서 `arm_idle` 대신 `arm_return_near`로 가게 하여
이 1회까지 없앤다. 이 판은 Event Viewer에서 AC 0회를 먼저 확인한 뒤 판정한다.

### zeroac 사용자 시험

소유자 체감 결과:

```
zeroac에서도 밀림/흔들림은 남는다.
다만 현재 0.6.2에서 보는 증상보다는 줄었다.
```

Event Viewer에서도 Arcade read/write가 0회임을 확인했다.

판정: AC 경로는 흔들림을 분명히 증폭하지만 단독 원인은 아니다. AC를 완전히
제거해도 남는 기본 흔들림이 있으며, 다음 조사에서는 VDC 갱신 시점·프레임 경계·
인터럽트 지연처럼 AC와 동적 글자 경로가 함께 악화시킬 수 있는 공통 타이밍 문제를
우선한다. 이 결과로 AC 단독 원인 가설은 기각한다.

## 다음 분리 시험 — nodraw

`build/patch/nodraw/`

```
$5F31  JSR $7F88       유지 — 헬퍼와 AC 전개 실행
$5F34  CMP #$00        -> LDA #$01 — 뒤의 동적 레코드 출력만 차단
```

세 판을 같은 상태에서 비교한다.

| 판 | AC 전개 | 동적 출력 |
|---|---:|---:|
| 0.6.2 | 켬 | 켬 |
| nodraw | 켬 | 끔 |
| noexpand | 끔 | 끔 |

- `nodraw ≈ noexpand`: 동적 출력/VDC 쪽 기여가 크다.
- `nodraw ≈ 0.6.2`: 헬퍼/AC 점유 쪽 기여가 크다.
- 중간: 둘 다 기여한다.

아직 일본판 원본 대조와 남은 흔들림의 원인 분리는 하지 않았다.
