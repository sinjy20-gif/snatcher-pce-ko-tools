## 2. 자판 그림 네이티브 (§ 별도 문서)

전체 경위는 `SNATCHER_GAUDI_KEYPAD_BG_GEOMETRY_2026-09-14.md`. 요점만:

- 한 칸의 타일 쌍은 `(33,34) (35,36) (37,38)` 이다. 9/13 코드의 34/36/38 은 한 행 밀려
  있었고, 그 때문에 "16칸 분리 필요" 같은 제약이 생겼다. 실제로는 **3칸**이다.
- **타일맵은 열 단위**다 — 열 하나 = 행 32~39 의 8 바이트. VRAM 증가값이 64 이기
  때문이다. 행 단위로 디스크를 뒤지면 **절대 안 나온다**. 반나절을 여기서 태웠다.
- 글꼴은 `GalmuriMono7` (OFL-1.1). 45 자가 `6~7 × 6~7px` 이라 **원본 가나와 같은
  상자**에 눌림 없이 들어간다. Galmuri9/11 은 눌러야 해서 `나`→`니` 가 됐다.
- `決定`→`결정`, 수식키 `ー`·`゜`·`゛` 는 그림만 지웠다. `◀`(지우기)는 손대지 않았다.

⚠ 비운 키에 **커서는 여전히 선다** — `결정` 에서 왼쪽으로 네 번. 없애려면 Track 2 의
키 표를 고쳐야 하고, 그건 BG 타일 칠하기와 다른 작업이다.

## 3. 검색이 일부만 되던 진짜 이유 — 입력이 다시 잘린다

`0.7.13` 에서 `미카`·`제이미`·`해리` 는 되고 `길리언`·`깁슨`·`코지마` 는 안 됐다.

검색 루틴은 **진입할 때마다** 입력을 타이핑한 글자 수로 다시 자른다:

```
$B9A6  LDY $36B2      <- 타이핑한 글자 수
$B9A9  LDA $3690,Y
$B9AC  BEQ $B9AF
$B9AE  INY
$B9AF  TYA
$B9B0  ASL A          <- x2 = 바이트 길이
$B9B1  TAY
$B9B2  LDA #$FF
$B9B4  STA $363E,Y    ★ 여기서 자른다
```

그리고 우리 훅 `$B9E0` 은 `$B9CE BSR $B9E0` 으로 **후보 하나당 한 번씩 불리는 비교
루틴**이다. 그래서 긴 원본 키를 넣어도 다음 진입에서 뒤가 날아간다.

```
ギリアン -> ギリア    ギブスン -> ギブ    ジエミー -> ジエミ    ハリー -> ハリ
```

★ **되던 이름들은 우연이었다.** 잘린 다음 글자가 장음 `ー`(`81 5B`)처럼 `$81` 로
시작하면 비교가 거기서 끝나 통과한다(제이미·해리). `ン`(`83 93`)처럼 `$83` 이면
비교가 이어져서 실패한다(길리언·깁슨). `미카`는 키가 입력과 같은 길이라 안 잘렸다.

**고침은 5 바이트**다 — 키를 쓴 뒤 글자 수도 같이 갱신한다:

```asm
STA $363E,X      ; $FF 종결자
TXA / LSR A      ; 바이트 수 -> 글자 수
STA $36B2        ; ★ 이 한 줄
```

`0.7.12` 의 깁슨 전용 동굴은 잘린 `ギブ` 도 같이 매칭해 **복원**하고 있었다
(`$BE64 CMP #$45` = 깁슨 · `$BE6B CMP #$4D` = `ギブ`). 표로 일반화하면서 그 조건이
빠진 것이 `0.7.13` 회귀의 원인이다.

### 동굴 예산

`$BE56` 에서 `$C000` 까지 **426 B 가 전부**다. 뱅크 `$7D`(CPU `$A000-$BFFF`)에 다른
빈 자리는 없다 — 48 B 이상 연속 0 구간 **0 개**로 실측했다.

```
코드 114 B + 표 295 B = 409 B / 426 B   여유 17 B
```

더 필요하면 표를 줄인다. 한글쪽 상위바이트가 **전부 `$83`** 이라 빼면 **53 B**,
가나쪽(`$81` 장음만 예외)까지 빼면 **126 B** 가 나온다. AC 로 빼는 것은 표가 300 B 를
넘을 때 값어치가 생긴다 — 자막 엔진이 이미 `$1A00` 포트로 AC 를 읽으므로 원리적으로는
가능하지만, 검색 오버레이는 실행 맥락이 달라 따로 증명해야 한다.

## 4. 퀴즈 답 3개 — 아직 없다

`천하`·`벤슨`·`퀸` 은 **인명 검색표에 없다.** 다른 표에 산다.

| 답 | 원본 | 위치 | 주변 |
|---|---|---|---|
| 천하 | `テンカ` | `$00BAC47` | 화제(話題) 목록 |
| 퀸 | `クイーン` | `$018ED62` | 장소/사물 목록 |
| 벤슨 | `ベンソン` | `$00F0427` | 인명표에 있지만 인명 검색으로는 **안 걸린다**(실기 확인) |

필요한 것 둘:

1. **퀴즈 비교 지점 찾기** — 인명 때처럼 프로브 한 번이면 잡히는데, 퀴즈 장면이
   게임 막바지라 거기까지 간 세이브가 필요하다.
2. **자리** — 3 개를 표에 넣으면 38 B 가 더 든다. 지금 여유 17 B 라 표 줄이기가
   먼저다(§3 끝).

## 5. 원본 인명 검색표

`$00F000D~$00F0497` 에 **92 개**, `$00EE097~$00EE2E3` 에 **40 개**. SJIS + `$FF`.

사람마다 **별칭이 여러 개**다 (`<원문 7자>`/`リサ`, `<원문 9자>`/`<원문 5자>`,
`<원문 11자>`/`ギブスン`).

⚠ **임의 접두어는 안 된다.** 표에 **등록된** 짧은 이름만 쓸 수 있다. `ハヤサカ`·`コジマ`
는 짧은 별칭이 없어 전체 키(`<원문 7자>`·`<원문 6자>`)를 써야 한다.
`커닝햄` 도 전체 `<원문 9자>`, `첸슈호` 는 `チン` 으로 된다.

추출 도구: `tools/extract_gaudi_search_aliases.py`
