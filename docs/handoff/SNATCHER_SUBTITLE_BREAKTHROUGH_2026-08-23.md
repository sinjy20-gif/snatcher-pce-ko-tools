# 자막 — 화면에 글자가 떴다 · 2026-08-23 새벽

2주 막혀 있던 부팅이 뚫렸고, 같은 밤에 **한글 글리프가 게임 화면에 표시됐다.**
이 문서는 그 경로 전체와, 거기까지 오면서 확정한 사실들을 남긴다.

직전 문서: `SNATCHER_SUBTITLE_STATE_2026-08-23.md` (현황 통합)

---

## 0. 결론

```
게임의 스프라이트 조립 지점 $6500 에서 제로페이지 $00-$07 을 우리 엔트리로
바꿔치기하면, 게임이 **자기 스프라이트로 알고** 밀어 넣는다.  지워지지 않는다.
```

개념 증명에서는 게임 스프라이트 하나(길리언 눈)를 빼앗아 그 자리에 우리 글리프를
띄웠다.  실제 구현은 빼앗는 것이 아니라 **한 칸 늘리는** 것이 된다 (§6).

## 1. 오늘 뚫은 벽 세 개

### 1.1 부팅 멈춤 — 게이트가 부팅 중에 통과했다

`0.2.5`/`0.2.6` 이 부팅에서 멈추고 `0.2.4` 는 멀쩡한 역설이 단서였다.
`0.2.4` 케이브를 디스어셈블하니:

```asm
FF66  LDA #$80 / STA $2202      IRQ 벡터 = $5B80 설치
FF6B  LDA #$5B / STA $2203
FF70  LDA $2203 / CMP #$5B      ★ 방금 자기가 쓴 값을 검사한다
FF75  BNE $FFC9                    항상 일치하므로 절대 안 뛴다
FFC2  TAI $1A00,$5B80,#$0480    설치한 것을 즉시 되돌린다
```

**0.2.4 는 설치하자마자 스스로 취소했다.**  그래서 부팅이 됐고, 같은 이유로 자막도
안 나왔다.  0.2.5 가 그 흘러듦을 고치니 설치가 남았는데, 부팅 시점에는 Lua 로더가
AC 를 아직 안 채웠으므로 `$5B80` 에 쓰레기가 들어가고 벡터가 그것을 가리켰다.

게이트 5 조건(`$22A6`·`$22A7`·`$22AA`·`$2202`·`$2203`)은 **Lua 실행 여부와 무관**하다.
게임이 자기 IRQ1 을 설치한 뒤 ADPCM 이 한 번이라도 울리면 전부 참이 된다.

> 로더 `LOAD_SUBTITEL_0_2_5.lua` 헤더가 이 실패를 이미 적어 두었다:
> *"안 붙은 상태로 음성이 시작되면 케이브가 쓰레기를 RAM 으로 복사해 실행한다."*
> 알고 있던 위험인데 케이브 쪽에 방어가 없었다.

**해결 (0.2.7)** — AC 매직값 검사.  로더가 페이로드를 다 얹고 **검증에 통과한
뒤에만** 매직 `'K' 'O'` 를 `$1C04F0` 에 쓴다.  따라서 `매직이 보인다 == 페이로드가
온전하다` 가 성립한다.  순서를 반대로 하면 반쯤 쓰인 페이로드를 온전한 것으로
오인할 수 있다.

### 1.2 RAM 대여는 무죄 — 일반 대사 중에도 안전하다

문서에 `$5B80-$5E3F` 는 레코드 캐시이고 *"컷신 중에는 게임도 안 건드린다"* 로
적혀 있었다.  **"컷신 중에는" 이 조건**이므로 일반 대사에서도 안전한지는 미지였다.

`0.2.9` 로 갈랐다 — 엔진에서 VDC 접근만 빼고 RAM 대여와 IRQ 가로채기는 유지.

```
0.2.7  $7B00 업로드   화면 오염
0.2.8  $7900 업로드   화면 오염 (동일)
0.2.9  VDC 접근 없음  ★ 화면 깨끗
```

**RAM 대여는 원인이 아니다.**  일반 대사 중에도 `$5B80` 을 빌려 쓸 수 있다.

### 1.3 화면 오염 — MAWR 경합이었다

데이터가 떨어지는 자리는 무해했다.  SAT 실측상 게임 스프라이트 패턴은
`$1400~$75FF` 이고 우리가 쓴 `$7900`/`$7B00` 과 겹치지 않는다.  깨진 것은 **MAWR** 이다.

게임이 VRAM 전송 중 MAWR 을 들고 있을 때 IRQ 가 걸리면, 우리가 MAWR 을 세우는
순간 게임의 전송이 엉뚱한 주소로 간다.  MAWR 은 쓰기 전용이라 저장·복구가 안 되므로
**피하는 수밖에 없다.**

```
PROBE_IRQ_VS_SATB_0.1.0 :  IN_HOLD ($600C-$6527) 14 회 / IRQ 19,421 회
```

한 번이면 0.07% 지만 `0.2.7`/`0.2.8` 은 **매 프레임** 업로드했다.  초당 60 번씩
주사위를 굴렸으니 몇 초 안에 반드시 터진다.

**해결 (0.2.10)** — 둘을 같이 넣었다.

```
1  한 번만 업로드한다    done 플래그.  패턴은 한 번 올리면 VRAM 에 남는다
2  안전할 때만 올린다     끊긴 PC 가 $60xx-$65xx 면 이번 프레임은 건너뛴다
```

끊긴 PC 는 스택에서 읽는다.  IRQ 가 PCH·PCL·P 를 밀고 우리 핸들러가 PHA·PHX·PHY 를
더 미므로, PCE 스택 페이지 `$2100-$21FF` 기준 `TSX` 뒤 `LDA $2106,X` 가 PCH 다.

## 2. 마지막 벽 — 게임이 SATB 64 칸을 매 프레임 전부 다시 쓴다

`0.2.13` 까지 오니 모든 단계가 통과했는데도 글자가 안 보였다.
`PROBE_SUBS_VERIFY 0.1.1` 이 설치 순간을 잡아 되읽었다:

```
[설치직후 프레임 5306]
  done $5BDE       01                                 업로드 경로를 탔다
  VRAM byte $F200  00 00 00 00 7E 20 02 20 ...        ★ 패턴 도착
  SAT  byte $2140  F4 00 84 00 C8 03 80 00            ★ SAT 정확히 도착
[+30 프레임]
  VRAM byte $F200  ...변화 없음...                     패턴은 남아 있다
  SAT  byte $2140  00 00 00 00 00 00 00 00            ★★ SAT 만 0 으로 지워졌다
```

우리 코드는 완벽히 동작했다.  **게임이 지운 것이다.**

`PROBE_VDC_LAYOUT 0.1.2` 가 `satbTransferRunning=false 100%` 를 냈지만 그것은
**DMA 를 안 쓴다는 뜻**이었지 안 민다는 뜻이 아니었다.  게임은 VWR 로 직접 쓴다.

디스크 오버레이를 정적으로 디스어셈블해 그 루프를 찾았다 (Track02 섹터 251+, `$6000` 베이스):

```asm
64E7  LDA ($10),Y      스프라이트 원본 목록.  포인터가 zp $10/$11
64FF  PHX
6500  CLX              ★ 엔트리 하나당 한 번
6501  LDA $00,X        제로페이지 $00-$07 에 조립된 엔트리를
6503  STA $0002        VWR 로 밀어 넣는다
650D  CPX #$08         8 바이트 = 엔트리 하나
650F  BNE $6501
6512  DEC $17          남은 엔트리 수
6524  JMP $6463        다음
6527  RTS              루프 종료
```

`$6527` 에 훅을 걸어 매번 우리 엔트리를 다시 써봤다:

```
PROBE_SAT_SURVIVE 0.1.0 :  $6527 쓰기 2,068 회 · 프레임끝 생존 1 · 지워짐 359
```

**빈 슬롯을 빌리는 접근은 구조적으로 성립하지 않는다.**  게임은 안 쓰는 슬롯도
0 으로 채우며 64 칸 전부를 매 프레임 자기 것으로 다시 쓴다.

## 3. 뚫은 방법 — 게임 손을 빌린다

`$6500` 에서 제로페이지 `$00-$07` 을 우리 엔트리로 바꿔치기했다.
그러면 **게임이 자기 스프라이트로 알고** 밀어 넣는다.  지울 이유가 없다.

```
PROBE_SAT_HIJACK 0.1.0  ->  화면에 글리프가 떴다
```

개념 증명이므로 프레임당 5 번째 엔트리 하나를 빼앗았다.  그 자리에 있던
길리언의 눈 스프라이트가 우리 좌표로 옮겨가면서 얼굴에 검은 띠가 남았다.
**그 대가로 글자가 나왔다.**

PCE 제로페이지는 `$2000-$20FF` 이므로 zp `$00` = CPU `$2000` 이다.

## 5. 오늘 두 번 밟은 함정 — 규칙으로 남긴다

```
오프닝에서 잰 값을 일반 대사에 그대로 쓰지 않는다
```

`PROBE_OPENING_SPRITE` 는 오프닝에서 `SAT 64 엔트리 전부 비어 있음` 과
`satbBlockSrc=$1000` 을 냈다.  오프닝은 **스프라이트를 아예 안 켜는** 특수한 화면이다.
일반 대사에 적용했더니 슬롯 가정이 깨졌고 (실제 최대 27), 뒤에 타일맵도 깼다.

```
한 순간의 레지스터 값으로 장면의 성질을 단정하지 않는다
```

`PROBE_VDC_LAYOUT 0.1.1` 이 60 프레임째 한 번만 찍어 `spritesEnabled=false` ·
`columnCount=32` 를 냈다.  누적해 보니 각각 92% true · 64 가 정답이었다.
하필 8%·6% 짜리 순간을 집었던 것이다.

같은 밤에 VRAM 덤프 3 장을 보고 `$7B00` 이 비었다고 판단했다가 323 샘플 프로브에
뒤집힌 것과 같은 실수다.  **표본 하나는 분포가 아니다.**

## 6. 다음 — 빼앗지 말고 늘린다

개념 증명은 게임 스프라이트를 하나 빼앗았다.  실제 구현은 **한 칸 늘려야** 한다.

```
1  zp $16/$17 (남은 엔트리 수) 를 하나 늘린다
2  원본 목록(zp $10/$11 이 가리키는 곳)에 우리 엔트리를 하나 덧붙인다
3  그 자리에 자막 스프라이트를 넣는다
```

확인할 것:

```
목록의 엔트리 형식과 stride      $64E7 LDA ($10),Y 주변을 더 읽어야 한다
목록이 어디에 있고 뒤에 여유가 있나
$16 과 $17 의 역할 구분          하나는 그룹, 하나는 그룹 내 개수로 보인다
자막 16 자 = 슬롯 16 개가 들어가나  일반 대사에서 게임이 27 개까지 쓴다
```

그리고 이 모든 것은 최종적으로 **디스크 패치의 6280 코드**가 해야 한다.
지금 Lua 가 하는 일은 배달부(AC 적재)와 개념 증명뿐이다.
