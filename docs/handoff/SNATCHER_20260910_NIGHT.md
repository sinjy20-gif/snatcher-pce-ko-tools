## 1. 닫힌 것

### 1-1. 프론트도어에 그래픽 18 장 통합

전에는 굽고 나서 `patch_gfx_screen.py` 를 손으로 다섯 줄 더 쳐야 했다. 빠뜨리면
그래픽 없는 판이 그대로 나갔고(실제로 그랬다), 단계마다 새 폴더에 Track 02(80 MB)
를 새로 써서 **한 판에 400 MB** 를 버렸다.

이제 `make_subtitle_build.py` 의 `[8/8]` 이 같은 폴더에 **제자리로** 얹는다
(`--base` == `--version`). 끄려면 `--no-gfx`.

    python tools/make_subtitle_build.py <판> --skip-oversize

검증: 새 빌더 산출물이 손으로 얹은 것과 Track 02 **sha256 동일**
(`b838546cdf262469…`). 제자리 얹기의 유일한 안전장치는 `patch_gfx_screen.py` 에
넣은 **하드링크 끊기**다 — 안 끊고 제자리에 쓰면 같은 inode 인 기준판까지 바뀐다
(09-09 에 0.6.5 매니페스트를 실제로 오염시킨 적이 있다).

### 1-2. 트랙 1 자막 제거 · CD-DA 안전자리 갱신

### 1-3. 트랙 17 통과

어제 빌드를 막던 트랙 17 이 **35 구간으로 정상 통과**. 16 트랙 전부 자리를 받았고
빠진 트랙 없음.

### 1-4. 음성 변종 `k003D2A_4000_0E_vF66D321F.bin` — 오염으로 판정

같은 열쇠로 덤프가 둘이던 건이 닫혔다. **음성은 하나**고, 변종은 오염된 포착이다.

    ev17  read $0064  len 16,284  ->  16,284 B  커버리지 100.1%   본체
    ev18  read $06A9  len 14,679  ->  39,046 B  jumps 4          변종
    ev23  read $0064  len 16,284  ->  16,284 B  커버리지 100.1%   또 본체

변종의 `read_address $06A9` = `$0064 + 1605` 이고, 어긋남을 직접 재도 1,605 B 다.
선언 길이 14,679 도 두 파일이 겹치는 구간과 정확히 일치한다. 뒤 24,367 B 는
클립 1,225 개 어디에도 없는 남의 데이터고, 그 END 이벤트는 **프레임이 START 보다
앞선다**(세이브스테이트/리셋). 병합 도구가 거부한 것이 옳았다.

→ 변종 파일은 버려도 된다. 남겨도 마스터엔 영향 없다.

⚠ 수집기 0.1.5 에 `partial` 가드는 있으나 **`jumps>0` 이거나 선언 길이보다 파일이
길 때** 걸러내는 장치는 없다. 오늘 266 이벤트 중 이 한 건뿐이라 급하진 않다.

## 2. 실패한 것 — CD-DA 자리 옮기기 3연패

메탈 초상화 깨짐(트랙 5·6, 0.6.5 부터)을 고치려고 관찰이 가리키는 자리로 옮겼다.
**세 번 다 다른 것이 깨졌다.**

    0.7.2  5=$7300 6=$3B00   초상화만 깨짐          ← 셋 중 제일 낫다
    0.7.3  5=$3B00 6=$3600   초상화 정상 · 깁슨 문서 깨짐
    0.7.4  5=$6300 6=$7300   전반적으로 더 깨짐

그런데 관찰 점수는 **정반대**였다 (0.7.4 주행까지 넣은 창고 기준):

    트랙 5 · 살아남은 창 50
        $7300    0/50      실제로는 제일 멀쩡
        $3B00    0/50
        $6300   50/50      만점인데 실제로 제일 많이 깨졌다

**부호가 안 맞는다.** 방향이 어긋난 게 아니라 반대다. 이 모델로 base 를 고르면
안 된다.

`PROVEN_BASE` 에 `5: 0x7300, 6: 0x3B00` 을 못 박아 두었다. 빼면 빌더가 새 관찰을
보고 다시 `$6300` 쪽으로 가서 0.7.4 가 재현된다.

### 2-1. 왜 틀리나 — `buildOccupancy()`

`lua/SUB/0.5.47-vram-key-map-0.4.lua:600`

    wordMark    VDC 에 실제로 쓰인 워드      ← 사실
    tileMark    BAT 가 참조하는 타일 전부     ← 16 word 씩 통째로 부풀린다
    unitMark    32 word 씩 통째로
    batWords    BAT 본체 전부
    satbSeen    SATB 256 word 씩

**실제 쓰기를 이미 재고 있는데 "화면이 참조하는 것 전부"를 union 해서 내보낸다.**
그래서 띠가 `$2BC0-$523F`(5,760 word) 처럼 거대해진다.

반례가 이미 있다: **트랙 3 은 관찰이 22/22 창 막힘이라 하는데 실기는 멀쩡하다.**
`STRICT BAT ON` 이 스쳐간 UI 까지 그 음성 구간 전체 점유로 쌓는 탓이다.

다만 쓰기만 봐도 답이 아니다. 음성 시작 **전에** 올라간 타일은 그 구간 동안 쓰기가
없어서 "비었다"로 보인다 — 깁슨 문서가 정확히 그렇다(페이지 넘길 때 `$3000` 부터
올리고 그다음엔 안 씀).

    쓰기만    미리 올라간 타일을 놓친다   (과소)
    참조까지  스쳐간 것까지 센다          (과다)

### 2-2. 다음 첫 수

**두 값을 한 표에 나란히 뽑는다.** `buildOccupancy` 를 갈아엎지 말고 출력만 나눈다.
대조군이 이미 있다 — 트랙 3(실기 정상) · 트랙 5(실기 깨짐). 표만 나오면 어느
지표가 실기와 맞는지 바로 갈린다. **오늘처럼 한 값만 믿고 자리를 옮기지 말 것.**

## 4. 남은 문제와 선택지

**메탈 초상화 깨짐** (트랙 5·6, 0.6.5 부터). 0.7.2 에 그대로 있다.

경위가 오래 헷갈렸는데 이렇게 정리된다: 자리는 `0.6.2 ~ 0.7.2` 내내 같았다
(`5=$7300 6=$3B00`). 0.6.4→0.6.5 는 **Track 02 동일 · Track 24 다름 · BIOS 1 B
다름**(AC 포인터 상수 `$98FE→$98C8`, 코드 아니라 `record_off` 데이터)이다.
즉 0.6.5 는 **자막 팩만** 바꿨고, 그 장면에 걸리는 창이 새로 생겨 예전부터 있던
자리에 그리며 초상화를 덮었다. **자리 이력이 같다는 것이 자리가 무죄라는 뜻은 아니다.**

판마다 자리를 읽는 법: 구운 디스크/BIOS 에서 `0A 10` · `0B 11` · `0C 12` 가 16 B
간격으로 이어지는 곳이 256 B 디렉터리, 항목 `+6` 이 base 상위 바이트.

### 선택지 넷

1. **이사 부활** — 구조적 해결. 지금 막힌 이유는 상주부가 AC 이미지를 CPU 로
   재복사하며 이사가 쓴 값을 되돌리기 때문(`build_cdda_mini_index_all.py:269`
   에 0.5.18 실측 로그). 즉치를 AC 이미지에도 쓰는 쪽은 84 B 필요/40 B 여유라
   안 맞고, **재복사 다음 프레임에 CPU 즉치를 쓰는 2 단 이사**는 아직 안 재봤다.
2. **자막 포기** — 트랙 5·6 만 빼면 초상화가 산다.
3. **창만 빼기** — 부딪히는 창만. 빌더가 "자유자리 0 인 창"에 이미 하는 일이라
   범위만 넓히면 된다.
4. **글리프 창 줄이기** — 트랙 5·6 만 칸 수를 줄이면 창이 작아져 들어갈 틈이
   늘어난다. **자리를 옮기는 게 아니라 좁히는 접근**이라 오늘 실패한 것과 성격이
   다르고, 코드도 거의 안 건드리며 효과가 바로 계산된다. → 다음에 이것부터.

### 곁가지 결함 (안 고침)

`NO_MOVE_TRACKS` 가 커버리지를 안 보고 run0 자리를 집는다. 트랙 3 에 그대로
적용하면 `$7A00` = **3/20 창**. 지금 멀쩡한 건 `PROVEN_FIRST_BASE` 가 덮어서다.
이사를 안 할 거면 run 구조가 아니라 전 구간 커버리지 최대를 골라야 한다.
