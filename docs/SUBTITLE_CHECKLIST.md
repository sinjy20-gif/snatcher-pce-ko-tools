# 자막 프로브 지침서 — 기준판에서 반드시 이어받을 것

새 자막 Lua 를 만들거나 판을 올릴 때 **매번** 보는 문서다.

## 왜 이 문서가 있나

`PROBE_SUB_PACK` 계열이 기준판 `PROBE_SUB_TEXT_0_1_0.lua` 를 **안 이어받고 따로
자랐다.**  그래서 2026-08-23 오전에 닫은 구멍(잔류 → UI 스프라이트 깨짐)이
2026-08-24 에 그대로 다시 열렸다.

```
3_PLACED §2 가 고친 것        pushed_this_frame · clear_ours · SATB 주소
SUB_PACK 0.1.8 에 있는 것      하나도 없음
```

버전 번호가 크다고 최신 기능을 다 가진 것이 아니다.  **갈래가 갈리면 각각
따로 자란다.**  같은 일이 수집기에서도 있었다 (0.2.2 가 둘이었고 한쪽에 음성
덤프가 없었다 — `docs/MERGE_CHECKLIST.md` §7).

## 1. ★ 기준판에서 이어받을 것 넷

기준판: `lua/PROBE_SUB_TEXT_0_1_0.lua` (`3_PLACED §7` 이 ★ 기준판으로 지정)

### 1-0. ★ 우리 엔트리 판별은 **팔레트 니블**이다 (attr == $0080 이 아니다)

기준판의 `attr == $0080` 을 그대로 베끼면 **영영 0 개**다.  그것은 팔레트가 0 이던
시절 조건이고, `6_LIVE §4` 가 그날 밤 팔레트를 **0 -> 15** 로 바꿨다 (0 은 메뉴가
쓴다).  엔진이 실제로 쓰는 값은

```
0x80 | ((패턴워드 >> 8) << 4) | PALETTE      PALETTE = 15
```

라 상위 니블이 패턴 상위비트에 따라 흔들린다.  그래서 이렇게 본다:

```lua
(attr & 0x0F) == PALETTE  and  (attr & 0x80) ~= 0  and  패턴이 우리 대역
```

2026-08-24 에 이걸 베껴 와서 백스톱이 안 켜졌고, 안 켜지니 매 프레임 다시 재면서
로그를 수천 줄 도배했다.

### 1-1. 잔류 백스톱 — "이번 프레임에 실제로 밀었는가"

```
증상    메뉴를 열면 UI 선택 스프라이트가 깨진다
원인    지문은 맞는데 $601E 를 안 지나는 프레임이 있다 (메뉴가 떠 있을 때 등).
        그러면 게임이 SATB 를 다시 안 쓰고 지난 프레임의 우리 엔트리가 남는다
고침    안 밀었으면 SATB 64 칸을 훑어 **우리 것만** 지운다
```

> **지문으로 판단하면 이 상태를 못 잡는다.**  지문은 "오버레이가 갈렸다" 만
> 알려주지 "이번에 안 그렸다" 는 못 알려준다.

우리 것 판별은 **§1-0 의 조건**을 쓴다 (팔레트 니블 + 패턴 대역).
하나만 보고 지우면 남의 스프라이트를 부순다.

### 1-2. 밀었는지 잡는 자리는 판마다 다르다

```
기준판 (Lua 가 스텁을 심던 때)     $5C71   스텁 안 JSR
지금   (상주부가 디스크에 박힘)    $5C06   engine.bin 안 JSR $6463  ← 실측
```

**엔진을 다시 구우면 이 주소가 밀린다.**  `engine.bin` 에서 `20 63 64` 를 찾아
확인할 것:

```bash
python -c "d=open(r'build/cutscene_subs/engine.bin','rb').read(); i=d.find(b'\x20\x63\x64'); print(hex(0x5B80+i))"
```

### 1-3. SATB 주소 — ★ 문서가 갈린다.  짐작하지 말 것

```
1_BREAKTHROUGH §4    SATB = VDC 워드 $1000 = Mesen 바이트 $2000
PROBE_SUB_TEXT       SATB_BYTE 0x2000 · PAT_VRAM_BYTE 0xF200      (바이트)
PROBE_SUB_PACK 0.1.8 SATB 0x1000 · PAT_VRAM 0x7900                (워드)
```

**둘 다 맞을 수는 없다.**  그런데 0.1.8 쪽 주소로 패턴을 올려서 화면에 글자가
떴고, 기준판은 바이트 주소로 잔류를 지워서 UI 가 정상으로 돌아왔다.
(아래에서 닫혔다.)

`PROBE_SUB_PACK 0.1.9` 는 **재서 정한다** — 민 다음 프레임에 후보 둘을 다 훑어
우리 엔트리(`attr $0080` + 패턴 대역)가 실제로 있는 쪽을 고르고, 고르기 전에는
아무것도 안 지운다.  로그에 이렇게 나온다:

```
SATB 후보 워드 $1000    우리 엔트리 0 개
SATB 후보 바이트 $2000  우리 엔트리 4 개
-> SATB 는 바이트 $2000 다.  백스톱을 켠다
```

### ★ 닫혔다 — SATB 는 **바이트 `$2000`** 이다 (2026-08-24 실측)

실기 로그:

```
SATB 자리 결정: 바이트 $2000  (우리 엔트리 16 개 · 2 번째 시도)
후보별: 워드 $1000 0 · 바이트 $2000 16
```

`1_BREAKTHROUGH §4` 와 기준판이 맞았고, `SUB_PACK 0.1.8` 의 `0x1000` 이 틀렸다.
0.1.8 의 `[4] SATB[0] ...` 과 `[5] 쓰인 슬롯 64/64 · 우리 것 0` 은 **틀린 자리를
읽은 값**이다.  그걸 이상 징후로 읽고 두 번 헛다리를 짚었다.

```
SATB      바이트 $2000 · 한 엔트리 8 B · y(0,1) x(2,3) pattern(4,5) attr(6,7)
패턴 VRAM  emu.read/write 는 0x7900 (워드) 로 올려서 화면에 뜬다
```

⚠ **둘의 단위가 다르다.**  SATB 는 바이트로, 패턴 업로드는 워드로 접근하는데
둘 다 실제로 동작한다.  왜 그런지는 아직 안 닫혔다 -- 건드리지 말 것.

### 1-4. VRAM 은 빌리되 되돌린다

```
$7900 부터 19 x $40 워드.  음성 시작에 떠 두고 끝나면 되돌린다
```

RAM 과 달리 **게임이 안 지운다.**  되돌리기를 빼면 안 된다 — 컷신마다 사정이
다르다.

## 2. 로그에서 오해하기 쉬운 값들

이 셋은 **정상이다.**  이걸 이상 징후로 읽고 헛다리를 짚은 적이 있다.

```
쓰인 슬롯 64/64        정상.  게임은 안 쓰는 슬롯도 0 으로 채우며 64 칸 전부를
                       매 프레임 자기 것으로 다시 쓴다 (1_BREAKTHROUGH §2)

zp $17 = 255           정상.  $601E 가 $3F 로 세우고 푸시가 깎는 예산이다.
                       조립이 끝나면 음수(BMI)가 되어 $FF 로 보인다 (2_EXTEND §1)

zp $16 = 255           정상.  리스트 머리의 개수 바이트를 담는 칸이라 조립 뒤
                       값이 남아 있는 것뿐이다 ($6459 LDA ($10) / STA $16)
```

그리고 `[4] SATB[0] ...` 가 말이 안 되는 값이면 **SATB 주소가 틀린 것**이지
게임이 이상한 것이 아니다 (§1-3).

## 5. 확정 상수

`1_BREAKTHROUGH §4` · `2_EXTEND §1` · `engine.json` 에서 온 것.

```
SAT 조립 시작      $601E   LDA #$3F / STA $17     ★ 우리 훅이 밀어낸 자리
SAT 조립 끝        $6072   JMP $43BE
객체 하나 원점     $63CB
개수 바이트        $6459   LDA ($10) / STA $16
엔트리 푸시 루프   $6500   (엔트리당 1 회) · 종료 $6527
0 채우기          $60A6
게임 푸시 진입     $6463   ← 엔진이 빌려 쓰는 것

엔트리 형식        16x16 · front(attr bit7) · **팔레트 15**
                  실제 값 = 0x80 | ((패턴워드 >> 8) << 4) | 15
                  ★ 문서의 "attr $0080 · pal 0" 은 팔레트 0 이던 시절 것이다
SATB              바이트 $2000 · 엔트리 8 B (2026-08-24 실측 확정)
패턴번호 공식      (word2 >> 1) * 64 = VRAM 워드
우리 패턴 대역     $3C8 부터 2 씩 (= (PAT_VRAM >> 6) << 1)

상주부            $7FA0  32 B   (헬퍼 여유 151 B $7F49-$7FDF 안)
엔진              $5B80  704 B 중 362 B · 매직 'SUB'
엔진 안 JSR $6463 $5C06
VRAM 빌림         $7900 부터 19 x $40 워드
자리              위 32 · 중간 122 · 아래 192   (기본 ADPCM 중간 · CD-DA 아래)
한 줄             19 자 / 192 px
팔레트            15   ★ 0 은 메뉴가 쓴다
```
